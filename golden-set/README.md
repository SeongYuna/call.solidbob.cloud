# 골든셋 — v1 (10개 → 50개)

[데이터 확보 계획 5.3절](/docs/05/)의 목표(1주차 10개 → 2주차 50개 → 3주차 150개)를 채워가는
중이다. `knowledge-base/`의 실제 문서 ID(도메인 접두어 포함)를 그대로 참조하므로, 지식베이스
문서가 바뀌면 이 골든셋도 같이 갱신해야 한다.

> **2026-08-26 전면 재작성.** 데모 도메인을 가상 통신사 "한별텔레콤" 단일 시나리오에서
> 실제 확보 데이터 4종(금융보험·다산콜센터·쇼핑·질병관리본부)으로 한정하면서, 이전
> 버전(`TERM-*` 등 통신 도메인 문서 ID를 참조)이 전부 무효가 됐다. 근거:
> `_project/decisions/004-데모-도메인-4종-확정.md`.

## 파일

- `v1-10.json` — 1주차 항목 10개. (2주차 50개 안에 그대로 포함되어 있다 — GS-001~010)
- `v1-50.json` — 2주차 항목 50개(`w2-golden-set-50.md`). 스키마는 아래 참고.

## 스키마 (5.3절 "골든셋 스펙에 포함할 항목" 그대로)

| 필드 | 설명 |
|---|---|
| `domain` | `finance` / `dasan` / `shopping` / `health` 중 하나 — [1.4절](/docs/01/) 4개 도메인 |
| `customer_utterance` / `agent_utterance` | 고객 또는 상담원 발화 스크립트 |
| `utterance_end_ms` | 발화 종료 시각 — [4.1절](/docs/04/) 트리거 채점(0~1,500ms 허용창)용. B 모듈 항목에만 있다 |
| `expected_doc_ids` | 이 시점에 표시되어야 할 정답 문서 ID (도메인 접두어 포함, 예: `FIN-TERM-2.2`) |
| `distractor_doc_ids` | 표시되면 안 되는 오답 후보 문서 ID (같은 도메인 내 근접 조항) |
| `compliance_violation` | C-1~C-4 위반 삽입 여부와 유형 (`C-1` 확정적 보장, `C-2` 불필요한 개인정보 요구, `C-3` 필수 안내 누락) |
| `pii_patterns` | P1~P7 개인정보 패턴 삽입 여부 (C-5 채점용) |
| `f2_case` | 처리 유형 + 근거 필드 충족 상태 + 기대 판정 (F-2 케이스만 — **금융보험·쇼핑 도메인에만 존재**, 다산콜센터·질병관리본부는 F-2 미적용) |

모든 문서 ID·필드명은 `knowledge-base/{finance,dasan,shopping,health}/`의 실제 `<!-- id: -->`
주석과 대조해 검증했다(존재하지 않는 ID를 참조하는 항목 0건).

| C-3 (필수 안내 누락) | 4 | 해지·반품·대리신청 고지 누락, 응급 신호 무시(4개 도메인 각 1건) |
| C-5 (마스킹) | 10 | P1~P7 전 패턴 커버 — 구분자 유무·복수 패턴 동시 등장 케이스 포함 |
| F-2 (종결 게이트) | 16 | 금융보험(상품해지·보상) 9건, 쇼핑(반품·교환) 7건 — 승인/차단 사례를 결여된 근거 필드별로 다양화 |

## 도메인별 분포 (50개)

| 도메인 | 개수 | 비고 |
|---|---|---|
| 금융보험 | 18 | F-2(상품해지·보상)가 있어 가장 많음 |
| 쇼핑 | 16 | F-2(반품·교환)가 있어 두 번째로 많음 |
| 다산콜센터 | 9 | 안내형 업무, F-2 없음 |
| 질병관리본부 | 7 | 안내형 업무, F-2 없음 |

균등 배분(각 12~13건) 대신 F-2 적용 도메인(금융보험·쇼핑)에 더 배정했다 — `w2-golden-set-50.md`가
제기한 질문에 대한 답이다. F-2 없는 두 도메인은 B/C/C-5로만 구성해도 도메인별 Recall@5·
컴플라이언스 재현율을 계산하기에 충분한 표본(7~9건)을 확보했다.
