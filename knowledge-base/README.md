# 지식베이스 — 다산콜센터 단일 도메인 (2026-08-28)

[데이터 확보 계획 5.1절](/docs/05/)에 따라 팀이 직접 작성하는 문서다.

**2026-08-28 다산콜센터 하나로 줄였다**(`_project/decisions/201`). 금융보험·쇼핑·질병관리본부
디렉터리를 삭제했고 조항이 **102개 → 20개**가 됐다. 이전 이력: 원래 가상 통신사 "한별텔레콤"
단일 도메인이었다가, 실제 확보 데이터에 통신이 없어 4개 도메인으로 재구성했고(`decisions/004`),
다시 다산 하나로 좁혔다.

**왜 다산인가** — ① 음성 데이터를 가진 유일한 도메인(다산콜DB 6,614건) ② 서류 문의 상위 단어에
`여권` 이 있어 외국인 맥락이 데이터에 이미 있다 ③ 120이 사람 통역으로 외국어 상담을 이미 한다.

⚠ **지운 3개 도메인은 git 이력에 있다** — `git checkout <이 커밋 이전> -- knowledge-base/`.

각 도메인 문서는 **약관 원문을 전재하지 않고, 가상 사업자/기관 기준으로 처음부터
작성**한다 — 저작권 문제가 없고, 프로젝트가 원하는 규칙(C-1~C-4 위반 유형, F-2 필수
확인 항목)을 정확히 반영하도록 설계할 수 있다. 다만 카테고리·의도 체계는 AI Hub
「민원(콜센터) 질의-응답」데이터셋(`data/raw/aihub-minwon-qa/`)의 실측 라벨을 따른다.

## 도메인별 문서 3종

각 도메인 폴더 아래 공통 구조를 둔다.

| 하위 폴더 | 문서 | 역할 |
|---|---|---|
| `terms/` | 이용약관/안내지침 | B(검색) 대상. 화면에 "출처: 이용약관 N.N조"로 인용됨 |
| `manual/` | 응대 매뉴얼 | B(검색) 대상. F-2 근거로도 쓰임(해당 도메인만) |
| `policy/` | 내부 처리 규정 | **F-2 게이트가 직접 참조**하는 처리유형별 필수 확인 항목 정의 (F-2 미적용 도메인은 미적용 사유와 대체 검증 수단을 명시) |

네 도메인 × 세 문서 = 12개 문서(조항 102개)가 Elasticsearch 에 적재된다. 상담 중에는
통화가 어느 도메인인지 먼저 라우팅한 뒤 그 도메인으로 좁혀 검색한다.

**인덱스 하나(`callguard-kb-single`)에 전부 넣고 `domain` 필드로 필터한다**
(2026-08-27, `_project/decisions/017`). 조항이 102개뿐이라 도메인별로 나눌 이유가 없다.

```bash
export ELASTICSEARCH_URL=http://localhost:9200      # cd infra && docker compose up -d
.venv/bin/python scripts/index_knowledge_base.py --to-es --recreate
```

**도메인이 크게 늘면 도메인별 인덱스로 전환한다**(`--layout per-domain`). 볼륨 증가만으로는
바꾸지 않는다 — 전환 조건과 방법(alias 를 앞에 세운다)은 `decisions/017` 에 있다.

## ID 체계

도메인 코드 접두어 + 기존 체계를 그대로 쓴다. `<!-- id: ... -->` 주석으로 문서 ID를
붙였다.

| 도메인 | 접두어 | 예시 |
|---|---|---|
| 다산콜센터 | `DASAN-` | `DASAN-TERM-5.1`, `DASAN-MANUAL-4.1`, `DASAN-POLICY-1` |

⚠ 폐기된 접두어 `FIN-`·`SHOP-`·`HLT-`·`TELCO-` 는 `parse_doc_id()` 가 **ValueError 로 거부**한다
(`ai/apps/retrieval/domain/services/chunking.py`) — 남은 문서가 섞여 색인에 유령 도메인이
생기는 것을 막는다.
