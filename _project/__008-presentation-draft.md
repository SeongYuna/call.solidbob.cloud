# 발표 자료 초안 — CallGuard (SOLIDBOB) · 2026-10-01

> 비공개 초안. 슬라이드 장수·시간·제출물 형식이 정해지면 그 틀로 옮긴다. **모든 숫자의 출처는 `decisions/138` 인용 정본**(6주차 판정문 run 8·9 · 지연 실측)이고, 문구 셋을 반드시 붙인다. 시연은 `demo-script.md` 의 영상 또는 라이브.

## 1. 한 줄

서울시 120 다산콜센터 상담원 옆에서 통화를 실시간으로 들으며 **그 민원에 필요한 구비서류를 띄우고**, 개인정보를 **그 자리에서 가리고**, 상담원 위반과 고객 폭언을 잡는 상담원 어시스트. 판정은 규칙이, 설명만 모델이 한다.

## 2. 누구의 어떤 문제인가

- 다산 서류 문의 2.18%(146건)가 **64종 서비스**에 흩어져 있다 — 상담원이 외울 규모가 아니다(09-11 재측정).
- 체류외국인 287만 명(2026-06). 서툰 한국어 발화의 STT 단어 오류율이 **초급 0.412 · 유창 0.198**(n 20/등급, 상한) — 단어 다섯 중 둘을 틀린다. 문제의 크기이지 해결의 증거가 아니다.

## 4. 아키텍처 한 장

상담원 브라우저 ⇄ 콜 미디에이터(Node, WS) → 서버(FastAPI 허브 + 스포크 11) → PostgreSQL(29 테이블) · Elasticsearch(nori + dense). 단일 EC2 k3s, GPU 없음. 프론트 셋은 Vercel.

## 11. 물으면 답할 것

- STT 는? — 영상은 글자 채널. 구글 스트리밍은 운영에 있고 화자 분리는 미검증.
- 통번역은? — 1차 범위만 실물. 나머지 미착수.
- 숫자 어떻게 나왔나? — 하네스 `--record`, run_id 8·9, 커밋·명령·표본 수 전부 판정문에.
- 왜 규칙인가? — 같은 입력에 같은 답. LLM 은 채점자로 쓰지 않는다(절대 원칙 1·9).
