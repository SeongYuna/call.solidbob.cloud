## 2. 부탁드리는 것 — 우선순위 (09-24 재정렬)

### P0 — 이게 없으면 영상을 못 찍습니다

#### P0-1 — **「절차를 하나도 안 잡는 통화」가 생깁니다** (새 항목, 09-24)

오늘 F-2 필요서류 **절차 채택 조건**을 바꿨습니다(`_project/decisions/219`, 커밋 `f725e41`).
전에는 추천이 뜰 때마다 **1순위 카드의 조항을 무조건** 절차로 삼았는데, 이제는
**1순위 카드 점수가 `0.635` 이상일 때만** 삼습니다(`F2_PROCEDURE_ADOPTION=score-floor`, 콜 미디에이터 `0.2.10` 기본값).

잰 결과(보류 표본 12건): 엉뚱한 (대본, 절차) **10쌍·42행 → 3쌍·12행**, 필요한 절차는 **8/8 그대로**.
학습 표본 24건에서도 **31쌍·186행 → 21쌍·127행**입니다.

**그런데 이것이 화면에 새 상태를 만듭니다** — 점수가 하한을 못 넘으면 **통화 내내 절차가 하나도 안 잡힙니다.**
전에는 (엉뚱하더라도) 늘 무언가 잡혔기 때문에 화면이 이 상태를 거의 본 적이 없습니다. 그때 지금 화면은:

| | 무슨 일이 | 어디 |
|---|---|---|
| ① | **기본 탭인 「필요서류」가 통화 내내 빈 문구** 「필요서류 안내가 필요한 민원이 아직 없습니다」 | `TermsPanel.tsx:64`(기본 탭) · `:160-163`(빈 문구) |
| ② | **상단 진행 칩**(「서류 n/m 안내 완료」)이 안 뜸 | `TermsPanel.tsx:103-108` — `pending`(=closure 있는 카드)이 없으면 `null` |
| ③ | **하단 책갈피 독이 통째로 사라짐** | `BookmarkDock.tsx:12-18` — closure 없는 카드만 있으면 `return null` |
| ④ | **「안내 완료로 표시」 버튼이 안 나타남**(= 종결 처리 흐름 자체가 안 열림) | `TermsPanel.tsx:198`(`canSettle`) · `:329-332` |
| ⑤ | **수동 검색으로 조항을 직접 찾아도 체크리스트가 안 붙음** | `callStore.ts:530-556` — `applyManualResult` 가 카드를 `closure: null` 로 넣고(`:549`), 나중에 판정이 와도 이 카드에 붙일 경로가 없음 |

**부탁드리는 것 — 화면 쪽 셋**

1. **「빈 상태」가 사실대로 읽히게 문구를 바꿔 주세요.** 지금 문구는 **부록 A-1 이 금지하는 단정**이 됐습니다 —
   - `TermsPanel.tsx:117` 「**이 민원 유형은 서류 안내 대상이 아닙니다.**」 → **사실이 아닙니다.**
     실제 뜻은 「트리거가 발동하지 않았다」입니다. 예: 「아직 문의 내용이 없습니다」
   - `TermsPanel.tsx:161-163` 「필요서류 안내가 필요한 민원이 아직 없습니다」 → 이것도 단정입니다.
     실제 뜻은 「**확실한 절차를 아직 못 찾았습니다**」입니다. 예: 「아직 확실한 절차를 찾지 못했습니다 —
     「팝업창」 탭의 문서나 수동 검색을 참고하세요」
   - 문구는 서희 님이 정해 주세요. **지켜야 할 선 하나** — 「대상이 아니다 / 필요 없다」처럼
     **없다고 단정하지 않기**. 우리가 아는 것은 「점수가 하한 아래라 안 잡았다」뿐입니다.
2. **빈 상태에서도 화면이 죽지 않게** — 필요서류 탭이 비었을 때 「팝업창」 탭에 카드가 있으면
   그쪽으로 유도하는 한 줄(또는 자동 전환)을 넣어 주시면 영상에서 화면이 멈춘 것처럼 안 보입니다.
   *(권고일 뿐입니다 — 판단은 서희 님께 맡깁니다.)*
3. **수동 검색 카드에도 판정이 붙게**(⑤) — `applyManualResult` 가 넣은 카드에 나중에 `closure` 가 오면
   붙도록. 지금은 `withClosure` 의 짝짓기 대상에 안 들어갑니다. **이건 P1 로 봐도 됩니다** —
   시연 대본 셋은 자동 추천으로 잡히니까요.

**⚠ 통화 ID 유실은 시연에서는 안 터집니다 — 하지만 근본 수정은 그대로 필요합니다.**
절차가 안 잡히는 통화가 늘면서 기존 버그(`w6-close-callid-missing`)가 **상시 발현될 뻔했는데,
제가 콜 미디에이터 쪽에서 막았습니다** — `0.2.10` 부터 추천 메시지에 **`call_id` 를 늘 싣습니다**
(`services/call-mediator/src/app/call_registry.ts:711-719`). 서버는 계약대로 트리거 미발동 응답에
`call_id` 를 `null` 로 싣는데, 미디에이터가 그 뒤에 실제 값을 덮어씁니다.
**그래서 화면을 안 고쳐도 시연 중에는 멈추지 않습니다.**
다만 **구조는 그대로 남아 있습니다** → P0-2 에서 계속.

**안심하셔도 되는 것**: 시연 대본 **SYN-021·SYN-004·SYN-009 는 셋 다 점수가 하한 위**라
(0.7037 · 0.7998 · 0.8344 vs 하한 0.635) **화면이 09-22 과 똑같이 나옵니다.**
P0-1 은 「시연이 깨져서」가 아니라 **「다른 통화를 즉석에서 틀면 이렇게 보인다」**를 막는 작업입니다.

#### P0-2 — `callId` 덮어쓰기 (`w6-close-callid-missing`) — **구조 수정은 그대로 필요**

09-23 에 `started` 메시지를 잡도록 해 주신 것(`applyStarted`)으로 **가장 이른 시점에 `callId` 를 잡는 것은 됐습니다.**
그런데 **그 뒤에 덮어쓰는 경로가 그대로 남아 있습니다** — 파서가 없는 `call_id` 를 `""` 로 채우고,
스토어가 그 값으로 이미 잡아 둔 `callId` 를 덮어씁니다.

- `apps/call/src/lib/ws/realCallMediatorClient.ts:449` — `call_id: readString(body, "call_id") ?? ""`
- `apps/call/src/store/callStore.ts:503` 과 `:522` — `applyRecommendation` 이 그 값으로 `return { callId, … }`
