## 1. 정성윤 — 겹치는 것 둘

### ① `ai/apps/postcall_summary/` — **내가 물러났다. 성윤 님 것이 그대로 산다**

성윤 님이 **09-23 `e8f2dc4`** 로 D-2 유형 이름표를 운영 표에 맞추셨다.
나는 오늘 교차 검수에서 같은 문제를 발견하고 **같은 파일 3개를 고쳤다가, 먼저 손댄 쪽이 산다(`CLAUDE.md` §4)에 따라 전부 되돌렸다.**
**PM 브랜치를 머지하실 때 이 파일들에서 내 변경과 부딪힐 일은 없다.**

**되돌리면서 성윤 님 판단이 더 맞다고 봤다.** 나는 6장(재난·생계 지원금)을 투표 표에 **추가**했는데,
성윤 님은 일부러 넣지 않고 *「이름만 맞춘다 … 넣으려면 표본으로 재고 따로 결정한다」* 고 적어 두셨다.
내 쪽은 **어느 장이 투표하는지를 바꾸는 동작 변경**이었고 그것을 재지 않았다 — 절대 원칙 2 에 걸린다.

**다만 하나는 가져가시면 좋겠다 — 가드 테스트를 «직접 import» 로 바꾸는 것.**
지금 `test_types_match_aihub_categories` 는 운영 이름 4개를 **손으로 적어 두고** 대조한다.
그러면 운영 표(`server/apps/postcall/domain/services/inquiry_rules.py`)가 바뀔 때 **또 갈라진다** — 이번에 갈라진 경위와 똑같다.

```python
def test_types_match_production_catalogue():
    from postcall.domain.services.inquiry_rules import INQUIRY_RULES   # 운영 표를 직접 읽는다
    assert set(INQUIRY_TYPES) <= {name for name, _ in INQUIRY_RULES}
```

`ai/pytest.ini` 가 이미 `../server/apps` 를 경로에 올려 두어 그대로 돈다(같은 방식을 `ai/tests/test_postcall_catalogue.py` 가 쓰고 있다).
**왜 필요한가**: 이 표의 값이 **운영 판정을 덮어쓴다**(`model_postcall_adapter.py` 의 `suggest_inquiry_type(...) or inquiry_type`).
즉 `GENERATION_MODEL` 을 `server-env` 에 넣는 순간 화면·DB 의 유형 라벨이 이 표로 바뀐다.
09-22 에 정답 파일만 맞추고 이 표를 안 고쳤을 때 **가드는 초록인데 운영 라벨은 틀리는** 상태였다.

## 2. 조서희 — 코드 충돌 없음. 대신 **화면에 새 상태가 생긴다**

`apps/` 는 한 줄도 건드리지 않았다. 그런데 **화면이 기대던 전제가 깨진다.**

### ⚠ P0 — 절차를 하나도 안 잡은 통화에서 **요약·확정 버튼이 사라진다**

필요서류 절차를 **점수로 거르기 시작**하면서(`decisions/219`), 절차를 하나도 안 잡는 통화가 생긴다.
그때 **통화 ID 가 빈 문자열로 남는 기존 버그**(`w6-close-callid-missing`, 진행 중)가 **상시로 터진다** —
지금까지는 뒤따라오던 필요서류 판정 메시지가 통화 ID 를 되살려 줘서 가려져 있었다.

**내 쪽에서 막았다**: 콜 미디에이터가 추천 메시지에 `call_id` 를 **늘** 싣는다(`0.2.10` 부터).
→ **서희 님 화면을 안 고쳐도 상시 발현은 멈춘다.** 다만 **근본 수정은 그대로 필요하다** —
파서가 없는 값을 `""` 로 채워 스토어를 덮어쓰는 구조 자체는 남아 있다.

### 통화에 절차가 0건일 때만 나타나는 화면 상태 (전수)

1. 「필요서류」 탭이 통화 내내 빈 문구 (그게 **기본 탭**이다)
2. 상단 진행 칩(「서류 N/M 안내 완료」)이 한 번도 안 뜸
3. 하단 책갈피 독이 통째로 사라짐
4. 「종결 처리」 버튼이 안 나타남 → **시연에서 F-2 완료 흐름을 못 보여준다**
5. 판정 전용 카드 경로가 아예 안 돎 — 화면 카드가 전부 추천 카드
6. 수동 검색으로 정확한 조항을 찾아도 체크리스트가 안 붙음

### ⚠ 부록 A-1(단정 금지)에 걸리는 문구가 둘로 늘었다

화면이 「**이 민원 유형은 서류 안내 대상이 아닙니다**」라고 단정하는데,
이제 그 통화는 **「점수가 낮아 절차를 안 잡았다」**인 경우가 많다. 사실이 아닌 단정이다.
필요서류 탭의 빈 문구도 같다. **문구를 「아직 안내할 서류를 찾지 못했습니다」 류로 바꿔 주시면 좋겠다.**

> 시연 대본 3건(SYN-021·004·009)은 점수가 하한 위라 **화면이 그대로 나온다** — 녹화에는 영향이 없다.

## 3. 장민석 — 충돌 없음. 확인만 둘

1. **C-5 마스킹은 겹치지 않는다**(교차 검수로 확인). 민석 님의 중간 자막 숫자 가드는 **숫자 전용·중간 자막에만**,
   내 이름 끝 글자 수정은 **확정 경로의 이름 규칙**이다. 같은 발화를 두 규칙이 다르게 판정하는 자리는 없다.
2. **여권 조항(`TERM-4.23`)은 `EXCLUDED` 그대로 두었다.** 점수 하한을 넘어 1순위로 잡혀도 서버가 422 를 돌려주고
   미디에이터가 「절차 아님」으로 넘겨서 **거짓 「빠진 서류」는 생기지 않는다.**
   ⚠ **그 조항에 규칙을 붙이시면 그 순간 절차로 잡히기 시작한다** — 붙이실 때 알려 주시면 대본으로 다시 재겠다.
3. **내 도구가 기대는 계약**(깨지면 E2E 판정이 전부 ❌ 가 된다):
   - `GET /hub/calls`·`/transcript`·`/record` 를 **서비스 토큰으로** 읽을 수 있다 → `w8-call-owner-scope` 가 상담원 기준만 보면 깨진다

## 4. 모두가 알아야 할 것 — **점수 하한은 눈금에 묶여 있다**

`0.635` 는 **KoE5(의미 검색) 코사인 눈금**에서 고른 값이다. 그래서:

| 상황 | 무슨 일이 일어나나 |
|---|---|
| 의미 검색이 죽어 **BM25 로 내려가면** | BM25 점수는 대개 1 보다 커서 **하한이 늘 통과** → 옛 동작으로 조용히 되돌아간다 |
| **리랭커를 켜면** | 점수가 로짓 눈금이라 **전 통화에서 절차를 안 잡을** 수 있다 |
| 점수 필드가 안 오면 | 절차를 **영영 안 잡는다** (안전한 쪽이지만 조용하다) |

### ⚠ 이 중 하나는 **로컬에서 실제로 일어났다** (2026-09-24 실측)

`RETRIEVAL_EMBED_MODEL_DIR` 을 **상대 경로**로 주면 모델을 못 찾는데 **예외가 아니라 빈 층이 돌아온다** — 로그도 없다.
그 상태로 E2E 를 돌렸더니 점수가 BM25 원점수라 **하한이 한 번도 걸리지 않았고**(미채택 로그 0건), 대본 3건 중 2건이 실패했다.
**절대 경로로 고쳐 `retrieval_dense` 가 붙자 3건 모두 통과**했다(엉뚱한 판정 0 · 정답 절차 2/2 · 실제 점수 0.556·0.608·0.631 — 코사인 눈금).

→ 고친 것 둘: **기동 로그**(`server/main.py` — 「층이 비었다 — BM25 로 돈다」) · **`E2E.md` 에 절대 경로 명시**.
→ **운영에도 같은 함정이 있다**: 모델 경로가 어긋나면 `/health` 의 `spokes` 에서 `retrieval_dense` 가 사라지는 것이 유일한 신호였다. 이제 로그도 남는다.

**셋 다 경고가 없어서**, 미채택 시 **점수·하한을 남기는 로그를 넣었다**(`절차 미채택 call=… score=… 하한=…`).
「필요서류가 안 떠요」가 들어오면 **먼저 이 줄을 본다.** 점수가 `없음` 이면 눈금이 아니라 **필드가 안 온 것**이다.
