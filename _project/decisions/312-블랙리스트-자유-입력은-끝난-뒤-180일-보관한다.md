# 312 — 블랙리스트 자유 입력 문장은 끝난 뒤 180일 보관하고 비운다

**날짜**: 2026-09-15
**작성**: 장민석 (브랜치 `server`)
**관련**: `decisions/205` ⑤(반려 요청 사유·자막을 일정 기간 뒤 비운다 — 기간·방법 미정) · `decisions/309`(만료 변경 사유 — 보존 기간 미정)

## 맥락

블랙리스트 요청 사유·자막 발췌·만료 변경 사유는 사람이 쓴 문장이라 마스킹을 거쳐도 상세한 사정이 담긴다. 205 가 «반려된 요청은 일정 기간 뒤 비운다» 고 정했지만
기간도 실행 방법도 없었고, 309 로 만료 변경 사유가 새로 쌓이기 시작했다. 서버에는 주기적으로 도는 작업이 없다.

## 결정 (사용자 선택, 2026-09-15)

| | 선택 | 대안 |
|---|---|---|
| 기간 | **끝난 뒤 180일** | 1년 · 끝나면 바로 |
| 실행 | **관리자 API `POST /hub/blacklist-retention/purge`** | k8s CronJob 매일 |
| 범위 | **만료 변경 사유 + 반려 요청의 사유·자막** | 변경 사유만 |

- «끝난 시각» — 등록은 해제 시각, 해제가 없으면 만료 시각. 반려 요청은 결정 시각. 그 시각이 **지금 − 180일** 이전이면 비운다(경계 포함)
- **행을 지우지 않는다** — 문장만 표시 `(보존 기간이 지나 비움)` 로 바꾼다. 건수·시각·결정·변경 전후 만료 시각은 남는다. NOT NULL 이라 NULL 대신 표시 — «원래 비어 있었다» 와 구분된다
- 여러 번 불러도 결과가 같다 — 이미 비운 행은 다시 세지 않는다. 응답: 보존 기간 · 기준 시각 · 비운 건수 둘
- 규칙(180일·기준선)은 블랙리스트 도메인(`blacklist/domain/services/retention.py`)이 갖는다

## 근거

- 205 의 문장 그대로다: *조치 대상이 아닌 사람이 가장 상세한 기록을 갖는 상태를 두지 않는다*
- 관리자 API 는 인프라를 늘리지 않고, 나중에 주기 실행(CronJob)이 같은 경로를 부를 수 있다. 운영 인스턴스가 매일 02시에 꺼지는 것(런북 21장)도 CronJob 설계에 걸린다

## ⚠ 남는 것

- **180일의 근거는 없다**(절대 원칙 2) — 조직이 정하면 상수 하나를 바꾼다
- **누가 부르지 않으면 비워지지 않는다.** 주기 실행은 없다 — 부르는 사람·주기를 정하지 않았다
- **승인된 요청의 사유·자막, 등록의 해제 사유·승인 메모(`note`), 요약 재수정 사유(311)는 대상이 아니다** — 이번 범위 밖
- 운영 관리자 로그인이 돌아야 부를 수 있다

## 되돌리는 법

`main.py` 에서 `blacklist_retention_purge_router` 를 빼면 닫힌다. 이미 비운 문장은 되살릴 수 없다 — 그것이 목적이다.
