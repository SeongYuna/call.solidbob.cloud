# 323 — D-2 문의 유형은 지식베이스 장(章) 어휘로 제안한다

**날짜**: 2026-09-22
**작성**: 장민석 (브랜치 `server`)
**상태**: 채택 — 구현됨(배포 전). **측정 안 됨**(골든셋 D 케이스 0건)
**관련**: `306`(통화 후 초안 — 규칙 발췌, D-2 는 None 으로 둔다) · `310`(요약 확정 — 상담원이 유형을 고친다) · 미결 「D-2 문의 유형이 24/24 NULL」

---

## 맥락

`306` 은 「유형을 가를 규칙표가 없다 — 없는 규칙으로 분류하면 지어낸 값이다」로 D-2 를 늘 None 으로 뒀다. 운영 통화 24건이 전부 `inquiry_type` NULL 이다.
그런데 규칙표를 만들 재료는 이미 있었다 — 지식베이스 `TERM.md` 가 **장(章)으로 나뉘어 있고**(2장 대중교통 · 3장 생활하수도 · 4장 일반행정 · 5장 감염병 · 6장 재난·생계 지원금), 조항 제목이 그 장의 말을 담고 있다.

## 선택지

| | 판단 |
|---|---|
| **장 어휘 규칙표** — 조항 제목에서 뽑은 말로 고객 발화를 가른다 | 결정적·재현 가능 · 유형 이름이 지식베이스 장 이름이라 새 분류 체계를 지어내지 않는다 |
| 통화 중 고른 조항(추천 카드·필요서류 판정)의 장을 쓴다 | 더 정확할 수 있다. 조항 기록이 통화마다 남지 않고(`recommendation_card` 는 `document` FK 를 채우는 길이 없다) 포트가 하나 더 든다 |
| 생성 모델로 분류 | 판정을 모델에 맡기지 않는다(절대 원칙 9) |

## 결정

**장 어휘 규칙표** — `postcall/domain/services/inquiry_rules.py`.
- 고객 확정 발화만 · **처음 걸린 발화가 정한다**(곁가지보다 처음 문의) · 한 발화에 둘이 걸리면 많이 걸린 쪽, 같으면 표 순서
- 안 걸리면 **「미분류」** — NULL 은 「통화 후 처리 전」이라(`call_list_dto`) 처리했는데 못 가른 통화와 섞이면 안 된다(`w6-d2-inquiry-type-null` 완료 조건)
- 1장 총칙은 유형이 아니라 뺐다. 「여권」·「신분증」 은 모든 장에 나오는 서류라 어휘에서 뺐다
- **제안**이다 — 초안(`confirmed=False`)에 실리고, 상담원이 확정 화면에서 고친다(`310`)

## 근거

- 없던 것은 규칙이 아니라 **규칙표를 적는 일**이었다. 재료(장 구분)는 지식베이스에 있다
- 페르소나 대본(SYN-*)의 문의가 전부 이 다섯 장 안에 있다 — 시연에서 빈칸 대신 유형이 보인다

## ⚠ 한계

- **측정하지 않았다** — 정확도를 말하지 않는다(절대 원칙 2). 골든셋에 D 케이스가 생기면 잰다
- 어휘 규칙이라 「수도권」 같은 말에 「수도」 가 걸릴 수 있다. 제안이고 사람이 고친다

## 되돌리는 법

`summary_rules.build_draft` 의 `inquiry_type=classify_inquiry(...)` 를 `None` 으로 되돌린다(`e2e_check.py` 의 「D-2·문의 유형 저장」 검사도 함께 뺀다). 이미 저장된 제안은 `call.inquiry_type` 에 남는다.
