# 102 — 커스텀 도메인 `call.solidbob.cloud` 를 **가비아 DNS 로** 붙인다 (클라우드플레어 경유 안 함)

> ⚠ **이 문서는 두 군데가 뒤집혔다 (둘 다 2026-08-28 같은 날).** 본문은 기록으로 그대로 둔다.
> - **DNS 위치** — 가비아 → **클라우드플레어** (`decisions/103`)
> - **주소** — `call.solidbob.cloud` → **`docs.solidbob.cloud`** (`decisions/104`. `call` 은 프론트가 쓴다)
>
> **404 의 원인 분석과 「커스텀 도메인이 해법이다」라는 결론은 그대로 유효하다.**

**작성일**: 2026-08-28
**작성**: 정성윤
**상태**: 확정 — 저장소 쪽 반영 완료, **DNS·Settings 작업은 사람이 해야 남는다**
**갱신 대상**: `jekyll/_config.yml` · `jekyll/CNAME`(신규) · `.github/workflows/pages.yml`(주석) · `jekyll/open-items.markdown`
**관련**: `w1-pages-deploy`(Sprint 7 로 미뤄 뒀던 것을 앞당긴다) · `decisions/024`(`ai/` 도메인 서술 — 별개 사안)

## 맥락

배포된 사이트에서 **목차·문서 페이지 링크가 전부 404** 다.

```
동작:   https://solidbob02.github.io/call.solidbob.cloud/progress/     ← 상단 내비는 살아 있다
404:    https://solidbob02.github.io/docs/09/                          ← 본문 링크는 죽는다
```

원인은 **주소 한 겹**이다. 프로젝트 페이지라 사이트가 `/call.solidbob.cloud/` 아래에 놓이는데,
사이트 안의 링크가 **405곳이 `[9절](/docs/09/)` 같은 루트 절대경로**로 적혀 있다.
레이아웃의 상단 내비만 `relative_url` 을 쓰고 있어서 **내비는 되고 본문은 안 되는** 모양이 됐다.

**CI 가 이걸 못 잡는 이유도 여기 있다.** `test.yml` 의 링크 검사는 `jekyll build` 를
**`--baseurl` 없이** 돌린 `_site` 를 본다(즉 baseurl `""`). 배포는 `pages.yml` 이
`--baseurl /call.solidbob.cloud` 로 다시 빌드한다. **CI 가 검사한 사이트와 배포된 사이트가
다른 사이트다.** 405개 링크는 CI 쪽 조건에서는 전부 맞다.

## 선택지

| | 방법 | 판단 |
|---|---|---|
| A | **커스텀 도메인을 붙여 사이트를 루트에 올린다**(baseurl `""`) | ✅ |
| B | 링크 405곳을 `{{ '/docs/09/' \| relative_url }}` 로 고친다 | ❌ 문서 대부분을 건드리는 변경이라 **네 브랜치 전부와 충돌**한다. 새로 쓰는 링크마다 같은 실수가 재발하고, 표지에 이미 도메인을 적어 둔 마당에 주소도 그대로 남는다 |
| C | CI 도 `--baseurl` 을 주고 링크 검사를 맞춘다 | ❌ **깨진 걸 정확히 확인하는 것**일 뿐 고치지 못한다. A 를 하면 두 빌드가 저절로 같아진다 |

DNS 를 어디에 둘지는 그 안에서 다시 갈렸다.

| | 방법 | 판단 |
|---|---|---|
| A-1 | **가비아 DNS 에 CNAME 한 줄** | ✅ 레코드 1건. 존을 건드리지 않는다 |
| A-2 | 존을 클라우드플레어로 옮기고 거기서 건다 | ❌ **이 목적에는 얻는 게 없다.** 클라우드플레어는 서브도메인만 위임받지 못해(부분 설정은 엔터프라이즈) **네임서버를 통째로 옮겨야** 하고, 그러면 지금 살아 있는 apex·`www`(Vercel)를 다시 만들어야 한다. 게다가 **주황 구름(프록시)을 켜면 GitHub 의 인증서 발급이 막힌다** — DNS-only 로 두고 발급을 기다렸다가 켜야 하고, SSL 모드가 `Flexible` 이면 리다이렉트 루프가 난다 |

## 결정

**A-1. 가비아 DNS 에 CNAME 을 걸고, GitHub Pages 의 커스텀 도메인으로 `call.solidbob.cloud` 를 지정한다.**

사람이 해야 하는 두 단계 —

```
① 가비아 DNS 관리 →  호스트 call   타입 CNAME   값 solidbob02.github.io.   TTL 600
② GitHub → 저장소 Settings → Pages → Custom domain 에 call.solidbob.cloud 입력 → Save
   DNS check 통과 후 Enforce HTTPS 체크 (인증서 발급까지 몇 분~한 시간)
```

저장소 쪽은 반영해 뒀다 —

1. **`jekyll/_config.yml`** — `url` 을 `https://call.solidbob.cloud` 로. `baseurl` 은 `""` 유지.
2. **`jekyll/CNAME`** 신규 — ⚠ **Actions 로 배포하면 GitHub 은 이 파일을 읽지 않는다**(커스텀
   도메인은 저장소 설정에 저장된다). 표식으로 두는 것이고, 나중에 브랜치 배포로 바꾸면 그때 쓰인다.
   **①② 를 대신하지 못한다.**
3. **`pages.yml` 주석** — `--baseurl` 이 왜 자동으로 비워지는지.

`configure-pages` 가 `page_url` 의 경로 부분을 `base_path` 로 넘기므로, ② 가 끝나면
`--baseurl` 은 **빈 문자열이 되고 405개 링크가 전부 맞아떨어진다.** 워크플로는 안 고친다.
동시에 **CI 빌드와 배포 빌드의 baseurl 이 같아져서** 위의 "다른 사이트" 문제도 사라진다.

## 근거

- **존이 단순해서 오히려 A-1 이 싸다.** 지금 `solidbob.cloud` 에 있는 것은 apex `A 216.198.79.1`(Vercel)과
  `www CNAME …vercel-dns-017.com` **둘뿐**이고 MX·TXT 가 없다. `call` 은 **비어 있는 이름**이라
  새 레코드 한 줄이 기존 것과 겹치지 않는다.
- **클라우드플레어를 안 쓴다는 게 아니라, 이 문제의 해법이 아니라는 것이다.** 나중에
  `server.solidbob.cloud`(AWS 백엔드)에 프록시·터널·WAF 가 필요해지면 그때 존 이관을 따로 판단한다 —
  레코드가 2건뿐이라 그 시점에도 비용은 지금과 같다.
- **GitHub 이 인증서를 직접 발급한다**(Let's Encrypt). 정적 문서 사이트에 프록시가 더해 줄 게 없다.
- 표지·문서가 이미 `call.solidbob.cloud` 를 데모 주소로 적고 있다. 주소를 실제와 맞추는 쪽이 맞다.

## 되돌리는 법

Settings → Pages 의 Custom domain 을 비우고, 가비아에서 `call` CNAME 을 지운다.
`_config.yml` 의 `url` 을 `""` 로, `jekyll/CNAME` 을 삭제한다. 그러면
`https://solidbob02.github.io/call.solidbob.cloud/` 로 되돌아오고 — **404 도 함께 돌아온다.**
그 상태에서 링크를 고치려면 선택지 B(405곳 `relative_url`)뿐이다.

## 남는 위험

**도메인이 만료되거나 DNS 가 끊기면 링크가 아니라 사이트 주소 자체가 죽는다.**
`github.io` 주소는 커스텀 도메인이 붙으면 그쪽으로 리다이렉트되므로 대체 주소로 쓸 수 없다.
도메인 만료일 관리가 곧 사이트 가용성 관리가 된다.
