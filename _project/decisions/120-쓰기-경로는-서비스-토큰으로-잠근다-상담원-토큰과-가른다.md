# 120. 쓰기 경로는 «서비스 토큰」으로 잠근다 — 상담원 토큰과 가른다

- 날짜: 2026-09-20
- 작성: 정성윤
- 상태: 채택 — ~~**1단계(서버)만 구현됐다. 2~4단계가 남아 있는 동안 문은 열려 있다**~~ → 2026-09-22 1~3단계 운영 완료(`ingest_guard: locked`),
  4단계(fail-closed)는 코드로 들어갔다 — `w6-ingest-guard-fail-closed`. **배포(태그 올림) 전까지 운영 서버는 여전히 「없으면 연다」다**
- 관련: `decisions/307`(상담원 전용 토큰) · `110`(업로드 문 — 같은 모양의 선례) · `109`(콜 미디에이터 토큰) · `302`(누구나 고친다)
- 티켓: 없음(미결 「운영 파이프라인 왕복에서 나온 것」에서 추적)

---

## 맥락

2026-09-20 운영에 테스트 통화를 태워 보니 **쓰기 경로가 토큰 없이 200** 이었다 —
`POST /hub/calls` · `/hub/transcripts` · `/hub/recommendations` · `/hub/call-guard-checks` ·
`/hub/compliance-checks` · `/hub/closure-checks`. **주소를 아는 사람은 누구나 운영 DB 에 통화·전사를 쓸 수 있다.**
CORS 는 브라우저에만 걸린다. 콜 미디에이터 자신의 문(`/ws`·`/ingest`)은 잠겨 있는데 **그 뒤의 서버가 열려 있었다.**

기존 미결 「상담원 토큰을 어디까지 걸지」가 이 문제를 가리키고 있었지만 **「실제로 열려 있다」는 확인은 이번이 처음**이다.

## 선택지

| 후보 | 판단 |
|---|---|
| 상담원 토큰(`require_agent`)을 이 경로에도 건다 | 이미 있는 가드라 싸 보인다. **그런데 이 경로를 부르는 것은 사람이 아니다** — 콜 미디에이터(서버↔서버)다. 미디에이터에 「어느 상담원」의 토큰을 넣을지 답이 없다 |
| **서비스 토큰 하나를 서버·미디에이터가 나눠 갖는다** | 부르는 주체와 맞는다. 스키마 변경 없음 · 환경변수 1개 · 가드 1개. 업로드 문(`110`)과 같은 모양이라 새로 배울 것이 없다 |
| 상담원 토큰을 대시보드 → 미디에이터 → 서버로 중계한다 | **「누가」 썼는지까지 남는다** — 가장 정확하다. 대신 프론트·미디에이터·서버 세 곳이 바뀌고 `apps/` 는 조서희 님 전담이다. 남은 기간에 비해 크다 |

## 결정

**서비스 토큰(`INGEST_SERVICE_TOKEN`)으로 잠근다.**

- **대상은 「콜 미디에이터만 부르는」 쓰기 일곱**이다 — 위 여섯 + `POST /hub/required-docs-checks`.
  **프론트 세 앱은 이 일곱을 한 곳도 부르지 않는다**(2026-09-20 전수 grep).
- **대시보드가 직접 부르는 쓰기(`/close` · 요약 확정·재수정 · 카드 피드백 · 공백 신고)는 넣지 않는다.**
  브라우저는 서비스 비밀을 가질 수 없다 — 그쪽은 **사람 토큰(`require_agent`) 몫**이고 별개의 일로 남긴다.
- 모양은 업로드 문과 같다 — `Authorization: Bearer <토큰>`, 바이트 `compare_digest`(비-ASCII 입력에 500 이 나지 않게).
- 일곱 라우터가 전부 라우트 하나씩이라 **합성 루트(`main.py`) 한 곳에서** 건다.

### 업로드 문과 다른 점 하나 — **없으면 연다**

업로드 문은 토큰이 없으면 잠긴다(fail-closed). 이 문은 **없으면 열린다.**
서버를 먼저 배포하는 순간 **돌고 있는 미디에이터가 전부 401 이 되는 것**을 피하려는 **이행기 동작**이다.

**조용히 열려 있지 않게** `/health` 에 `ingest_guard: "open" | "locked"` 를 실었다(값이 아니라 상태만 — SEC-2).
이 저장소는 「설정은 있는데 안 붙는다」·「빈 채로 초록불」 같은 **조용한 상태**에 여러 번 당했다.

## 전환 순서 — 어기면 통화가 막힌다

```
1. 서버      토큰이 «설정돼 있을 때만» 요구한다           ← 2026-09-20 구현 (server 0.1.19). 시크릿엔 아직 없다 → 영향 0
2. 미디에이터 `CORE_API_TOKEN` 이 있으면 Authorization 헤더로 보낸다 (hub_http.ts · 태그 올림)
3. 시크릿    같은 값을 `server-env`(INGEST_SERVICE_TOKEN) 와 미디에이터 쪽에 넣는다 → 이 순간부터 실제로 잠긴다
             확인: /health 의 ingest_guard 가 "locked" · 토큰 없는 POST /hub/transcripts 가 401 · 합성 통화 1건 왕복
4. 서버      「없으면 연다」를 걷어 fail-closed 로 (업로드 문과 같게)
```

**3번을 2번보다 먼저 하면 운영의 모든 통화가 401 로 막힌다.**

## 남는 것

- **사람이 부르는 쓰기 경로는 여전히 열려 있다**(`/close` 등). 이 결정의 범위 밖이고 미결에 남긴다.
- 서비스 토큰은 **「미디에이터가 썼다」까지만** 말한다. 어느 상담원의 통화인지는 증명하지 않는다 — 세 번째 선택지가 그것을 푼다.

## 되돌리는 법

`main.py` 의 `_INGEST_ONLY` 를 비우면 문이 사라진다. 시크릿에서 `INGEST_SERVICE_TOKEN` 을 빼도 같은 효과다(1~3단계 동안).
