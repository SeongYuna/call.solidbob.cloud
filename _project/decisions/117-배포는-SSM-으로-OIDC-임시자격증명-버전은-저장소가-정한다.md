# 117. 배포는 SSM 으로, 자격증명은 OIDC 임시, 버전은 저장소가 정한다

- 날짜: 2026-09-19 (**설계·구현은 2026-09-09~09-14. 이 문서는 뒤늦게 남기는 기록이다**)
- 작성: 정성윤
- 상태: 채택 (이미 운영 중 — `release.yml` 이 이대로 돈다)
- 관련: `decisions/105`(한 컨테이너·한 도메인) · `107`(컴포즈 → k3s) · `111`(배포 태그 게이트) · `114`(필수 검사 다섯) · `116`(자동 중지·AMI 를 하지 않는다)
- 티켓: `w3-cicd-release-pipeline`

---

## 맥락

`main` 에 머지하면 이미지를 굽고 EC2 의 k3s 에 배포된다. 이 파이프라인은 2026-09-09~09-14 에
만들어져 **09-14 PR #74 에서 네 잡이 전부 통과**했고 그 뒤 계속 돌고 있다.
그런데 **설계가 갈린 지점 넷에 결정 기록이 없었다** — 티켓 본문에만 적혀 있었다.
번호를 예약해 둔 `108` 은 운영 DB RDS 이관이 가져갔고 태그 게이트는 `111` 이 가져가면서
파이프라인 자체의 기록만 빈 채로 남았다. **이 문서가 그 빈자리를 채운다**(새 결정이 아니다).

## 결정 — 넷

**① 버전은 저장소가 정한다.** `infra/k8s/base/kustomization.yaml` 의 `images.newTag` 를 읽어 그 태그로 굽는다.
CI 가 태그를 만들어 저장소에 되쓰지 **않는다**. 버전 올리기는 **PR 안에서 사람이** 한다.

- 왜: main 이 보호돼 있어 봇이 push 할 수 없고, 되쓰면 「저장소 = 클러스터」 불변식이 흔들린다.
- 딸린 것: 코드가 바뀌었는데 태그가 그대로면 배포가 막힌다 → 그 판정을 **머지 전으로** 당긴 것이 `111`(`tag-check`)이다.
- ⚠ `sha-<커밋>` 자동 태그는 **기각**이다 — 부팅 수렴 스크립트(`converge.sh`)가 저장소의 `newTag` 를 직접 읽어
  매일 되돌려 놓기 때문이다.

**② 인스턴스에서 git 을 쓰지 않는다.** 러너가 `kubectl kustomize` 로 렌더한 YAML 을 base64 로 SSM 에 실어 보내고,
인스턴스는 그것을 그대로 적용한다. 렌더 결과는 `/opt/callguard/current.yaml` 에 남아 부팅 시 자동 수렴이 재사용한다.

- 왜: 2026-09-09 확인 결과 인스턴스에 git 도 클론도 없었다. 만들 이유가 없다 —
  **CI 가 렌더한 그 YAML 이 그대로 적용되는 편이 어긋날 여지가 적다.**

**③ 통로는 SSM 이다. 포트를 열지 않는다.**

- 왜: 러너 IP 는 매번 바뀌는데 6443·22 는 담당자 IP 하나로만 열려 있다.
  GitHub IP 대역을 여는 것은 **6443 을 인터넷에 여는 것과 같다.**
- 부수 효과: 사람이 운영을 읽을 때도 같은 통로를 쓴다 — 2026-09-19 에 이 경로로
  이미지 태그·k8s 오브젝트·운영 DB 를 확인했다(`ssm send-command` + `get-command-invocation`,
  세션 매니저 플러그인 없이 된다).

**④ 자격증명을 저장하지 않는다.** OIDC 로 `callguard-deploy-role` 을 빌린다(1시간 임시).
신뢰 정책은 `ref:refs/heads/main` 한정이고, GitHub OIDC 를 신뢰하는 역할은 그것 하나뿐이다(09-15 확인).

- 왜: 대안은 장기 액세스 키를 GitHub Secrets 에 넣는 것인데, 그건 계정 하나를 통째로 맡기는 것이다.
- ⚠ **옛 서술 정정**: 이 항목은 원래 *"Root 단독 운영이라 대안이 Root 액세스 키뿐"* 이라고 적혀 있었다.
  **사실과 다르다** — 이 계정의 루트에는 액세스 키가 **0개**이고, 장기 키는 IAM 사용자 `admin`
  (`AdministratorAccess`, 키 1개, 2026-07-24 생성)의 것 하나뿐이다(2026-09-19 실측).
  결론(장기 키를 GitHub 에 두지 않는다)은 그대로다.

## 되돌리는 법

- ①을 되돌리려면 `release.yml` 이 커밋 SHA 로 태그를 만들게 하고 **`converge.sh` 가 저장소를 읽지 않도록** 같이 고친다. 둘 중 하나만 고치면 매일 아침 옛 이미지로 되돌아간다.
- ②③은 인스턴스에 6443 을 러너 대역으로 열고 `kubectl` 을 직접 치는 구성으로 바꿀 수 있다 — **포트를 여는 대가**를 받는다.
- ④를 되돌리려면 장기 키를 Secrets 에 넣는다. 권장하지 않는다.

## 남는 한계

**`destroy` → `apply` 로 같은 상태를 다시 세울 수 없다.** 운영 구성은 콘솔과 EC2 안에만 있고
`infra/terraform/` 은 설계서로만 남는다. 대체물인 AMI 스냅샷도 **`decisions/116` 으로 뜨지 않기로 했다** —
즉 **인스턴스를 잃으면 노드를 손으로 다시 세워야 한다.** 지우지 않고 여기 적어 둔다(절대 원칙 8).
