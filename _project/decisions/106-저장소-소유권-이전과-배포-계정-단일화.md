## Vercel 이전 — 남은 절차

**걸림돌은 하나다: 한 도메인은 한 Vercel 계정에만 붙는다.** 조서희가 먼저 놓아줘야 한다.

1. 정성윤 Vercel → Import `SeongYuna/call.solidbob.cloud`
   → Root Directory **`apps/platform`** · Vite · `npm run build` · `dist` · Production Branch `main`
   → `*.vercel.app` 에서 최신 랜딩 확인. **여기까지 `www` 는 살아 있다.**
2. 클라우드플레어 `www`·apex TTL 을 Auto(300초)로 낮춘다.
3. 조서희 프로젝트 → Settings → Domains → `solidbob.cloud`·`www` **Remove** ⏱ 다운타임 시작
4. 정성윤 프로젝트에 `www`(Primary) + apex(Redirect to `www`) 추가
5. 클라우드플레어 갱신 — `_vercel` TXT 2건 **새 값**(복사 버튼으로), `www` CNAME **새 해시**,
   apex `A` 는 그대로, **전부 회색 구름**(`103`)
6. 권위 서버 직접 질의로 검증 + 라이브 번들에 `핵심 어시스트 기능`·`동시 통번역 언어` 확인

> 4단계에서 Vercel 이 TXT 검증 챌린지를 주면 3단계 없이 붙을 수 있다 — **4를 먼저 시도하고
> 막히면 3으로 간다.** 다운타임이 거의 0 이 된다.

**뒤처리**: 조서희를 정성윤 Vercel 팀에 초대한다(안 그러면 `frontend` Preview 를 못 본다 —
지금 있던 것을 뺏는 셈이다). `docs`·`api` 레코드는 건드리지 않는다.

## 실제로 어떻게 됐나 (2026-09-03 당일 완료)

**예상보다 쉬웠다 — 조서희가 도메인을 놓아줄 필요가 없었다.**

정성윤 계정에 프로젝트를 만들고 `Add Existing` 으로 `www`·apex 를 추가하자 Vercel 이
**`Verification Required` + TXT 챌린지**를 줬다(위 절차의 «붙이기를 먼저 시도한다» 쪽이 걸렸다).
새 `_vercel` TXT 2건을 클라우드플레어에 넣자 **검증이 통과하면서 도메인이 그대로 넘어왔다.**
조서희 프로젝트에서 Remove 하는 단계는 **실행되지 않았다.**

| | 값 |
|---|---|
| 새 `_vercel` TXT | `solidbob.cloud,d6ed4bb765cc19600009` · `www.solidbob.cloud,8b6c87dca5bf2a244207` |
| 체감 다운타임 | **없다** — 전환 전후 `www` 가 계속 200 |

⚠ **`www` CNAME 은 옛 해시(`ea6aaafa…`) 그대로인데 정상 동작한다.** Vercel 엣지가 CNAME 해시가
아니라 **Host 헤더로 프로젝트를 판단**하기 때문이다. 이 저장소의 옛 DNS 문서가
*"호스트명 문자열 자체가 프로젝트 식별자라 한 글자도 틀리면 안 된다"* 고 적어 뒀는데
**실측으로 그렇지 않았다** — `_project/dns-solidbob-cloud.md` 에 정정했다.

### 대시보드도 같은 날 올렸다

같은 저장소에서 **두 번째 프로젝트**(Root Directory `apps/dashboard`)를 만들어 붙였다.
환경변수는 **비워 둔다** — `VITE_GATEWAY_WS_URL` 이 비면 `MockGatewayClient` 로 도는데,
`services/gateway` 는 코드가 0줄이고 `server` 도 아직 안 떠서 지금은 그게 맞다.

처음 `dashboard.solidbob.cloud` 로 붙였다가 **`decisions/104` 대로 `call.solidbob.cloud` 로
옮겼다** — `104` 가 `call` 을 프론트 데모에 배정해 뒀고, 그 이름을 비워 두면 아무도 안 쓰는
이름이 된다. `call` 을 먼저 붙여 200 을 확인한 뒤 `dashboard` 를 뗐다(무중단).
