# 315 — `/close` 와 카드 피드백에 문을 단다 · 상담원 토큰은 PC 에 남긴다

**날짜**: 2026-09-22
**작성**: 장민석 (브랜치 `server`)
**관련**: `decisions/120`(쓰기 일곱 경로 서비스 토큰) · `122`(상담원 토큰 만료 없음 — 폐기로 관리) · `307`(상담원 토큰) · 부록 A-1 · 티켓 `w6-open-write-guards` · 미결 「상담원 토큰을 어디까지 걸지」

## 맥락

`POST /hub/calls/{id}/close`(통화 후 초안, 통화를 닫는다)와 `POST /hub/cards/{id}/feedback` 이 **어느 토큰도 요구하지 않았다.**
`main.py` 주석은 「사람 토큰 몫」이라 적었지만 실제로 걸린 것은 요약 확정·재수정뿐이었다. 주소를 아는 누구나 통화를 닫고 초안을 덮고 피드백을 쓸 수 있었다.
카드 피드백에는 제약이 있었다 — **상담원 ID 를 일부러 받지 않는 API**라, 상담원 토큰을 걸면 카드 품질 데이터가 상담원 줄 세우기 데이터가 될 수 있다.

## 결정 (사용자 선택, 2026-09-22)

1. **`/close` — 상담원 토큰 또는 서비스 토큰**(`hub/dependencies/close_guard.py`). 부르는 쪽이 대시보드(상담원)와 합성 통화 재생기(사람 없음)다.
   재생기는 `CORE_API_TOKEN` 을 싣게 고쳤다. `ingest_guard` 와 달리 **서비스 토큰이 미설정이어도 열지 않는다**(상담원 토큰 길이 늘 있다). 누가 닫았는지는 기록하지 않는다
2. **카드 피드백 — 상담원 토큰을 확인하되 누구인지는 버린다.** 라우터에 `dependencies=[Depends(require_agent)]` 로 걸어 가드의 반환값이
   **라우트 함수에 아예 들어오지 않는다** — 넘길 수 없으니 저장할 수도 없다. 라우트 인자·`CardFeedback` DTO 에 상담원 자리가 없음을 테스트로 고정했다.
   서비스 토큰은 여기서 받지 않는다
3. **상담원 토큰은 PC 에 남긴다 — PC 한 대당 한 번만 준다.** 지금 화면(`apps/call/src/lib/agentToken.ts`)은 `sessionStorage` 라 탭을 닫으면 잊는다.
   `localStorage` 로 바꾼다(조서희 님 작업 — 서버 변경 없음). 잃어버린 PC·퇴사는 **폐기**로 끊는다(`122` 와 같은 관리 방식)

## 근거

- XSS 로 토큰을 읽는 위험은 `sessionStorage` 도 같다 — `localStorage` 로 새로 생기는 위험은 「남는 시간」 하나이고 그것은 폐기로 관리한다
- 관리자가 탭마다 링크를 다시 보내는 부담이 컸다(사용자 지적)
- 카드 피드백을 열어 두는 것(대안)은 누구나 채택률을 조작할 수 있게 둔다 — E-1 품질 데이터가 오염된다

## ⚠ 남는 것

- **서버만 먼저 잠그면 화면이 깨진다** — `apps/call` 의 `closeCall`·`submitCardFeedback` 이 아직 토큰을 싣지 않는다. 프론트가 바뀐 뒤 머지한다
- **여러 사람이 한 PC 를 쓰면** 뒷사람의 행동이 앞사람 이름으로 남는다 — 교대 시 로그아웃(`clearAgentToken`)이 전제다
- 읽기 경로(통화 목록·전사·기록)의 무인증은 이 결정 범위 밖이다(미결 그대로)
- 더 나은 방식으로 셋을 검토했고 이번엔 채택하지 않았다: ① 쓰기 일곱 경로를 ingress 에서 외부 차단(미디에이터는 클러스터 안 `http://callguard-server` 로 부른다 — 가장 효과가 크다, 인프라 변경이라 별도) ② 1회 교환 → `HttpOnly` 세션 쿠키 ③ 통화 단위 권한 토큰(서버가 상담원을 아예 모른다 — A-1 에 가장 맞지만 셋 다 바뀐다)

## 되돌리는 법

`postcall_router.py`·`card_feedback_router.py` 의 `dependencies=[...]` 를 걷는다. 프론트의 `localStorage` 는 `sessionStorage` 로 되돌리면 된다.
