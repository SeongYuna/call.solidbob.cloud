# 130. 운영 DB 의 합성 통화 4건은 남긴다 — 수동 QA·시연 재료다

- 날짜: 2026-09-22
- 작성: 정성윤
- 상태: 채택
- 관련: `decisions/127`(공개 데모는 라이브) · `319`(수동 QA 게이트) · `316`(블랙리스트 요청 — 온도 미측정)
- 티켓: `w6-synthetic-calls-retention`(이 결정으로 닫음) · `w5-manual-qa-full-stack`(재료로 씀)

---

## 맥락

09-22 운영 확인으로 합성 통화 4건이 운영 DB 에 남았다 —
`syn-prod-syn-010-20260922`(류준) · `syn-prod-syn-008-20260922`(류준) · `syn-prod-syn-010-seongyun-130124` ·
`syn-prod-syn-006-20260922-132934`(블랙리스트 요청 확인용, 콜 가드 3건). 전부 `stt_engine=synthetic-script` 로 구분된다.
09-21 에는 테스트 통화를 자식 행부터 지웠다(`closure_item` → `closure` → … → `call`). 이번에도 지울지 정해야 한다.

## 선택지

| | 안 | 판단 |
|---|---|---|
| A | 4건 다 남긴다 | ✅ 채택 |
| B | 4건 다 지운다 | 수동 QA 3~6장(통화 중 버튼 · 종료·요약 · 승인·반려·해제)의 재료가 없어진다 — 다시 흘려야 한다 |
| C | 류준 님 2건만 남긴다 | 콜 가드 3건이 붙은 SYN-006 이 블랙리스트 화면 QA 의 유일한 재료라 뺄 수 없다 |

## 결정

**4건 다 남긴다.** 수동 QA(`decisions/319`)와 시연 리허설의 재료로 쓴다. 지우지 않는다.

- 화면에서는 `stt_engine=synthetic-script` 로 구분된다 — 조서희 님께 알린다(상담기록 목록에 표시할지는 화면 쪽 판단).
- SYN-006 에 붙은 블랙리스트 **등록 1**(09-22 승인, 만료 2027-03-21)은 통화와 별개다 — 관리자 화면에서 **해제**한다(운영 확인용 등록을 살려 두지 않는다).
- 발표 뒤 종료 정리(`decisions/133`)에서 운영을 내리면 같이 사라진다. 그 전에 지울 이유가 생기면 09-21 방식(자식 행부터)으로 지우고 행 수를 기록에 남긴다.

## 근거

- 재료를 지우고 다시 흘리면 STT 를 타지 않아 비용은 없지만, 재생기가 마지막 턴을 잃는 결함(`w6-replay-last-turn`)이 있어 **같은 상태를 다시 만들 수 있다는 보장이 없다.**
- 운영 DB 의 통화 14건 중 09-11~15 테스트 통화 10건도 남아 있다 — 4건을 지운다고 「깨끗한 운영 DB」가 되지 않는다.

## 되돌리는 법

지우기로 하면 ID 4개를 명시해 자식 행부터 지우고 행 수를 `_logs/` 에 남긴다. 이 파일의 상태 줄을 「철회」로 고친다.
