## 측정 (2026-10-13, 커밋 `63c4d41`, 로컬 CPU · `eval/review-2026-10/`)

### 1. 빼면 어떻게 되나 — NER 없이(규칙만) vs 지금 NER

| 조건 | 규칙만 | 규칙 + 지금 NER |
|---|---|---|
| 골든셋 C-5 (n 40, 오류 없음) | 누락 0 | 누락 0 |
| STT 오류 5% (시드 3 중 최대) | 1 | 1 |
| 10% | 3 | 2 |
| 15% | 5 | 2 |
| 20% | **6** | 2 |
| 실제 AI Hub 고객 발화 10,223 — 규칙이 놓친 이름·주소를 NER 이 더 가린 것 | — | **16조각**(읽고 판정, 오탐 14 별도) |

→ **빼면 안 된다.** 오류 없는 골든셋에서는 규칙만으로도 0 이지만 그 규칙은 그 골든셋을 보고 보강한 것이고(자기충족), STT 오류가 있으면 누락이 3배로 늘고, 실제 발화에서 규칙이 놓치는 이름·주소가 있다. 실제 STT 단어 오류율은 0.358 이다(`03_new_measurements.md` M3). 원칙 3 을 깬다.

### 2. 대신 무엇으로 — 라이선스가 열린 후보

HF 에서 한국어 NER 중 라이선스·학습 데이터가 밝혀진 것을 찾았다. KLUE(CC-BY-SA-4.0) 로 학습한 것만 남겼고, F1 이 낮은 것(`sunwooooong/klue-bert-finetuned-klue-ner` F1 0.39)은 뺐다.
**`vmaca123/korean-pii-ner-v3`** — `klue/roberta-large` 미세조정 · **CC-BY-SA-4.0**(상업 이용 가능, 수정본은 같은 조건) · 개인정보 가드레일용 · 라벨 NAME/ADDRESS/ORG · 카드 기준 KLUE-NER 검증 micro F1 0.792

| 조건 | 규칙 + 지금 NER | **규칙 + 후보** |
|---|---|---|
| 골든셋 오류 0 / 5 / 10 / 15 / 20% 누락(최대) | 0 / 1 / 2 / 2 / 2 | **0 / 0 / 0 / 0 / 0** |
| 실제 고객 발화 — NER 이 더 가린 조각 | 30 (이름·주소 16 · 오탐 14) | 40 (이름·주소 15 · **오탐 25**) |
| 상주 메모리 추가 | 478 MB | **1,349 MB** |
| 발화당 태깅(CPU) | 13 ms | 38 ms |

- 후보는 **누락 쪽에서 낫고**(STT 오류 20% 까지 0) **과잉 쪽에서 나쁘다**(실제 발화 1만 건 중 오탐 25 = 0.24% 의 발화). 원칙 3 순서(누락 0 > 과잉 억제)로 후보가 낫다
- ⚠ 후보는 우리 골든셋을 본 적이 없다 — 지금 NER 주변 규칙(`spans.py` 이름 꼬리·주소 어절)은 지금 NER 의 실측 버릇에 맞춰 쓴 것이라, 후보에 맞춘 조정은 하지 않았다. 그래도 0 이었다
- ⚠ 후보 카드는 학습 데이터를 「klue + 내부 테스트 3,401문장」으로 적는다 — 내부 데이터의 출처는 카드에 없다. 라이선스는 저작자가 CC-BY-SA-4.0 로 밝혔다

## 결정

1. **NER 을 빼지 않는다.** 위 1 의 측정 — 빼면 실제 STT 조건에서 누락이 늘어 원칙 3 을 깬다
2. **교체 대상은 `vmaca123/korean-pii-ner-v3`.** 라벨만 옮긴다(`NAME → PER`, `ADDRESS → LOC`, `ORG` 버림) — `pii_ner` 도메인(`spans.py`)은 그대로
3. **지금(발표·시연)은 바꾸지 않는다.** `138` 고정 중이고, 바꾸면 서버 프로세스가 약 3.2 GB 로 **운영 파드 상한 3Gi 를 넘는다** — 인프라 변경(메모리 상한)이 함께 가야 한다. 시연은 비상업 용도라 지금 모델로 둔다
4. 발표에서는 「납품 가능」 이라고 말하지 않고 「라이선스 문제를 찾았고, 바꿀 모델을 재서 정해 뒀다」 로 말한다
