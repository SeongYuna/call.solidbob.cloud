# 122. 상담원 토큰에 만료를 두지 않는다 — 폐기(revoke)로 관리한다

- 날짜: 2026-09-21
- 작성: 정성윤
- 상태: 채택
- 관련: `decisions/307`(상담원 전용 토큰) · `403`(관리자 로그인 — access 5분·refresh 10분은 테스트 값) · `120`(쓰기 경로 서비스 토큰)

---

## 맥락

`agent_token` 테이블에는 `issued_at`·`revoked_at` 만 있고 **`expires_at` 이 없다**(2026-09-20 스키마 확인).
한 번 발급한 토큰은 **관리자가 폐기하기 전까지 영원히 유효하다.** 2026-09-17 멘토링 브리핑이 이것을 「확인 안 된 것」으로 올렸다.

## 선택지

| 후보 | 판단 |
|---|---|
| 만료를 둔다(예: 30일) | 유출된 토큰이 저절로 죽는다. 대신 **스키마 컬럼 + 운영 마이그레이션 + 발급·검증 코드 + 관리자 화면**이 함께 바뀐다 |
| **두지 않는다** | 지금 구조 그대로. 유출 대응은 **폐기**다(`POST /admin/agent-tokens/{id}/revoke` — 이미 있고 관리자 화면에도 붙어 있다) |

## 결정

**지금은 만료를 두지 않는다.** 토큰은 폐기로 관리한다.

## 근거

- **규모가 작다.** 토큰을 가진 사람은 팀원 몇 명이고, 발급·목록·폐기가 관리자 화면에 이미 있다.
- **저장되는 것은 해시뿐이다**(SHA-256, 원문 `cga_…` 은 발급 응답으로 한 번만 나간다) — DB 가 새도 토큰은 새지 않는다.
- 만료를 넣는 비용(스키마·마이그레이션·화면)이 남은 기간의 임계 경로(재측정 → 6주차 판정 → 발표)에 없다.

## 남는 위험

- **유출된 토큰은 누가 알아채기 전까지 계속 쓰인다.** 만료가 있었다면 저절로 끊겼을 것이다.
- 상담원 토큰이 걸린 경로는 아직 **블랙리스트 요청 하나**다 — 대시보드가 직접 부르는 다른 쓰기(`/close`·요약 확정·카드 피드백)는
  **토큰 없이 열려 있다**(`120` 의 범위 밖). 만료보다 그쪽이 먼저다.

## 되돌리는 법

`db/generate_schema_docs.py` 의 `agent_token` 에 `expires_at TIMESTAMPTZ NULL` 을 더하고(NULL = 만료 없음 — 기존 토큰이 안 죽는다),
발급 시 채우고 `require_agent` 가 본다. 운영은 `ALTER TABLE … ADD COLUMN` 한 줄이다.
**마감 뒤 전시용으로 남길 때는 이 결정을 다시 본다** — 아무도 지켜보지 않는 서버에서는 「폐기로 관리」가 성립하지 않는다.
