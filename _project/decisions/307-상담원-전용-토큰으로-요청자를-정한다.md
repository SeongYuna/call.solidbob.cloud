# 307 — 상담원 요청자는 관리자가 발급한 상담원 전용 토큰으로 정한다

**날짜**: 2026-09-15
**작성**: 장민석 (브랜치 `server`)
**관련**: `decisions/304` 「⚠ 남는 것」 첫 줄(상담원 인증 없음) · `decisions/403`(관리자 로그인) · 티켓 `w4-blacklist-api`

## 맥락

`POST /hub/blacklist-requests` 는 요청자를 본문 `requested_by` 로 받아, **`agent` 에 있는 아무 ID 로나 요청할 수 있었다**(`decisions/304`).
상담원 로그인은 없고, 있는 것은 관리자 구글 로그인과 게이트웨이 공용 토큰(`GATEWAY_INGEST_TOKEN`, 사람을 구분하지 않는다)뿐이다.

## 선택지

| | 내용 | 걸리는 것 |
|---|---|---|
| ① 관리자 구글 로그인 확장 | 상담원도 구글 OAuth, `admin_account.agent_id` 재사용 | 상담원마다 구글 계정 · Redis 필수 · 프론트 로그인 화면 |
| ② **상담원 전용 토큰** | 관리자가 상담원별 토큰을 발급, 요청은 `Authorization: Bearer` | 발급·폐기 관리가 새로 생긴다 |
| ③ 보류 | `agent` 존재 검사(422)만 | 구멍이 그대로 |

## 결정 (사용자 선택, 2026-09-15)

**②.**

- 새 앱 **`server/apps/agent_auth/`** — `admin_auth` 와 같은 헥사고날 단면. `.importlinter` 계약 4종에 등록
- 테이블 **`agent_token`**(`id`·`agent_id` FK·`token_hash` UNIQUE·`issued_by` FK `admin_account`·`issued_at`·`revoked_at`)
- 토큰은 `cga_` + 256비트 난수(`secrets.token_urlsafe(32)`). **DB 에는 SHA-256 hex 만** — 원문은 발급 응답에 한 번만 나간다
  (`admin_refresh_token` 과 같은 원칙). 키(pepper)를 두지 않는다 — 난수라 전수 대입이 불가능해 **새 비밀 설정이 필요 없다**
- 관리 API(**관리자 로그인 필수**): `POST /admin/agent-tokens {agent_id}` → 201 + 토큰 · `GET /admin/agent-tokens[?agent_id=]` · `POST /admin/agent-tokens/{id}/revoke`
- 가드 **`require_agent`**(`agent_auth/adapter/inbound/api/agent_guard.py`) — 없거나 폐기됐거나 `cga_` 가 아니면 401. `cga_` 가 아닌 값은 DB 를 보지 않는다
- **`POST /hub/blacklist-requests` 에 가드를 달고 `requested_by` 를 본문에서 뺐다.** 본문에 실어 보내도 무시되고 토큰의 상담원이 저장된다
- 폐기는 행을 지우지 않고 `revoked_at` 만 남긴다(멱등 — 처음 폐기 시각 유지). 절대 원칙 8

## 근거

- 구멍이 «누가 요청했는가를 본문이 정한다» 하나라, 사람별 비밀 하나로 막힌다. ①은 같은 구멍을 막으려고 구글 계정·Redis·로그인 화면을 상담원 전원에게 요구한다
- 관리자 로그인 기반 위에 얹었다 — 발급 권한은 이미 있는 `require_admin` 이 준다. 새 인증 체계를 두 벌 만들지 않는다
- 저장 원칙을 기존 refresh token 과 맞췄다 — 코드 리뷰어가 두 규칙을 따로 기억할 필요가 없다

## ⚠ 남는 것

- **만료가 없다** — 폐기로만 끊는다. 토큰이 새면 관리자가 폐기해야 한다. 기간이 필요하면 `expires_at` 을 더한다
- **가드를 단 곳은 블랙리스트 요청 하나다.** 카드 피드백·수동 검색·통화 목록·전사 조회 등 상담원 화면 API 는 여전히 인증이 없다 — 어디까지 걸지는 미결
- **프론트가 바뀌어야 한다**(조서희) — `apps/call` 은 요청에 `Authorization: Bearer <토큰>` 을 싣고 `requested_by` 를 빼야 한다. 토큰을 어디에 두는지(입력·sessionStorage)는 프론트가 정한다. `apps/admin` 에 발급·폐기 화면이 필요하다
- **운영 순서**: `db/migrations/2026-09-15-agent-token.sql` 을 **이미지를 올리기 전에** 넣는다. 안 넣으면 블랙리스트 요청·토큰 API 가 500(`42P01`)
- 발급하려면 관리자 로그인이 운영에서 돌아야 한다 — 09-14 기준 운영 관리자 로그인은 500 이다(`w4-admin-auth-runtime`)

## 되돌리는 법

1. `blacklist_request_create_router.py` 의 `require_agent` 의존성을 지우고 `requested_by` 를 스키마·커맨드로 되돌린다
2. `main.py` 의 `agent_token_router` import·include 를 지우고 `server/apps/agent_auth/` 를 지운다 · `.importlinter` 의 `agent_auth` 를 지운다
3. 스키마: `db/generate_schema_docs.py` 의 `agent_token` 을 지우고 재생성 · 운영에서는 `DROP TABLE "agent_token"`(다른 테이블이 참조하지 않는다)
