# 310 — 통화 후 요약 초안을 상담원이 고쳐서 확정한다

**날짜**: 2026-09-15
**작성**: 장민석 (브랜치 `server`)
**관련**: `decisions/306`(규칙 발췌 초안) · `decisions/205` ⑧(`summary_confirmed_at` — NULL 이면 초안) · 부록 A-1 · `decisions/307`(상담원 토큰)

## 맥락

통화 후 요약·유형·후속조치는 **초안**이다 — DTO 이름이 `CallSummaryDraft` 이고 서버가 `confirmed` 를 늘 `false` 로 덮는다.
설계는 «확정은 상담원이 화면에서 한다» 였는데 **확정하는 API 가 없어** 모든 요약이 영원히 초안으로 남았다. 초안은 규칙 발췌라 틀리거나 빠진 것이 있다.

## 선택지

| | 내용 |
|---|---|
| ① **고쳐서 확정** | 상담원이 요약 문구·유형·후속조치를 고친 뒤 확정 |
| ② 초안 그대로 확정 | «확인했다» 표시만 — 틀린 요약이 확정된다 |
| ③ 보류 | 초안으로만 둔다 |

## 결정 (사용자 선택, 2026-09-15)

**①.** `POST /hub/calls/{call_id}/summary-confirmation {summary_text, inquiry_type?, follow_up_actions[]}`

- **상담원 토큰 필수** — 확정은 «사람이 봤다» 는 표시라 익명으로 받지 않는다. **누가 확정했는지는 저장하지 않는다** — 카드 피드백과 같은 이유(부록 A-1, 상담원 단위 집계 금지)
- 고친 문구(요약·유형·후속조치)는 **저장 전 마스킹** — 사람이 쓴 문장에는 이름·번호가 새로 섞인다(블랙리스트 사유와 같은 이유)
- `call.summary_text`·`inquiry_type` 을 확정본으로 · `summary_confirmed_at` 기록 · 후속조치는 `draft` 를 지우고 `confirmed` 로 넣는다(다른 상태 항목은 남긴다)
- **확정은 한 번이다** — 이미 확정이면 409. 확정 뒤 `POST …/close` 로 초안을 다시 만들면 409(이미 구현 — 덮지 않는다)
- 없는 통화 404 · DB 없음 501(로그로 대신하면 «확정됐다» 는 거짓말이 된다)

## 근거

- 초안 생성이 규칙 발췌(306)라 품질을 잰 적이 없다 — 틀린 초안을 그대로 확정하면 기록이 틀린다. 고칠 수 있어야 확정이 의미가 있다
- 콜센터 통화 후 정리(wrap-up)가 같은 구조다 — 시스템이 제안하고 상담원이 고쳐 확정한다

## ⚠ 남는 것

- **확정 후 수정 경로가 없다** — 잘못 확정하면 되돌릴 API 가 없다(DB 수작업). 필요해지면 이력 테이블과 함께 정한다
- 초안과 확정본의 차이(상담원이 얼마나 고쳤는가)는 남지 않는다 — 초안을 덮어쓴다. 요약 품질 측정 재료로 쓰려면 초안 보존이 필요하다
- 운영에서 상담원 토큰 발급은 관리자 로그인이 돌아야 한다

## 되돌리는 법

`main.py` 에서 `summary_confirmation_router` 를 빼면 닫힌다. 완전히 지우려면 `summary_confirmation_*` 슬라이스 파일을 지운다(스키마 변경 없음).
