# 114. 미결로 남겨둔 CI 결함 다섯을 닫는다

- 날짜: 2026-09-15
- 작성: 정성윤
- 상태: 채택
- 관련: `decisions/111`(배포 태그 게이트 — 이때 「이번에 하지 않은 것」으로 남긴 항목들이다) · `024`(스포크는 조용히 501)

---

## 맥락

`111` 에서 릴리스 태그 게이트를 고치면서 **범위 밖으로 미뤄 둔 것이 다섯** 있었다.
전부 「지금 터지지는 않지만 조용히 새는」 부류라 미결 항목에만 적어 뒀는데, 그대로 두면
`111` 이 경계한 바로 그 방식(아무 일도 안 일어나서 조용히 밀림)으로 잊힌다. 한 번에 닫는다.

## 결정

| | 무엇이 문제였나 | 어떻게 했나 |
|---|---|---|
| ① | **ES 이미지를 CI 가 아예 몰랐다.** `infra/elasticsearch/Dockerfile` 을 고쳐도 `release.yml` 의 `paths` 에 없어 워크플로가 깨어나지 않고, ES `newTag` 만 올리면 워크플로는 도는데 **굽는 잡이 없어** 없는 태그를 적용해 **ImagePullBackOff** 가 난다. server 스모크는 통과하므로 늦게 발견된다 | `paths` 에 `infra/elasticsearch/**` 추가 · `es-image` 잡 신설 · `check_release_tags.py` 의 `IMAGES` 에 `es` 추가(게이트도 함께 걸린다) |
| ② | **`converge.sh` 가 게이트웨이 롤아웃을 보지 않았다.** `callguard-server` 만 기다려서, 부팅 시 게이트웨이가 못 떠도 「완료」를 찍는다. `release.yml` 의 배포는 둘 다 보는데 **부팅 경로만 하나**였다(09-11 게이트웨이 도입 때 누락) | `rollout status deploy/callguard-gateway` 한 줄 추가 |
| ③ | **같은 SHA 에 검사가 두 벌** 달렸다 — 브랜치 push 런과 PR 런이 같은 커밋을 헤드로 쓴다(실측: `61a3d35d`) | `test.yml` 의 push 트리거를 **`[main]` 으로 좁혔다** |
| ④ | **`.github/branch-protection.json` 이 라이브 룰셋과 어긋났다** — 파일은 승인 1건 필수·검사 셋, 라이브는 승인 0건·검사 다섯 | 라이브에 맞췄다(다른 세션이 09-15 에 수정, 이 커밋으로 들어간다) |
| ⑤ | **운영 이미지에 테스트가 실렸다** — `COPY server/` · `COPY ai/apps/` 가 넓어 `tests/` 하위 `.py` **86개**(디렉터리 9개)와 `ai/apps/evaluation/`(336K)이 들어간다. `pytest` 가 이미지에 없어 **동작 위험은 없었지만**, `.dockerignore` 머리말의 의도와 어긋났다 | `.dockerignore` 에 `**/tests`·`**/conftest.py`·`**/pytest.ini`·`**/.importlinter`·`ai/apps/evaluation` 추가 |

## 근거 — 판단이 갈렸던 둘

### ③ 은 「싼 수정」을 쓰지 않았다

`concurrency` group 을 합쳐 한쪽을 취소하는 방법이 먼저 떠오르지만 **쓰면 안 된다.**
두 런이 **같은 SHA 에 같은 이름**(`server`·`ai`·`jekyll`·`gateway`)으로 check-run 을 보고하므로,
취소된 쪽이 나중에 기록되면 필수 검사가 `cancelled` 로 남아 **PR 이 머지 불가**가 된다.
경합이라 재현이 들쭉날쭉해 원인을 찾기도 어렵다. 필수 검사가 다섯이 된 지금은 더 위험하다.

그래서 **트리거를 좁혔다.** 잃는 것은 「PR 없이 브랜치에만 push 했을 때의 CI」 하나뿐이다 —
PR 이 열려 있으면 `pull_request` 가 push 마다(synchronize) 돌고, main 은 머지 후 그대로 돈다.
일찍 보고 싶으면 초안 PR 을 연다. **`CLAUDE.md` §7 의 서술도 함께 고쳤다.**

### ⑤ 는 경계선을 그었고, 안전망을 넓혔다

**`ai/apps/call_guard`·`voice_signal` 은 빼지 않는다.** C-6·D-5 가 꽂힐 자리다 — 지금 배선이
없을 뿐이고(`/health` 의 `spokes` 와 릴리스 스모크의 `EXPECTED` 둘 다 넷), 빼면 나중에 꽂는 사람이
**로컬에선 되는데 운영에서만 ImportError** 로 헤맨다. `decisions/024` 가 말하는 「조용히 빠지는」 사촌이다.

그리고 **`.dockerignore` 로 빼는 순간 기존 안전망에 사각지대가 생긴다.**
`server/tests/test_image_layout.py` 는 Dockerfile 의 `COPY` 만 읽으므로, `COPY ai/apps/` 가 그대로여도
`.dockerignore` 가 그 안을 빼면 **테스트는 초록인데 이미지엔 없다.** 그래서 그 테스트가
`.dockerignore` 도 함께 보도록 넓혔다(`_ignored_by()`). 실측으로 확인했다 —
`ai/apps/evaluation` 은 「빠짐」으로 잡히고 `retrieval`·`provider.py`·`call_guard` 는 안 잡힌다.

## 딸린 변경

- **태그를 올렸다**: server `0.1.10 → 0.1.12` · gateway `0.1.4 → 0.1.5`.
  `.dockerignore` 가 **두 이미지의 경로 정규식에 다 걸리기 때문**이다.
  ⚠ `0.1.11` 은 `origin/ai` 가 이미 집었다(`c9fa746`) — `111` 에서 넣은 브랜치 간 경고가 실제로 알려줬다.
  gateway 이미지는 `src/` 와 `package*.json` 만 담아 **내용이 안 바뀌는 것이 확실하지만**, 게이트는
  「`.dockerignore` 가 바뀌면 두 이미지 다 바뀔 수 있다」로 보수적으로 판정한다 — 헛 태그 한 번이
  조용한 옛 이미지보다 싸다.
- **브랜치 간 태그 경고의 판정 기준을 고쳤다.** `111` 에서는 「그 커밋이 우리 계보 안인가」로
  봤는데, 그러면 모두가 공유하는 값(`es` 의 `9.5.1` 처럼)마다 경고가 떠서 **아무도 안 읽게 된다.**
  **갈라진 지점(merge-base)의 값과 비교해 «저쪽이 실제로 바꿨는가»** 로 바꿨다.
  실측: 지금 상태에서는 조용하고, `origin/ai` 가 실제로 올린 `0.1.11` 을 집으면 경고가 뜬다.
- `test.yml` 의 낡은 주석 둘을 고쳤다(`gateway` 가 필수가 아니라는 서술 · 필수 검사 이름 목록).

## 되돌리는 법

- **①**: `release.yml` 에서 `es-image` 잡과 `paths` 의 `infra/elasticsearch/**` 를 빼고,
  `check_release_tags.py` 의 `IMAGES` 에서 `es` 항목을 지운다. 손으로 굽는 경로(`infra/README.md:34`)는 그대로 있다.
- **②**: `converge.sh` 의 게이트웨이 `rollout status` 한 줄을 지운다.
- **③**: `test.yml` 의 `push.branches` 를 `[main, PM, ai, server, frontend]` 로 되돌린다.
  **`concurrency` 를 합치는 쪽으로는 되돌리지 않는다** — 위 근거대로 머지를 막을 수 있다.
- **⑤**: `.dockerignore` 의 추가분을 지운다. `test_image_layout.py` 의 `_ignored_by()` 는
  남겨도 무해하다(뺀 것이 없으면 항상 통과한다).

## 남는 것

- **ES 태그는 ES 버전을 따라간다**(`Dockerfile` 의 `ARG ES_VERSION`). Dockerfile 만 고치고 버전은
  그대로일 때는 빌드 접미사를 붙인다 — 예: `9.5.1-2`. `es-image` 잡 주석에 적어 뒀다.
- **③ 으로 「PR 없는 브랜치 push」는 CI 가 돌지 않는다.** 팀이 초안 PR 을 쓰지 않아 불편하다는
  얘기가 나오면 되돌릴 수 있다 — 그때는 중복 2벌도 같이 돌아온다는 것을 알고 정한다.
