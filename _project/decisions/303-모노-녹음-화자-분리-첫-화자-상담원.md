# 303 — 모노 녹음은 `speaker=auto` 로 가르고, 먼저 말한 화자를 상담원으로 친다

**날짜**: 2026-09-14
**작성**: 장민석 (브랜치 `server`)
**관련**: A-2 · `services/gateway` · [미결](/open-items/) 「모노 한 줄에 섞인 두 화자는 가르지 못한다」(2026-09-11) · 티켓 `w4-gateway-mono-diarization`

## 맥락

A-2(화자 분리)는 **채널 분리**만 한다 — `/ingest` 연결 하나가 화자 하나다. V1 실측대로 AI Hub 녹음은 전부
모노라, `scripts/stream_wav.ts` 로 재생하면 **상담원과 고객이 한 화자로 찍힌다.** 그러면 방향이 걸린 기능이
전부 틀린 사람을 본다 — C-1~C-4 는 상담원 발화, C-6·트리거(B-1)는 고객 발화만 본다.

구글 STT 화자 분리(diarization)는 단어마다 «1번·2번 화자» 라벨을 붙이지만 **누가 상담원인지는 알려 주지
않는다.** 라벨을 상담원·고객으로 옮기려면 규칙이 하나 필요하고, 그 규칙은 무엇을 고르든 추측이다.
09-11 게이트웨이 작업이 그래서 이걸 넣지 않고 미결로 남겼다.

## 선택지

| | 방법 | 비용 |
|---|---|---|
| A | **먼저 말한 화자 = 상담원.** 생산자가 `speaker=auto` 를 줄 때만 | 고객이 먼저 말하는 녹음이면 **방향이 통째로 뒤집힌다** |
| B | 라벨로 문장만 나누고 화자는 연결 파라미터 그대로 | 뒤집힐 위험은 없지만 두 사람이 여전히 한 화자다 — 문제가 안 풀린다 |
| C | 발화 내용으로 판정(「다산콜센터입니다」 같은 인사말 규칙) | 규칙표를 새로 만들어야 하고, 인사가 전사 오류로 뭉개지면 같은 추측이 된다 |
| D | 데모는 물리 2채널(브라우저 2대)로만 한다 | 코드는 안 늘지만 AI Hub 녹음 재생 데모가 계속 한 화자다 |

## 결정

**A** — 사용자 선택(2026-09-14).

- **기본값이 아니다.** `/ingest?speaker=agent|customer` 는 지금과 똑같다. `speaker=auto` 를 줄 때만 켜진다
  (`stream_wav.ts --speaker auto`). 오디오 문만 받는다 — `/dev/text` 는 가를 소리가 없어 1008 로 닫는다
- `auto` 채널은 구글에 `diarizationConfig(2~2명)` + `enableWordTimeOffsets` 를 요청한다. **V4 측정 설정과
  달라지므로 이 채널의 지연을 V4 수치로 인용하지 않는다**
- final 결과의 단어를 **라벨이 바뀌는 곳마다 잘라** 발화로 보낸다. 처음 본 라벨 = `agent`, 나머지 전부 `customer`
- 구글은 화자 분리를 켜면 **응답마다 처음부터의 단어를 다시 보낸다**(`cloud_speech.proto`). 이미 보낸 단어는
  끝 시각 워터마크로 거른다. 라벨은 모델이 더 들을수록 고쳐지지만 **이미 화면·DB 로 나간 발화는 되돌리지 않는다**
- **interim 은 보내지 않는다** — 라벨이 final 에만 붙는다. 누구 말인지 모르는 자막을 어느 쪽으로도 지어내지
  않는다. 그래서 `auto` 채널의 자막은 발화가 끝나야 뜬다. 라벨 없는 final 도 버리고 경고 로그(번호만)를 남긴다
- **통화 기록에 추측이라는 것을 남긴다** — `call.stt_engine` 이 `google-stt+diarize` 다
- `auto` 는 그 통화의 두 화자를 다 차지한다 — 같은 `call_id` 에 다른 채널과 함께 열리지 않는다

## 근거

- 120 은 상담원이 먼저 인사한다(「네, 120 다산콜센터입니다」) — 재생할 녹음이 콜센터 통화라면 A 가 맞을 가능성이 높다.
  **측정은 안 했다**(절대 원칙 2) — 다산 음성은 발화 단위 클립이라 화자 분리를 잴 수 없다(`plan.md` 5.2절)
- 뒤집힘 위험은 **기본값에서 빼는 것**으로 막았다. 운영 데모의 물리 2채널 경로는 전혀 바뀌지 않는다
- C 는 A 보다 나을 수 있지만 규칙표·골든셋이 필요하다. A 로 먼저 돌려 보고 뒤집힘이 실제로 보이면 C 로 간다

## ⚠ 검증하지 못한 것

- **실제 구글 응답으로 돌려 보지 않았다** (2026-09-14). 이 머신에 STT 키도 AI Hub 음성도 없다.
  테스트는 `cloud_speech.proto` 에 적힌 응답 모양을 흉내 낸 가짜 스트림 위에서만 돈다.
  **확인할 것**: ① `ko-KR` 기본 모델이 스트리밍 화자 분리를 받는가(거절이면 `code=3` 으로 채널이 닫힌다)
  ② `speakerLabel` 이 오는가, `speakerTag` 만 오는가 ③ 라벨이 대화 중간에 뒤바뀌는 빈도

## 되돌리는 법

`services/gateway` 에서 — `src/domain/diarization.ts` · `test/diarization.test.ts` 를 지우고,
`google_stt.ts` 의 `diarize` 분기(`emitDiarized`·공장 설정) · `call_registry.ts` 의 `"auto"` 분기(`conflicts`·
`FirstSpeakerIsAgent`) · `ws_server.ts` `parseIngest` 의 `allowAuto` · `stream_wav.ts` `--speaker auto` 를 걷는다.
서버·DB 는 건드리지 않았다. 이미 저장된 `google-stt+diarize` 통화는 그대로 두고 화자를 믿지 않는다.
