# 325 — 보존 기간을 한 표로 묶는다

**날짜**: 2026-09-22
**작성**: 장민석 (브랜치 `server`)
**상태**: 채택 — **시연 범위의 결정**이다. 실제 도입 때는 기관 기록물 관리 규정이 이 표를 대신한다
**관련**: `205`(스키마 QA — 보존 기간) · `304`·`309`(블랙리스트 만료) · `308`(추천 — 「보존 기간은 정하지 않았다」) · `311`(요약 이력 — 「무기한」) · `312`(블랙리스트 자유 입력 180일) · `113`(정리는 사람이 누른다) · 절대 원칙 8
**티켓**: `w6-server-loose-ends` ③

---

## 맥락

보존 기간이 결정 여러 곳에 흩어져 있고, 몇 곳은 **「정하지 않았다」**로 끝난다(`308` 추천 · `311` 요약 이력 · 통화·전사·판정 기록은 언급 자체가 없다).
발표에서 「개인정보를 얼마나 갖고 있나」를 물으면 한 곳을 가리킬 수 있어야 한다.

## 결정 — 한 표

| 무엇 | 보존 | 근거 |
|---|---|---|
| **마스킹 전 원문**(전사·신고 설명·요약·사유) | **0 — 저장하지 않는다** | SEC-1 · C-5 는 저장 앞단에서 가린다(`324`·`322` 로 중간 자막·지식 공백 설명까지) |
| 발신 번호 평문 | **0** — HMAC 으로 바꾸고 버린다 | `304` |
| 블랙리스트 등록(`blacklist_entry`) | 승인 때 관리자가 정한 만료까지, **최대 365일** · 연장·단축 이력은 남는다 | `205` ⑤ · `304` · `309` |
| 블랙리스트 **자유 입력**(반려 요청 사유·자막 · 만료 변경 사유) | 끝난 지 **180일** 뒤 문장을 표시로 바꾼다 · 행은 남는다 | `312` · 실행은 관리자가 누른다(`113`) |
| 통화·마스킹된 전사·추천·필요서류 판정·콜 가드·컴플라이언스·요약(+수정 이력)·배정 판정 | **프로젝트 기간** — 종료(인프라 철거) 때 운영 DB 와 함께 지운다 | 시연 데이터다. 합성 통화는 `stt_engine=synthetic-script` 로 구분된다(`w6-synthetic-calls-retention`) |
| 평가 실행(`eval_run`·`eval_result`) | **지우지 않는다**(저장소 밖으로 뽑아 둔다) | 측정 기록이다 — 실패를 지운 기록은 기록이 아니다(절대 원칙 8) |
| 상담원 토큰 | 폐기해도 행은 남긴다(해시만 있다) | `307` — 누가 언제 발급·폐기했는지가 근거다 |

**기간 중 자동 삭제는 없다.** 180일 정리도 사람이 누른다(`113`).

## 근거

- 원문을 안 갖는 것이 가장 강한 보존 정책이다 — 가진 것은 이미 가려진 글자뿐이라, 나머지 기간은 **시연 범위**에서 정하면 된다
- 요약 수정 이력(`311`)을 기간 중에 지우면 「누가 확정·수정했나」의 근거가 사라진다 — 프로젝트 기간에는 둔다

## ⚠ 한계

- 실제 기관(120 다산콜센터)이라면 상담 기록 보존 연한은 **그 기관 규정**이 정한다. 이 표는 그것을 대신하지 않는다 — 발표에서 그렇게 말한다
- 프로젝트 종료 삭제는 인프라 철거 절차(`w8-project-closeout`)에 들어가야 실제로 일어난다

## 되돌리는 법

표의 한 줄을 새 결정으로 바꾼다. 코드에 걸린 값은 180일(`blacklist/domain/services/retention.py`)과 365일(`MAX_EXPIRES_IN_DAYS`) 둘뿐이다.
