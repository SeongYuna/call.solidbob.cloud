## 맥락

2026-09-17 로컬 전체 스택에 합성 통화 4건을 흘린 결과(규칙·BM25 만 켠 — **운영과 같은 구성**):

1. **C-5 이름·번지가 원문으로 자막·DB 에 남았다** — 「김도윤」·「제니 레예스」·「은하로 7-3」. SEC-1·절대 원칙 3(누락 0건) 위반.
   운영 서버 이미지에 torch 가 없어 `ai/apps/pii_ner` 이 **꽂히지 않고** 규칙만 돈다(`server/main.py` `_wire_pii_ner`).
2. **필요서류 판정이 엉뚱한 절차로 갔다** — 게이트웨이가 추천 1순위를 절차로 믿는데 BM25 1순위가 틀렸다
   (재난지원금 통화 → 「5.9 유급휴가비용」). 내부 규정 조항(POLICY)이 1순위가 된 경우는 이번 커밋에서 검색 필터로 뺐다.

두 문제의 근본 해결은 **이미 만든 모델을 운영에서 켜는 것**인데, 운영 노드가 런북의 GPU `g4dn.xlarge` 가 아니라
**CPU `t3.large`(2 vCPU · 메모리 7.8GB, 09-17 사용 3.6GB)** 다. 셋을 한꺼번에 켤 수는 없어 순서를 정한다.

## 결정 (제안)

1. **1단계 — NER 먼저.** C-5 는 절대 규칙이라 검색보다 앞선다. 메모리 약 0.7GB
2. **2단계 — 임베딩(dense) 검색.** 리랭커 없이. `_wire_retrieval` 은 `RETRIEVAL_RERANK_MODEL_DIR` 를 비워 두면 이미 dense 단독이다
3. **리랭커는 GPU 노드(또는 t3.xlarge 이상)로 올릴 때** 켠다 — `decisions/206` 의 채택은 유지하고 운영 반영만 미룬다
4. 이미지에 torch **CPU 휠**만 넣는다(CUDA 휠은 수 GB 더 크다). 모델 파일은 이미지에 굽지 않고 노드 볼륨(또는 S3 `assist-apne2` 에서 기동 시 받기)에 둔다
