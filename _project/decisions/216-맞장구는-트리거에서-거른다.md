## 결정

**넣지 않는다.** 사전 등록한 채택 규칙 (A)·(B) 를 **둘 다** 못 넘었다(손실 1 / 허용 0 · 억제 72.7 % / 기준 90 %). 결과를 본 뒤 어휘·규칙·라벨·위험 집합 정의를 고치지 않았다.

- **장치는 남긴다, 기본은 꺼짐.** `ai/apps/retrieval/adapter/outbound/is_final_trigger.py` `SUPPRESS_BACKCHANNEL_DEFAULT = False`. 운영 `server/main.py` `_wire_trigger` 는 `build_trigger_provider()` 를 인자 없이 부르므로 **운영 동작은 오늘과 같다**(맞장구에도 발동 → 카드 5장). 테스트가 기본 꺼짐을 고정한다.
- 215 dense 문턱도 **계속 꺼져 있다**(이 결정과 무관).
- 하네스(`run_eval.py --runs 1 --retriever dense`, 기록 안 함, 41c62bd 작업 트리): B Recall@5 **0.969** · MRR **0.868**(n 96) · `no_answer` 기권 0/24 · C-5 누락 0(n 28, P1~P7) · F-2(closure_gate) 정확도 1.0(n 99) — run_id 3 와 같다. **트리거는 하네스가 일부러 재지 않는다**(`[trigger] 측정 불가`, `scripts/run_eval.py` — 발동 시각이 모형값이라 절대 원칙 10). 그래서 이 결정의 근거는 하네스가 아니라 위 대화체 표본이다.

## 근거

- **사전 등록 규칙을 그대로 적용했다.** 215 에서 배운 것 — 결과를 보고 손잡이를 돌리지 않는다 — 을 이번에는 숫자 문턱 없이도 지켰다.
- **실패 모양이 두 가지로 갈렸고 둘 다 적는다**(절대 원칙 8):

  2. (A) — **위험 집합 정의가 너무 넓었다.** 「top-5 에 절차 문서」를 필요 신호로 쓴 것은 필요한 턴을 놓치지 않으려는 뜻이었지만, 내용 없는 발화에도 MANUAL-1.x 가 뜨는 검색 특성 때문에 맞장구 자체가 위험 집합에 들어갔다.
