# 144 — 관리자 화면에 고객 뒤 4자리(`****1234`)를 보인다 (316 「채우지 않는다」 일부 철회)

- 날짜: 2026-10-01
- 결정자: 정성윤 (사용자 선택 — 10-01 「뒤 4자리 보이기」)
- 관련: `316`(display_hint 를 채우지 않는다) · `304`(고객 식별 HMAC) · `205` ③ · 수동 QA 2회차 6장 관찰(`_logs/2026-09-30-01`)

## 맥락

`316` 은 전화번호 뒷자리도 P4 의 일부라 `display_hint` 를 채우지 않기로 했다. 그 결과 관리자 화면(승인요청·블랙리스트·감사 로그·알림)이 전부 `****` 라 **어느 요청인지 못 가린다** — QA 2회차에서 「다 가려져 있어서 잘 안 보인다」. 시연에서 관리자가 승인할 대상을 찾지 못한다.

## 선택지

1. 그대로 두고 알려진 한계로 말한다
2. **뒤 4자리를 다시 연다** — 통화 시작에서 발신 번호로 `****1234` 를 만들어 `customer.display_hint` 에 두고, 요청 생성 때 `blacklist_request.display_hint` 로 옮겨 적는다. 번호 원문은 어디에도 저장하지 않는다
3. call_id 를 크게 보인다(식별은 되지만 사람이 알아볼 값이 아니다)

## 결정

**2.** 316 의 「채우지 않는다」만 철회한다. 나머지(반려 사유·D-5 미측정)는 그대로다.

- 통화 시작(`POST /hub/calls`, `caller_phone`)에서 `CustomerRefPort.hint()` 가 정규화한 숫자의 뒤 4자리를 만든다. **식별자(HMAC)가 없으면 힌트도 없다** — 힌트만 남는 반쪽 기록을 만들지 않는다.
- `customer.display_hint` 신설(마이그레이션 `db/migrations/2026-10-01-customer-display-hint.sql`). 처음 값이 없던 고객에게만 채운다.
- 요청 생성 인터랙터가 `customer` 에서 옮겨 적는다. 옛 행·번호 없던 통화는 NULL 그대로 — 관리자 화면은 그때 `****` 를 보인다(전과 같다).
- 서버 `0.1.44`. **마이그레이션을 이미지보다 먼저 넣는다**(런북 19장).

## 근거

- 뒤 4자리만이라 번호를 되돌릴 수 없다. HMAC 과 함께 있어도 전수 대입의 후보가 10^7(11자리 번호에서 뒤 4자리 고정) 이라 316 이 걱정한 「되돌리는 단서」로는 부족하다.
- 시연·운영에서 관리자가 요청을 식별할 수단이 이것뿐이다(316 이 대안으로 든 call_id·마스킹 자막은 사람이 알아보는 값이 아니었다).
- SEC-1(원문 미보관)은 그대로다 — 저장되는 것은 `****` + 4자리뿐이다.

## 되돌리는 법

`hint()` 가 None 을 돌려주게 하면 새 통화부터 안 채워진다. 이미 채워진 값을 지우려면 `UPDATE customer SET display_hint = NULL` · `UPDATE blacklist_request SET display_hint = NULL`. 316 을 되살리고 이 파일에 날짜를 적는다.
