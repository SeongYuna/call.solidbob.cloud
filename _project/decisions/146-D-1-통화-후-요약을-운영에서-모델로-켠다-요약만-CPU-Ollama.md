# 146 — D-1 통화 후 요약을 운영에서 모델로 켠다 (요약만 · CPU Ollama · 서버 등급을 올린다)

- 날짜: 2026-10-02
- 결정자: 정성윤 (사용자 지시 — 10-02 「2번을 해보자」 · 「2단계부터 진행해줘」)
- 관련: `124`(모델은 운영 노드에 CPU 로 — **생성 모델은 올리지 않는다** 부분을 요약에 한해 뒤집는다) · `207`(생성 모델 kanana) · `306`(규칙 발췌 초안) · `138`(발표 준비 동결 — 시연 화면에 닿는 변경이라 예외) · `w7-postcall-spoke`

## 맥락

통화 후 처리 화면의 「요약 초안」 은 규칙 발췌다(`306`) — 문의·안내·서류·약속 발화를 골라 붙인다. 지어낸 문장이 없다는 장점이 있지만 **요약이라기보다 발화 모음으로 보인다**(10-02 사용자 지적). 모델 요약 코드는 09-15 에 만들어져 있었고(`w7-postcall-spoke`, 규칙 검사 통과 42/50) 운영에서는 꺼져 있었다 — 운영 노드에 GPU 도 Ollama 도 없다.

**10-02 운영 노드 임시 시험**(하네스 값이 아니다 — 임시 파드 실측. `t3.large` · llama.cpp server · kanana-1.5-2.1b Q4_K_M · temperature 0 · seed 20260915 · 서버가 보내는 것과 같은 프롬프트):

| 통화 | 발화 | 걸린 시간 | 프롬프트 처리 | 출력 |
|---|---|---|---|---|
| 시연 1막 | 17줄 | 38.1초 | 397토큰 21.5초 | 74토큰 16.6초 (4.4토큰/초) |
| 폭언·위기 통화 | 5줄 | 17.8초 | 199토큰 10.6초 | 36토큰 7.0초 |
| 외국인 고객 통화 | 19줄 | 53.4초 | 621토큰 33.7초 | 77토큰 19.6초 |

세 요약 모두 `summary_problems`(자막에 없는 숫자 · 금지 표현 · 길이) 통과, 같은 입력에 같은 출력. 생성 중 CPU 1.84코어 사용 · 모델 상주 메모리 2.1GB.

시험에서 드러난 것 셋 — ① `t3.large` 는 **물리 코어 1개**(2 vCPU = 하이퍼스레드)라 느리다 ② 요약 타임아웃이 30초라 지금 등급에서는 셋 중 둘이 규칙 초안으로 떨어진다 ③ `ollama/ollama` 이미지를 받자 디스크가 62% → 91% 로 뛰었다(압축 3.75GB) — 30GB 디스크에는 못 올린다. 그리고 1막 요약이 상담원의 위반 발화(「주민등록번호 열세 자리 전부 불러 주세요」)를 「본인 확인 안내」 로 매끄럽게 넘겼다.

## 선택지

1. 켜지 않는다 — 화면 제목만 「핵심 발화 (초안)」 으로 바꾸고 시험 결과를 발표에 싣는다 (Claude 권고)
2. 규칙 초안을 먼저 보이고 모델 요약을 나중에 바꿔 끼운다(비동기) — 서버·화면 둘 다 고친다
3. **지금 구조(Ollama)로 켜고, 느린 것은 서버 등급을 올려 푼다** — 임시 서버로 먼저 재는 단계는 건너뛴다

## 결정

**3.** 사용자가 정했다.

- **요약만 켠다.** 스위치를 나눈다 — `POSTCALL_MODEL`(새 키)은 D-1 요약만, `GENERATION_MODEL` 은 전처럼 B-4 카드 생성(+요약). 운영에는 `OLLAMA_URL` + `POSTCALL_MODEL` 만 넣는다. 카드는 스니펫 그대로다 — 추천마다 모델을 부르면 실시간 경로가 무너진다.
- **위반 발화는 모델에게도 주지 않는다.** 규칙이 잡은 상담원 발화 번호(`summarize_with_flags`, 10-01)를 모델 어댑터가 받아 프롬프트에서 뺀다. 판정은 규칙이, 설명만 모델이(절대 원칙 9).
- **모델 검사에 걸리면 규칙 초안으로 내려간다** — 그대로다. 요약 끝의 `(모델 요약 초안)` 표시도 그대로다.
- **Ollama 를 CPU 로 운영에 올린다**(`infra/k8s/base/ollama.yaml`, ClusterIP 전용, 메모리 상한 3Gi, 30분 유휴 시 모델 내림).
- **루트 볼륨 30 → 60GB · 고정 IP(EIP) · 인스턴스 등급 상향.** 등급과 「상시 / 필요한 날만」 은 올린 직후 같은 세 건을 재서 정하고 이 파일 「갱신」 절에 적는다.

## 근거

- 요약은 판정이 아니라 설명이다 — 모델에 맡겨도 절대 원칙 9 에 어긋나지 않는다. 검사(숫자·금지 표현)와 폴백이 이미 있다.
- 시연·발표에서 보이는 화면이라 `138` 동결의 예외 조건(「시연 화면에 닿는 변경」)에 든다.
- 등급을 올리면 통화 중 지연도 준다 — 글자 채널 통화의 내부 p95 가 예산을 넘는 원인이 코어 부족이었다(`w7-latency-budget` 10-01 밤 절).

## 알고 가는 것

- **재지 않고 올린다.** 등급을 올린 뒤의 요약 시간은 추정(코어 4개에서 1막 7초 안팎)이다. 올린 직후 잰다.
- 여섯 통 중 한 통꼴로 규칙 초안이 그대로 뜬다(검사 통과율 42/50, 09-15 로컬).
- 요약 품질은 하네스 D-1 지표(핵심 항목 포함률)로 **다시 재지 않았다** — 하네스는 규칙 어댑터를 잰다. 모델 요약의 포함률은 미측정이다.
- 비용: `t3.large` 0.104 → `c7i.xlarge` 0.2016 / `c7i.2xlarge` 0.4032 USD/시간(서울, 10-02 요금표). 디스크 +30GB 는 월 2.7 USD.

## 되돌리는 법

`server-env` 에서 `POSTCALL_MODEL` 을 지우고 서버를 다시 띄우면 규칙 초안으로 돌아간다(`/health` `spokes` 에서 `postcall_model` 이 빠진다). Ollama 파드는 `kustomization.yaml` 에서 `ollama.yaml` 줄을 빼고 적용한다. 등급은 EIP 가 붙어 있으면 껐다 켜는 5분으로 내린다. 디스크는 줄일 수 없다.

**재면서 알게 된 것 둘:**

1. **같은 입력에 글이 달라졌다.** 「1막 — 위반 줄 제외」 를 두 번 보내니 142자와 114자로 다른 요약이 나왔다(temperature 0 · seed 고정인데도). 「맥락」 절의 「같은 입력에 같은 출력」 은 llama.cpp 시험에서의 사실이고 Ollama 에서는 성립하지 않았다. 원인은 확인하지 않았다. 리허설과 본 촬영의 요약문이 다를 수 있다.
2. **메모리가 상한에 가까웠다.** 다섯 건을 돌린 뒤 Ollama 파드가 2,690Mi 였다(생성 중 CPU 4코어). 「결정」 절의 상한 3Gi 를 **4Gi 로 올렸다**(`infra/k8s/base/ollama.yaml`). 노드 여유는 그 시점 약 9.6GB.

**아직 하지 않은 것** — Ollama 정식 배포 · `server-env` 두 키 · server `0.1.45` 배포. 커밋·머지가 있어야 나간다(사용자 승인 대기). 임시 파드는 지웠고, 모델 파일 1.5GB 는 `/opt/callguard/ollama` 에 남겨 정식 배포가 다시 받지 않는다(이미지도 노드에 남아 있다 — 디스크 60GB 중 48%).

**아직 정하지 않은 것** — 이 등급을 상시로 둘지 필요한 날만 올릴지. `c7i.2xlarge` 는 시간당 0.4032 USD 로 `t3.large` 보다 0.2992 USD 비싸다. 고정 IP 가 붙어 있어 등급을 바꿔도 주소는 그대로다.
