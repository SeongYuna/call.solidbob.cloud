# 305 — F-2 를 다산 필요서류 체크리스트로 다시 만든다: 조건 없는 조항 25개 규칙화 + 상담원 발화 키워드 자동 판정

**날짜**: 2026-09-14
**작성**: 장민석 (브랜치 `server`)
**관련**: `decisions/201`(F-2 를 필요서류 체크리스트로 전용) · `plan.md` 7.3절 rev.5(`blocked`→`incomplete`) · 티켓 `w4-schema-qa-followup` ③ · `w4-required-docs-checklist`

## 맥락

`decisions/201` 이 F-2 를 「필요서류 체크리스트」로 전용했지만 코드·스키마는 금융보험·쇼핑 그대로였다 —
`closure_type CHECK('상품해지','보상','반품','교환')` + 전용 BOOLEAN 10개. **다산 절차를 넣으면 규칙표가 422, DB 가 CHECK 로 거부**했고,
골든셋 F-2 케이스가 0건인 원인의 절반이 여기였다. 대시보드는 `closure` 메시지를 기다리는데 보내는 쪽이 없었다.

## 선택지

| | 범위 | 비용 |
|---|---|---|
| A | 구조 + 조건 없는 조항만 규칙화 | 자동 판정이 없어 호출자가 체크리스트를 채워야 한다 |
| B | 구조 + 35개 조항 전부(조건 분기 포함) | 조건 해석이 들어가 틀리면 절대 규칙 위반 — 류준 검토 필요 |
| C | **구조 + 자동 안내 판정까지** | 판정 규칙(키워드) 설계가 들어가고 한계가 생긴다 |
| D | 보류 | — |

## 결정

**C** — 사용자 선택(2026-09-14). 규칙표는 A 의 범위(조건 없는 조항)를 쓴다.

**규칙표** (`server/apps/closure_gate/domain/value_objects/closure_rule.py`)
- 출처는 `knowledge-base/dasan/terms/TERM.md` 의 「— 필요서류」 조항 35개. **절차 ID = 조항 ID**(`DASAN-TERM-4.4`) — 추천 카드 `source.doc_id` 와 같은 체계
- **조항이 조건 없이 나열한 기본 서류만 필수**다. 조건부 추가 서류(대리·대상자 등)는 `conditional` 로 싣기만 하고 판정에 넣지 않는다 —
  조건 충족 여부를 모르는데 필수로 치면 해당 없는 통화마다 누락 경고가 뜬다
- **기본 목록 자체가 조건으로 갈리는 조항은 규칙을 만들지 않고 `EXCLUDED` 에 이유를 적는다** — 2.6·3.4·3.6·4.5·4.9·4.12·6.5·6.8 (+ 원칙 조항 1.3·1.4). 25개가 규칙이 됐다
- **옮겨 적기 검증**: `test_closure_rule_source.py` 가 서류 이름이 조항 본문에 실제로 있는지, 필요서류 조항이 전부 규칙이거나 제외 목록에 있는지 대조한다

**판정** — 필수 서류가 하나라도 안내되지 않았으면 `incomplete` + 빠짐없이 `missing`. rev.5 대로 **차단이 아니라 경고**다

**자동 판정** (`domain/services/detection.py`) — 서류마다 키워드를 두고 **상담원 확정 발화(마스킹본)** 에 있으면 안내로 센다. 신분증은 1.4 조의 인정 서류 이름도 같은 뜻으로 센다

**흐름** — 게이트웨이가 추천 응답 **1순위 카드의 `source.doc_id`** 를 통화의 절차로 잡고, 상담원 확정 발화가 쌓일 때마다 `POST /hub/required-docs-checks` 로
다시 판정한다(한 통화의 요청은 줄을 세운다). 규칙 없는 조항(422)은 다시 묻지 않는다. 대시보드 `closure` 전송은 **기본 꺼짐** — 대시보드 파서가 옛 형식만 받는다

**스키마** — `closure` 를 헤더(`procedure`·`verdict complete/incomplete`·`detected`·`source_doc_id`)로, `closure_item`(서류별 `informed`)을 새로. 이름을 유지한 이유는 `knowledge_gap.closure_id` 가 참조해서다. `source_doc_id` 는 `document` FK 를 걸지 않는다 — 그 테이블을 채우는 경로가 없다

## ⚠ 한계 — 측정하지 않았다

- **자동 판정은 부정 문맥을 모른다.** 「신분증은 필요 없어요」 도 안내로 센다. 짧은 키워드(「관계」·「소유」)는 다른 맥락에서도 걸린다.
  **둘 다 누락을 못 잡는 쪽**이라 F-2 절대 규칙(누락 0건 탐지)에 불리하다. 한계를 테스트로 고정해 뒀다(`test_detection.py`)
- **골든셋 필요서류 케이스가 0건이라 판정 정확도는 측정 불가다**(절대 원칙 2·10). 이제 케이스를 넣을 수 있다 — 류준 몫
- **절차 판정은 검색 1순위에 기댄다.** 검색이 틀린 조항을 1순위로 올리면 엉뚱한 체크리스트가 뜬다. ES 가 없으면 절차가 안 잡힌다
- `knowledge-base/dasan/policy/POLICY.md` 의 `DASAN-POLICY-1`(「F-2 미적용」)이 이 결정과 어긋난다 — 지식베이스 문서라 여기서 고치지 않았다

## 되돌리는 법

1. 게이트웨이 `checkRequiredDocs`·`topSourceDocId`·`announceClosure` 를 지운다 — 자동 판정이 멈춘다(수동 `POST /hub/closure-checks` 는 남는다)
2. 규칙을 줄이려면 `RULES` 에서 빼고 `EXCLUDED` 에 이유를 적는다 — 대조 테스트가 그걸 요구한다
3. 옛 금융·쇼핑 게이트로 되돌리는 것은 권하지 않는다(도메인이 없다). 필요하면 이 커밋의 `closure_rule.py`·`gate.py`·`closure` 테이블 정의를 되돌린다
