# 319 — 통합 수동 QA 게이트를 통과해야 다음 단계로 간다

**날짜**: 2026-09-22
**작성**: 장민석 (브랜치 `server`)
**관련**: 티켓 `w5-manual-qa-full-stack` · `w5-persona-e2e`(API 왕복 자동 검사) · `w8-demo-rehearsal`

## 맥락

5주차 끝인 지금까지 서버·AI·콜 미디에이터·상담원 화면·관리자 화면을 **한 번에 붙여 놓고 사람이 화면을 눌러 본 적이 한 번도 없다.**
그동안 한 검사는 전부 API 왕복이었다. `e2e_check.py`, 서버 pytest, `/health` 모두 **화면에 무엇이 보이는지는 보지 않는다.**
09-14 관리자 로그인은 `/health` 가 `ok` 인데도 화면에서 막혀 있었다. 코드만 읽어도 비슷한 자리가 보인다.
상담원 마이크는 오류가 나도 안내 없이 모달만 닫힌다(`apps/call/src/lib/useAgentCallSession.ts`).

각 영역은 자기 몫을 끝냈다고 보고하지만 **붙였을 때 되는지는 아무도 모른다.** 그래서 세 영역 모두 다음 작업의 전제를 확인하지 못한 채 멈춰 있다.

## 선택지

1. 지금처럼 자동 검사만 믿고 간다 — 화면에서 깨진 것은 시연 당일에 드러난다
2. 시연 리허설(8주차)에서 한꺼번에 확인한다 — 고칠 시간이 없다
3. **지금 통합 수동 QA 를 프로젝트 게이트로 두고, 통과 전에는 다음 단계를 시작하지 않는다**

## 결정

**3번.** `w5-manual-qa-full-stack` 을 **프로젝트 게이트**로 둔다. 개인의 요청이 아니라 프로젝트 진행 조건이다.

- **통과 조건**: 티켓의 완료 조건 전부. 특히 `Q-00a`~`Q-69` 의 빈칸이 0이어야 하고, 3장 → 5장 → 6장을 끊김 없이 한 번에 돌려야 한다
- **통과 전에 시작하지 않는 것**:
  - 정성윤 님의 다른 티켓. 진행 중인 `w7-latency-budget` 도 멈춘다
  - 시연 단계 `w8-demo-rehearsal`
  - 이 티켓들의 front matter 에 `depends_on: w5-manual-qa-full-stack` 을 단다
- **수행 방법**: 담당자(정성윤)가 **직접** 운영 주소에서 누른다
  - Claude 나 스크립트는 판정을 대신하지 않는다. 이 게이트가 생긴 이유가 지금까지의 검사가 전부 자동 API 왕복이었다는 것이다
  - Claude 에 요청이 오면 거절하고 티켓의 「규칙」을 안내한다
- **발견과 수정은 분리한다**: QA 는 ❌ 를 찾아 담당자에게 넘기기만 한다
  - 수정은 각 영역에서 한다. `server/` 장민석 · `ai/` 류준 · `apps/` 조서희 · 배포·토큰 정성윤
  - 고쳐진 번호만 다시 눌러 ✅ 로 바꾼다

## 근거

- **화면에서 되는지는 사람이 눌러야만 안다.** 자동 검사가 전부 통과해도 화면이 막혀 있던 사례가 이미 있다(09-14)
- 뒤로 미룰수록 비싸진다. 6주차 코어 기준선 판정(09-30)과 7·8주차 시연 준비가 모두 「붙이면 된다」를 전제로 한다. 그 전제가 틀렸다면 지금 알아야 고칠 시간이 있다
- 인프라 담당이 수행하는 이유는 배포·토큰·주소를 모두 쥐고 있어서다. ❌ 중 상당수가 「어느 쪽 문제인가」부터 가려야 하는데, 그 판단에 운영 환경 접근이 필요하다

## 되돌리는 법

게이트를 풀려면 이 결정을 철회하는 결정 기록을 새로 쓰고, 막아 둔 티켓들의 `depends_on` 에서 `w5-manual-qa-full-stack` 을 뺀다.
QA 가 끝나 게이트를 통과한 경우에는 되돌릴 것이 없다. 티켓이 `done` 이 되면 `depends_on` 은 충족된 기록으로 남는다.
