**AI Hub 데이터 이용정책**(https://www.aihub.or.kr/intrcn/guid/usagepolicy.do)에서 이 사안에 걸리는 것은 둘이다 — 원문은 옮기지 않는다(절대 원칙 6).

- **5항** — 승인받지 않은 제3자가 데이터를 열람하게 하거나, 데이터를 제공·양도·대여·판매하는 것을 금한다. 공개 저장소에 원문을 싣는 것은 **누구나 열람할 수 있게 하는 것**이다.
- **1항** — 데이터를 쓴 결과물(2차 저작물 포함)에 한국지능정보사회진흥원 사업 결과임을 밝히도록 한다.

12건이라는 숫자는 09-09 에 「2건과 90건은 규모가 다르다」며 **줄여서** 정한 것이지 허용 범위를 확인하고 정한 것이 아니었다(미결 항목 원문). 조항은 건수 문턱을 두지 않는다.

## 선택지

1. **그대로 둔다** — 비용 0. 실제 발화 문체 집단이 남는다. 대신 5항에 걸리는 상태가 계속되고, 발표·제출로 저장소가 더 읽힐수록 되돌리기 비싸진다.
2. **바꿔 쓴다** — 14건을 같은 민원 의도·같은 정답 조항을 가리키는 **새 문장**으로 교체한다. 라벨·표본 수는 그대로. 대신 「실제 발화 문체 vs 작성 문체」 비교가 사라지고, 이전 수치와 항목 단위 비교가 끊긴다.
3. **비공개 경로(S3)로 옮긴다** — 원문 14건을 `data/` 처럼 저장소 밖(S3)에 두고 골든셋은 ID 만 참조한다. 문체 비교가 살지만, CI·로컬 테스트가 S3 없이는 골든셋 전체를 못 읽게 되고 골든셋이 두 곳으로 갈라진다.

## 결정

**2 — 바꿔 쓴다.**

1. `v1-150.json` 의 14건 `customer_utterance`·`context_utterances` 를 **새로 쓴 문장**으로 바꿨다. 원문을 한 단어씩 바꾼 것이 아니라 의도(무슨 민원 · 무슨 서류)만 보고 다시 썼다. 다산 상담 구어체(짧은 말, 띄어쓰기 생략)는 유지했다.
   - 원문이 **오타를 일부러 남긴** 2건(GS-256·276, 「STT 결과와 비슷한 표기」)은 **다른 오타**(「어떻케」·「되요」 등)로 같은 성질을 살렸다.
   - 맥락 없이는 답이 없는 중간 턴 케이스(GS-226·277 등)는 그 성질을 그대로 두었다 — 새 발화도 단독으로는 무엇을 묻는지 모르고, 절차 이름은 `context_utterances` 에만 있다.
2. **채점 라벨은 한 글자도 고치지 않았다** — `expected_doc_ids`·`distractor_doc_ids`·`pii_patterns`·`module`·`utterance_end_ms`·`compliance_violation`·`f2_case`·`call_guard`(`decisions/123` 「수치를 올리려고 라벨을 고치지 않는다」). 14건마다 `knowledge-base/dasan/` 의 정답·오답 조항 본문을 열어 새 문장이 같은 조항을 가리키는지 확인했다. 14건 외 265건은 바이트 단위로 같다.
3. `source` 는 14건 모두 **`aihub_rewritten`** 으로 바꿨다 — 「AI Hub 에서 뽑은 문의의 의도를 보고 팀이 새로 쓴 발화」. `authored` 로 합치지 않은 이유는 **출처(어느 문의에서 왔는가)** 를 남기기 위해서다. GS-101·102 의 라벨 불일치도 이것으로 풀렸다. `aihub`(원문 그대로)는 이제 0건이고, 앞으로 싣지 않는다.
4. `notes` 는 지우지 않고 뒤에 「2026-09-22 바꿔 썼다」를 붙였다 — 앞의 「실제 발화」 서술은 교체 전 기록으로 남긴다(절대 원칙 8).
5. 판 표시 — `version: "v1-150.1"` · `revised: "2026-09-22"` · `note_2026_09_22`. 표본 수 279 그대로. 옛 판 `v1-10.json`·`v1-50.json` 의 GS-101·102 도 같은 새 문장으로 바꾸고 `note_2026_09_22` 를 달았다(문자열을 고정한 테스트는 0건 — grep 으로 확인).
6. **마스킹 테스트·탐지기의 조각은 그대로 둔다**(사용자 결정). 「과잉」 절의 문장과 `_NOT_NAMES` 류 목록은 **이름·주소로 잘못 가려진 단어 조각**을 재현한 짧은 문장이고, 발화 한 건을 옮긴 것이 아니다. 조각을 지우면 과잉 마스킹 회귀 테스트가 근거를 잃는다. 같은 성격의 짧은 인용(`golden-set/README.md` 「context_utterances 를 넣은 이유」의 「필요한 서류가 있나요?」류 3개 · `ai/apps/evaluation/harness.py`·`golden_set.py` 주석 2곳 · `jekyll/_backlogs/w2-golden-set-50.md` 의 GS-102 인용 1곳)도 이번에 고치지 않았다 — 마지막 것은 **발화 한 건 전체**라 아래 「남은 것」에 적는다.
7. **git 이력은 다시 쓰지 않는다**(사용자 결정). 원문은 이 커밋 이전의 이력에 **그대로 남아 있고**, 저장소를 받는 사람은 누구나 볼 수 있다. 이 결정이 막는 것은 **현재 판(main 의 최신 파일·사이트)에 원문이 계속 실리는 것**까지다. 「원문을 지웠다」고 말하지 않는다.

## 근거

- **5항은 건수가 아니라 행위를 막는다.** 12건이 적다는 것은 판단 근거가 되지 못한다.
- **바꿔 쓰기가 골든셋의 목적을 해치지 않는다.** 골든셋이 재는 것은 「이 의도의 문의에 이 조항이 뜨는가」다 — 의도와 정답 조항이 그대로면 채점 대상은 그대로다.
- **S3 이동은 비용이 크다.** 골든셋이 저장소와 S3 로 갈라지면 CI(`ai`·`server` job)가 S3 자격증명 없이는 골든셋을 다 못 읽고, `server` 의 골든셋 마스킹 테스트도 같은 파일을 읽는다. 14건 때문에 그 구조를 들일 이유가 없다.
- 조각을 남기는 판단은 **전재가 아니라 단어 수준 인용**이라는 데 있다. 이 판단이 틀렸다고 보이면 되돌리는 법 ③ 으로 따로 바꾼다.

## 이 결정의 비용 (숨기지 않는다)

- **「실제 발화 문체 vs 작성 문체」 비교가 사라졌다.** 09-09 README 가 「`source` 로 갈라 뒀으므로 두 집단의 지표를 따로 낼 수 있다」고 적었는데, 이제 `aihub_rewritten` 도 **팀이 쓴 문장**이다. `source` 로 가를 수는 있지만 두 집단 모두 작성 문체라 **문체 분포 차이를 재는 비교는 성립하지 않는다.** 미결 항목 「골든셋 문체와 실제 전사의 분포 차이」는 이 골든셋으로는 잴 수 없게 됐다 — 재려면 원문을 비공개로 읽는 측정(`data/` 원본, 결과 수치만 공개)이 필요하다.
- **이전 수치와 항목 단위로 비교할 수 없다.** 14건(B 96건 중 14건)의 질의가 바뀌었으므로 09-22 이전에 잰 B 검색 수치(Recall@5·MRR 등)는 이 판의 값이 아니다. 재측정 전까지 옛 수치를 이 판의 수치로 인용하지 않는다.
- **`eval_run.golden_set_version` 으로는 판을 못 가른다.** `scripts/run_eval.py` 가 파일 stem(`v1-150`)을 적으므로 이 판 전후 행이 같은 값을 갖는다 — `git_commit` 으로 가른다. 파일 이름을 바꾸지 않은 것은 테스트·하네스·문서의 경로 참조를 흔들지 않기 위해서다.
- `utterance_end_ms` 를 고치지 않았으므로 새 문장의 길이와 조금 어긋날 수 있다. 원문과 비슷한 길이로 썼지만 새 문장에 맞춰 **잰 값이 아니다**. 트리거 채점(0~1,500ms 허용창)은 이 값을 기준으로 하므로 라벨로 보고 그대로 두었다.

## 남은 것

- `jekyll/_backlogs/w2-golden-set-50.md` 가 GS-102 원문 한 건을 **통째로** 인용한다(18자). 완료된 티켓 본문이라 이번에 고치지 않았다 — 조각이 아니라 발화 한 건이므로 바꿀지 팀이 정한다.
- 1항(출처 표시) — 골든셋 README 에 AI Hub 사업 결과 표기를 둘지 정한다. 이제 원문은 없지만 의도·문체를 AI Hub 에서 가져왔다.

## 되돌리는 법

- ① **원문으로 되돌리기** — 이 커밋을 `git revert` 하면 14건과 옛 판 2건이 원문으로 돌아온다. 5항 판단이 바뀐 경우(예: 이용 승인을 받음)에만 한다.
- ② **S3 로 옮기기로 바꾸기** — 이 커밋 직전 판의 14건 원문을 S3 비공개 경로에 두고, 측정 스크립트가 로컬 `data/` 에서 읽어 원문 판을 따로 채점한다. 저장소의 `v1-150.json` 은 지금대로 둔다.
- ③ **조각까지 지우기로 바꾸기** — `test_pii_gaps_0917.py` 「과잉」 절과 탐지기 목록의 조각을 팀이 쓴 문장으로 바꾼다. 과잉 마스킹 회귀가 같은 모양을 잡는지 테스트로 먼저 확인한다.
- ④ **이력까지 지우기로 바꾸기** — `git filter-repo` 로 이력에서 원문을 지우고 강제 푸시. main 룰셋이 force push 를 막으므로 admin(정성윤)이 룰셋을 풀어야 하고, 모든 브랜치·포크·클론이 영향을 받는다. 되돌릴 수 없는 작업이라 팀 합의가 먼저다.
