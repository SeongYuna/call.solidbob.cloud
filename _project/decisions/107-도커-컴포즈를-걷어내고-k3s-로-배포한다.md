# 107. 도커 컴포즈를 걷어내고 k3s 로 배포한다

- 날짜: 2026-09-08
- 작성: 정성윤
- 관련: `020`(로컬 도커 환경 단일화) · `024`·`105`(한 컨테이너·한 도메인) · `w3-aws-deploy`

## 맥락

`server` 를 실제 주소(`server.solidbob.cloud`)에서 돌려야 한다. 지금 `infra/` 에는 로컬
개발용 `docker-compose.yml` 하나뿐이고 운영 쪽은 코드가 없었다.

티켓 `w3-aws-deploy` 는 `infra/docker/server.Dockerfile`·`infra/terraform/`·
`infra/aws-console-setup.md` 를 `[x]` 로 적어 두었으나 **셋 다 저장소에 커밋된 적이 없다**
(git 이력 전수 확인, 2026-09-08). 실제로 있는 것은 `infra/elasticsearch/Dockerfile` 하나였다.
체크만 먼저 되고 파일이 따라오지 않은 것이다 — 절대 원칙 8에 따라 그대로 적는다.

## 선택지

| | 내용 | 문제 |
|---|---|---|
| A | 컴포즈를 운영까지 그대로 (`compose.prod.yml`) | 재시작·롤백·상태 확인을 손으로 한다. 파드 단위 관측이 없다 |
| B | EKS | 컨트롤 플레인만 6주 $102. 예산 $400 에서 감당할 값이 아니다 |
| **C** | **k3s 단일 노드** | 학습 곡선. 대신 컨트롤 플레인이 공짜고 EC2 한 대에 다 들어간다 |

## 결정

**C. 컴포즈를 완전히 걷어내고 k3s 로 간다.**

1. **`infra/docker-compose.yml` 을 삭제한다.** 로컬 개발은 `docker run` 두 줄로 대체하고
   `infra/README.md` 에 적었다 — 컴포즈가 하던 일은 PostgreSQL·Elasticsearch 기동뿐이었다.
2. **이미지는 로컬에서 굽고 Docker Hub 로 보낸다.** EC2 는 pull 만 한다.
   지침서는 EC2 안에서 굽고 `k3s ctr images import` 로 반입하는 방식을 적고 있으나,
   **그 방식은 이미지가 GB 급일 때 유리하다.** 실측 결과 server 이미지는 **362MB** 다 —
   `ai/requirements.txt` 전체가 아니라 `elasticsearch` 하나만 얹기 때문이다(아래 근거).
   Docker Hub 를 쓰면 EC2 를 새로 세워도 이미지가 남고 롤백이 태그 하나로 끝난다.
3. **HTTPS 는 k3s 내장 Traefik + cert-manager 로 한다.** ALB 를 쓰지 않는 이유는 월 $20+.

   ⚠ **2026-09-08 정정**: 처음에는 Caddy 를 hostPort 로 붙이고 `--disable=traefik` 로
   설치할 계획이었다(지침서 16-2). 실제 EC2 구축은 **Traefik Ingress + cert-manager** 로
   갔고, 그쪽이 부품이 하나 적다 — k3s 가 Traefik 을 이미 갖고 있으므로 얹을 것은
   cert-manager 하나다. **매니페스트를 실제 구성에 맞춰 다시 썼다**(`infra/k8s/base/`).
   `kubectl diff` 로 클러스터와 차이 0을 확인했다. Caddyfile 은 삭제했다.

## 근거

**① 컴포즈에는 앱이 없었다.** `docker-compose.yml` 이 띄우던 것은 PostgreSQL 과
Elasticsearch 뿐이고 `server` 는 로컬에서 `uvicorn --reload` 로 돌고 있었다. 즉 컴포즈를
지워서 잃는 것은 **로컬 개발 편의 하나**이고, `docker run` 두 줄로 대체된다.

**② 이미지가 작다 — 362MB (실측).** 요청 경로가 `ai/` 에서 실제로 쓰는 서드파티를 전수
확인하니 `elasticsearch` 하나였다. `torch`·`transformers` 는 요청 경로에 없다. 그래서
`server/requirements.txt` + `elasticsearch` 만 설치한다. 이 크기면 Docker Hub 왕복이 싸다.

**③ `ai/apps` 를 같은 이미지에 넣어야 검색이 꽂힌다.** `main.py` 가 `../ai/apps` 를 경로에
올린다(`decisions/024`). 그래서 **빌드 컨텍스트가 저장소 루트**여야 한다. 확인 방법은
`/health` 의 `spokes` 다 — 2026-09-08 로컬 실측:

```
docker run -e ELASTICSEARCH_URL=... -e DATABASE_URL=... callguard-server
→ {"status":"ok","postgres_configured":true,"elasticsearch_configured":true,
   "spokes":["masking","closure_gate","retrieval"]}
```

`server/` 만 넣으면 `retrieval` 이 빠지는데 **서버는 정상으로 뜬다.** 조용히 501 로 남는
것이 설계된 동작이라(`decisions/024`) 이 확인을 거르면 드러나지 않는다.

## 함께 고친 것

- **`.env` 가 8월 25일자 MySQL 판이었다.** `MYSQL_*` 키를 `POSTGRES_*` 로 옮기고
  `POSTGRES_PORT` 를 `3306` → `5432` 로 고쳤다. 그대로 뒀으면 배포 후 `/health` 가
  `postgres_configured: false` 를 **에러 없이** 뱉었을 것이다. `decisions/018`(PostgreSQL
  전환) 이 코드는 바꿨지만 각자의 `.env` 는 손댈 수 없었던 것이다.
- `.dockerignore` 를 만들었다. 빌드 컨텍스트가 저장소 루트라 `.env`·`data/`·`jekyll/` 이
  통째로 딸려 들어갈 수 있었다(SEC-2).

## 팀에 미치는 영향 ⚠

**류준·장민석의 로컬 환경이 바뀐다.** `cd infra && docker compose up -d` 가 더는 없다.
`infra/README.md` 의 「로컬 개발」 절 두 줄로 대체된다. 데이터 볼륨 이름이 달라지므로
기존 컴포즈 볼륨은 남아 있고, 필요하면 그대로 두면 된다.

## 되돌리는 법

`git revert` 로 이 커밋을 되돌리면 `infra/docker-compose.yml` 이 살아난다 — 컴포즈 파일은
지웠을 뿐 고치지 않았다. 이미지 두 개는 컴포즈에서도 그대로 쓸 수 있다(`image:` 로 참조).
k3s 쪽은 EC2 를 종료하면 정리된다.

## 남은 것

**GPU·EXAONE(지침서 11·14장)을 지금 할지 미룰지는 아직 정하지 않았다.** 지금 코드에는
GPU 를 쓰는 경로가 없다(검색은 BM25 뿐, 생성 모델 미구현). 티켓 `w3-aws-deploy` 는
"EXAONE 을 EC2 에 올리지 않는다"고 적었는데 지침서(09-04)는 g4dn + Ollama 를 전제한다 —
지침서가 나중이라 방향이 바뀐 것으로 보이나 **명시된 적이 없다.** 미결 항목에 걸어 둔다.
