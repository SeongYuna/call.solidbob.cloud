# 105 — 배포는 한 컨테이너, 도메인도 `server.solidbob.cloud` 하나

**날짜**: 2026-09-03
**작성**: 정성윤 (브랜치 `PM`)
**관련**: `decisions/024`(검색 스포크를 같은 프로세스에서 꽂는다) · `decisions/104`(docs 서브도메인) ·
[w3-aws-deploy](/backlog/w3-aws-deploy/)

## 맥락

[미결 항목](/open-items/)에 *"배포를 한 컨테이너로 할지 둘로 나눌지 — 정성윤 님 결정"* 이
2026-08-27 부터 걸려 있었다. AWS 를 짜려면 여기서 시작해야 한다.

모순은 이렇다. `decisions/024` 가 **검색 스포크를 같은 프로세스에서 꽂기로** 했는데,
`CLAUDE.md` §3 은 여전히 **두 도메인**을 적고 있다.

```
server/   ... 배포: server.solidbob.cloud
ai/       ... 배포: ai.solidbob.cloud
```

같은 프로세스면 한 컨테이너에 둘이 함께 실린다. 지금은 `ai/` 에 서비스 실체가 없어
모순이 드러나지 않았을 뿐이다.

## 선택지

| | 방법 | 비용 |
|---|---|---|
| A | **한 컨테이너·한 도메인** — `CLAUDE.md` 의 도메인 서술을 하나로 고친다 | 문서 수정 |
| B | `ai/` 를 서비스로 올리고 HTTP 어댑터로 전환 | `ai/` 에 웹 서버를 새로 만든다. 홉이 늘어 4.1절 p95 예산을 먹는다 |
| C | 컨테이너는 하나인데 도메인을 둘 다 붙인다 | 같은 곳을 가리키는 이름이 둘. 나중에 누군가 분리된 줄 안다 |

## 결정

**A.** 컨테이너 하나, 도메인 하나 — `server.solidbob.cloud`.
`ai.solidbob.cloud` 는 **자리표시자 레코드째로 지운다.**

## 근거

**① 새 결정이 아니라 `024` 의 미반영분이다.** `024` 가 «같은 프로세스» 를 정한 순간
배포 단위는 이미 하나로 정해졌다. `CLAUDE.md` 쪽이 그 결정보다 낡은 것이고,
문서 우선순위(결정 기록 > 기획서 > 파생 문서)대로 결정 기록이 이긴다.

**② B 를 고를 이유가 지금 없다.** `ai/` 에는 HTTP 표면도 웹 프레임워크 의존성도 없다
(`ai/requirements.txt` 주석 — *"의존성(fastapi·uvicorn)은 `server/requirements.txt` 에 있다"*).
없는 서비스를 새로 만드는 일이 된다.

**③ C 는 거짓말이 오래 산다.** `ai.solidbob.cloud` 가 응답하면 다음 사람은 `ai/` 가
따로 떠 있다고 읽는다. 이 저장소는 이미 **자리표시자 레코드가 자리표시자인 줄 몰라서**
한 번 시간을 썼다(`decisions/103` 이관 중 레코드 소실 건).

## 되돌리는 법

`024` 의 「되돌리는 법」과 같은 조건에서 되돌린다 — `ai/` 가 GPU 나 별도 스케일링을
요구하게 되면 그때 서비스로 분리하고 도메인을 다시 판다. Terraform 으로 짜 두므로
대상 그룹을 하나 더 붙이는 일이 된다.

## 함께 고치는 것

- `CLAUDE.md` §3 의 `ai/` 줄에서 「배포: ai.solidbob.cloud」 삭제
- 클라우드플레어에서 `ai` 레코드 삭제, `server` 를 EIP 로
- [미결 항목](/open-items/)의 해당 줄을 해소로 표시
