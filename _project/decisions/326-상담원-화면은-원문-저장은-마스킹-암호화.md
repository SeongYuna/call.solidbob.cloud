# 326 — 상담원 화면에는 원문을 보여 주고, 저장할 때 마스킹하고 전사 본문은 암호화한다

**날짜**: 2026-10-06
**작성**: 장민석 (브랜치 `server`)
**상태**: 채택 — 구현됨(배포 전 · 운영 키 미설정)
**관련**: C-5 · SEC-1 · 절대 원칙 3 · `decisions/304`(HMAC 식별) · `decisions/324`(중간 자막 가드) · `decisions/408`(원문 열람 토글 철회, 조서희)

---

## 맥락

지금까지 C-5 는 **「자막·저장 양쪽 앞단」**이었다 — 서버가 마스킹한 응답만 상담원 화면으로 갔고, 같은 마스킹본이 DB 에 들어갔다.

**사용자 결정(2026-10-06)**: 상담원에게는 정보를 다 보여 주고, 데이터베이스나 저장할 때는 마스킹하고 암호화해서 저장한다.
프론트엔드(`apps/`)는 고치지 않고 서버·콜 미디에이터·인프라 쪽에서 바꾼다.

암호화 대상은 사용자와 두 번 맞췄다.

| 선택지 | 판단 |
|---|---|
| 마스킹본을 **해시**로 저장 | **기각** — 단방향이라 다시 읽을 수 없다. 지난 통화 보기·블랙리스트 근거 자막이 사라진다. 해시는 비교만 하는 식별자용이고 발신 번호에 이미 HMAC 으로 쓴다(`304`) |
| 마스킹본 + **원문 암호문**을 함께 저장 | **기각** — 원본을 (암호문으로라도) 보관하게 된다. 사용자가 원한 것은 「마스킹한 것을 암호화」다 |
| **마스킹본을 암호화** — 저장 텍스트 전부 | 보류 — 요약·블랙리스트 사유·지식 공백 설명까지 읽는 곳이 크게 늘어 마감(10-14) 안에 회귀 위험이 크다 |
| **마스킹본을 암호화 — 전사 본문(`transcript_segment.text`)만** | **채택**(사용자 선택) |
| 암호화하지 않는다(RDS 디스크 암호화만) | 기각 — DB 접속 권한·덤프가 새면 마스킹본이 그대로 읽힌다 |

## 결정

### 1. 화면 — 원문 + 서버가 준 강조 구간

- 콜 미디에이터가 `/ws` 로 내보내는 `transcript` 의 `text` 를 **원문**으로 바꾼다. `masked` 구간은 서버 응답 그대로 둔다 — 화면(`MaskedText`)이 그 자리를 `<mark>` 로 강조한다(프론트 무수정)
- 서버 마스킹은 한 글자를 `*` 한 글자로 바꿔 **길이를 보존**하므로(`masker.py`) 마스킹본 기준 구간이 원문에서도 같은 자리다.
  **코드포인트 수가 다르면 원문을 싣지 않고 마스킹본을 보낸다** — 어긋난 구간은 엉뚱한 글자를 가리킨다(애매하면 가린다, 원칙 3)
- **서버가 저장을 마친 뒤에만** 화면으로 간다(그대로). 서버가 실패하면 그 자막은 어디에도 가지 않는다
- 중간 자막(interim)도 원문이다. `324` 의 숫자 가드는 이제 **화면 강조 구간만** 만든다(interim 은 저장하지 않으므로 원래도 화면 전용이었다)

### 2. 하류 — 마스킹본 그대로

추천·콜 가드·컴플라이언스·필요서류 판정에는 **서버 마스킹본**이 간다(바뀐 것 없음). 그쪽은 받은 글을 저장한다.

### 3. `/close`(통화 후 요약) — 서버가 요약 전에 가린다

`/close` 는 **화면이 들고 있던 자막**을 본문으로 받는다. 화면이 원문을 갖게 되면 요약 입력에 원문이 섞이고 그 초안이 `call.summary_text` 에 저장된다.
그래서 postcall 인터랙터가 받은 자막을 **MaskingPort 로 가린 뒤에** 요약·저장으로 넘긴다(NER 이 꽂히면 그것까지).
입력 DTO 는 `PostcallSegment.raw_text` 로 바꿨다 — `TranscriptEvent` 는 「마스킹을 거친 것만」이라는 불변식을 지킨다.

### 4. 저장 — 전사 본문 AES-256-GCM

- `transcript_segment.text` 에 `enc:v1:` + urlsafe-base64(nonce 12 + 암호문 + 태그). 컬럼은 TEXT 그대로 — **스키마 변경 없음**
- 키: 환경변수 **`TRANSCRIPT_ENC_KEY`**(base64 32바이트, `openssl rand -base64 32`). 운영은 시크릿 `server-env`
- **키가 없으면 지금처럼 마스킹본 평문으로 저장한다.** `/health` 의 `transcript_encryption` 이 `"on"`/`"unset"` 으로 말한다
- **키 형식이 틀리면 서버가 뜨지 않는다**(합성 루트가 기동 때 한 번 만든다) — 조용히 평문으로 떨어지지 않고, 배포가 실패해 앞 파드가 남는다
- 읽는 곳 둘이 푼다: 지난 통화 보기(`transcript_query_repository`) · 블랙리스트 근거 자막(`blacklist_evidence_repository` — **풀고 나서** 자른다)
- **접두어가 없는 옛 행은 그대로 읽는다** — 기존 행을 다시 쓰지 않는다
- 못 풀면(키 없음·다른 키·암호문 변조) 예외 — 암호문을 화면으로 내보내지 않는다
- `masking_event` 는 위치·패턴뿐이라 암호화하지 않는다
- DB 를 직접 읽는 E2E 검사(`scripts/persona_sim/e2e_check.py`)도 같은 키로 푼다 — 암호문을 그대로 넘기면 SEC-1 판정이 헛통과한다

### SEC-1 은 어떻게 되나

**「마스킹 전 원문이 DB·로그 어디에도 남지 않는다」는 그대로다.** 바뀐 것은 C-5 의 위치다 — 「자막·저장 양쪽 앞단」 → **「저장 앞단(과 하류)」**.
원문이 머무는 곳은 서버 요청 처리 중 메모리 · 콜 미디에이터 메모리 · `/ws` 를 받은 브라우저 메모리다.

## 근거

- 사용자 결정이다(기획 변경 — 이 결정 기록이 공식 경로)
- 상담원은 통화 당사자라 고객이 말한 번호·주소를 이미 듣는다. 화면에서 가려도 상담원에게서 정보를 지키지 못하고, 받아 적기만 어렵게 한다
- 암호화는 마스킹 위의 한 겹이다 — 오류 전사에서 마스킹이 새는 것이 실측돼 있다(규칙만 5% 오류에 1건 · 10%에 2건, 커밋 `e966b62`).
  그 누락분과 패턴 밖 상담 내용을 DB 접속 권한·덤프 유출에서 지킨다. RDS 디스크 암호화는 DB 에 접속한 사람에게 평문을 보여 주므로 지키는 자리가 다르다
- 화면 원문을 콜 미디에이터에서 붙인 이유: 미디에이터가 원문을 이미 갖고 있다 — 서버 응답에 원문을 되실을 필요가 없고 서버 계약(`text` = 마스킹본)도 그대로다

## ⚠ 남는 것

1. **운영 키가 아직 없다**(정성윤 — `w8-transcript-enc-key-ops`). 배포해도 `transcript_encryption: "unset"`(마스킹본 평문 — 지금과 같다). `server-env` 에 넣는 절차는 런북 12-2-d. `.env.example` 은 보호 훅 때문에 사람이 `TRANSCRIPT_ENC_KEY=` 를 넣는다
2. **키를 잃으면 암호화된 전사를 되돌릴 수 없다** — 지난 통화 보기·블랙리스트 근거가 500 이 된다. 키 교체(rotation) 경로는 없다(`v1` 접두어만 있다)
3. **운영 DB 를 SQL 로 직접 보면 암호문이다** — 전사 확인은 API(`GET /hub/calls/{id}/transcript`)나 같은 키를 쓰는 스크립트로 한다
4. **배포 순서**(정성윤 — 같은 티켓): server `0.1.46` 이 call-mediator `0.2.14` 보다 먼저(또는 함께) 나가야 한다. 미디에이터만 먼저 나가면 `/close` 요약에 원문이 섞여 저장된다
5. **프론트 문구가 옛 정책 그대로다**(프론트 무수정 — 사용자 지시. 조서희 — `w8-agent-screen-plain-copy`). 자막 잠금 아이콘 title 「민감정보가 마스킹되었습니다」 · `MaskedText.tsx` 주석 「실서버는 원문을 절대 주지 않는다」 · `.claude/rules/call.md §2`.
6. 원문이 **브라우저 메모리**에 통화 동안 있다(스토어). 브라우저 저장소(`localStorage`·`sessionStorage`)에는 자막을 쓰지 않는다 — 테마·토큰·주소뿐이다(`apps/call/src` 전수 grep, 10-06). `/ws` 뷰 토큰을 가진 쪽(`replay_persona_call.ts --save-ws` 등)도 원문을 받는다
7. 전사 본문 밖의 저장 텍스트(요약 `summary_text` · 블랙리스트 사유·메모 · 지식 공백 설명 · 컴플라이언스·추천 기록)는 **마스킹만** 하고 암호화하지 않는다(범위 선택)
8. AAD 를 쓰지 않는다 — DB 에서 행끼리 암호문을 바꿔 끼우면 탐지하지 못한다
9. 하류에는 여전히 마스킹본이 간다 — 10-02 미결 「가려진 발화가 절차 판정과 카드에 쓰인다」는 이 결정으로 풀리지 않는다
10. 10-02 촬영한 시연 영상은 마스킹된 화면이다 — 배포 뒤 화면과 다르다

## 되돌리는 법

1. 화면: `call_registry.ts` 의 `forAgentScreen(...)` 을 `masked` 로 되돌린다(테스트 3건 원복)
2. `/close`: 마스킹을 빼면 안 된다 — 화면을 되돌린 뒤에도 남겨 두는 편이 안전하다(이중 마스킹은 무해하다)
3. 저장: `server-env` 에서 `TRANSCRIPT_ENC_KEY` 를 **지우지 않는다**(이미 암호화된 행을 못 읽는다). 새 행만 평문으로 돌리려면 저장소 쪽 `seal` 을 빼고 `unseal` 은 남긴다.
   완전히 걷으려면 암호화된 행을 같은 키로 풀어 평문으로 다시 쓰는 일회성 스크립트가 먼저다
