# 322 — 읽기 경로를 상담원 토큰으로 닫는다(두 단계) · 지식 공백은 관리자와 상담원

**날짜**: 2026-09-22
**작성**: 장민석 (브랜치 `server`)
**상태**: 채택 — 서버 구현됨(배포 전). 2단계(`READ_AUTH_REQUIRED=true`)는 상담원 화면이 토큰을 실은 뒤(`w6-read-path-token-ui`, 조서희)
**관련**: `120`(쓰기 경로 — 같은 두 단계 모양) · `307`(상담원 토큰) · `315`(`/close`·카드 피드백) · 미결 「읽기 경로 인증 없음」

---

## 맥락

운영에서 `GET /hub/calls` 가 토큰 없이 **실제 음성 테스트 통화 12건·고객 HMAC·`?customer_id=` 필터**까지 보여 줬다.
`/transcript`·`/record`·`POST /hub/search` 도 같다. `GET/PATCH /hub/knowledge-gaps` 도 열려 있었고, `POST` 는 설명을 **마스킹 없이** 저장했다.

부르는 쪽을 코드로 확인했다:

| 경로 | 부르는 쪽 | 지금 토큰 |
|---|---|---|
| `GET /hub/calls` · `/transcript` · `/record` · `POST /hub/search` | 상담원 화면 `apps/call` `coreClient.ts` · `scripts/persona_sim/e2e_check.py` | **안 싣는다** |
| `GET /hub/knowledge-gaps` · `/summary` · `PATCH` | 관리자 화면 `apps/admin` `hubClient.ts` | **관리자 토큰을 이미 싣는다** |
| `POST /hub/knowledge-gaps` | 없다 | — |

## 결정

1. **상담원 화면 읽기 넷 — `120` 처럼 두 단계.** 먼저 잠그면 운영 상담원 화면이 깨진다.
   - 지금: 상담원 토큰 **또는** 서비스 토큰을 **받는다.** 실었는데 틀리면 **401**(프론트가 틀린 값을 싣는 것을 이행기에 찾는다). 안 실으면 지나간다
   - 다음: `READ_AUTH_REQUIRED=true`(`server-env`) — 토큰 없는 요청도 401. **코드 배포 없이** 켠다
   - `/health` 에 `read_guard: open|locked` — 조용한 열림을 만들지 않는다
   - 상담원 토큰 확인은 **토큰이 왔을 때만** DB 를 탄다 — 이행기에 안 실은 요청은 DB 설정과 무관하게 전처럼 돈다
2. **지식 공백 조회·집계·상태 변경 — 관리자 토큰, 바로 닫는다.** 관리자 화면이 이미 싣는다(`authedRequest`).
3. **지식 공백 신고 — 상담원 토큰, 바로 닫는다.** 부르는 곳이 없다. **설명은 `MaskingPort` 로 가린 뒤 저장한다**(C-5·SEC-1). 누가 신고했는지는 저장하지 않는다(부록 A-1).
4. `e2e_check.py` 가 `INGEST_SERVICE_TOKEN` 이 있으면 읽기에 싣는다.

## 근거

- 상담원 화면은 조서희 님 전담이다 — 서버만 잠그면 화면이 깨지고, 그 사이 수동 QA(`319`)가 막힌다
- 관리자 쪽은 이미 토큰을 싣고 있어 이행기가 필요 없다 — 기다릴 이유가 없다
- 서비스 토큰도 받는 이유: 합성 통화 검사(`e2e_check.py`)가 읽는다. `/close` 가 같은 이유로 둘 다 받는다(`315`)

## 되돌리는 법

- 2단계만: `server-env` 에서 `READ_AUTH_REQUIRED` 를 지우고 서버 재시작 → `read_guard: open`
- 전부: `main.py` 의 `_READERS` 네 줄과 두 지식 공백 라우터의 `dependencies=` 를 걷는다. 설명 마스킹은 남겨 둔다(원문 저장으로 되돌리지 않는다)
