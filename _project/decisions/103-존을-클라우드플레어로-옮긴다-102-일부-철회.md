# 103 — `solidbob.cloud` 존을 클라우드플레어로 옮긴다 (`102` 의 DNS 위치 부분 철회)

**작성일**: 2026-08-28
**작성**: 정성윤
**상태**: 진행 중 — 존 추가 완료, **네임서버 전환 대기**
**갱신 대상**: `_project/decisions/102`(DNS 위치 부분만) · `jekyll/open-items.markdown` · [w2-custom-domain](/backlog/w2-custom-domain/)
**관련**: `decisions/102`(404 원인·커스텀 도메인 결정 — **그 부분은 그대로 유효하다**)

## 맥락

`102` 는 커스텀 도메인을 **가비아 DNS 에 CNAME 한 줄**로 붙이자고 했고, 클라우드플레어 경유는
"이 목적에는 얻는 게 없다"고 뺐다. 같은 날 사용자가 **클라우드플레어에 존을 이미 추가**했고
(`Waiting for your registrar to propagate your new nameservers` 상태), 방향을 그대로 간다.

**`102` 의 나머지는 하나도 바뀌지 않는다** — 404 의 원인(프로젝트 페이지 한 겹 ↔ 루트 절대경로
405곳)도, 해법이 커스텀 도메인이라는 것도, 저장소 쪽 반영(`_config.yml`·`CNAME`·`pages.yml`)도
그대로다. **바뀌는 것은 CNAME 을 어느 DNS 에 적는가 한 가지다.**

## 결정

**존을 클라우드플레어로 옮기고, `call` CNAME 을 거기에 둔다. 단 프록시는 켜지 않는다.**

`102` 가 클라우드플레어를 뺀 근거 셋 중 **둘은 순서를 지키면 사라지고, 하나는 남는다** —

| `102` 의 우려 | 지금 |
|---|---|
| 존을 통째로 옮겨야 한다 | 그대로 사실이다. 다만 **레코드가 2건뿐**(apex `A 216.198.79.1` · `www` CNAME, 둘 다 Vercel)이라 옮기는 비용이 작다 |
| 프록시가 GitHub 인증서 발급을 막는다 | **회색 구름(DNS only)으로 두면 발생하지 않는다.** 아래 조건 1 |
| `Flexible` 이면 리다이렉트 루프 | **`Full (strict)` 로 두면 발생하지 않는다.** 아래 조건 2 |

### 지키는 조건 (이걸 어기면 `102` 가 경고한 그대로 된다)

1. **`call` 은 항상 `DNS only`(회색 구름).** 프록시를 켜면 도메인이 클라우드플레어 IP 로 해석돼
   **GitHub 의 인증서 발급이 막힌다.** 정적 문서 사이트라 프록시가 줄 이점도 없다.
2. **암호화 모드는 `Full (strict)`.** `Flexible` 은 리다이렉트 루프를 만든다.
3. **apex·`www`(Vercel)도 `DNS only`.** Vercel 이 자기 인증서를 직접 발급하는데 주황 구름 뒤에서는 꼬인다.
4. **네임서버 전환 전에 레코드 2건을 대조한다.** 존 가져오기가 레코드를 놓치는 일이 있고,
   그 상태로 NS 를 바꾸면 **그 순간 랜딩 페이지가 죽는다.**

## 근거

- **얻는 게 생긴다.** `102` 시점의 판단은 "지금 목적에 이점이 없다"였는데, 존이 클라우드플레어에
  있으면 나중에 `server.solidbob.cloud`(AWS 백엔드)에 프록시·터널·WAF 를 붙일 때 이관 단계가 없어진다.
  `102` 자신이 *"그때 옮겨도 비용이 같다"* 고 적었으니, **지금 옮겨도 비용이 같다**는 뜻이기도 하다.
- **DNS 를 한 곳으로 모은다.** 가비아(등록)·클라우드플레어(DNS)로 갈리는 게 아니라, 레코드를 볼 곳이 하나가 된다.
- 위험은 조건 1~4 로 전부 닫힌다. 넷 다 **설정 화면에서 확인 가능한 상태**이지 운에 맡기는 것이 아니다.

## 되돌리는 법

가비아에서 네임서버를 `ns.gabia.co.kr` · `ns1.gabia.co.kr` · `ns.gabia.net` 로 되돌리고,
가비아 존에 apex `A 216.198.79.1` · `www CNAME 8511982eb7ecc120.vercel-dns-017.com.` ·
`call CNAME solidbob02.github.io.` 를 적는다. 그러면 `102` 의 원안(A-1)이 된다.
GitHub Pages 설정은 DNS 를 어디에 두든 그대로다.

## 남는 위험

**네임서버 전환 중에는 두 존이 동시에 유효하다**(전파 전 해석기는 가비아, 전파 후는 클라우드플레어).
두 곳의 레코드가 다르면 **사람마다 다른 사이트를 본다.** 조건 4 를 지키면 두 존의 내용이 같아
전환 중에도 차이가 없다.
