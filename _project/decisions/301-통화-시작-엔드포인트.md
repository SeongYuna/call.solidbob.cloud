# 301 — 통화 시작을 `POST /hub/calls` 로 알린다

**날짜**: 2026-09-10
**작성**: 장민석 (브랜치 `server`)
**관련**: `db/schema.sql` `call`·`transcript_segment` · `decisions/018`(PostgreSQL) · 7.3절 인터페이스 계약

## 맥락

`transcript_segment.call_id` 는 `call` 을 외래키로 참조한다. 그런데 **`call` 행을 만드는 경로가
없었다.** 통화 시작은 게이트웨이(Node, `services/gateway`)가 알리는 것으로 그려져 있지만
게이트웨이는 코드 0줄이고, 7.3절 계약 3종(전사·카드·종결)에도 "통화가 시작됐다"는 메시지가 없다.

2026-09-10 Neon 에 실제로 쳐 보니 `POST /hub/transcripts` 가 마스킹은 하고 **저장에서 500** 이
났다 — 어떤 `call_id` 를 보내도 첫 건부터 실패한다. 조서희가 ngrok 으로 서버 API 를 받아
붙이려는 시점이라 그대로 둘 수 없었다.

## 선택지

| | 방법 | 비용 |
|---|---|---|
| A | **`POST /hub/calls` 를 만든다** — 게이트웨이(지금은 테스트하는 사람)가 전사보다 먼저 부른다 | API 표면이 하나 는다. 7.3절 계약에 "통화 시작" 메시지를 올려야 한다 |
| B | 전사 첫 건에서 `call` 을 자동 생성한다 | `domain`·`stt_engine`·`channel_count` 를 전사 이벤트가 모른다 — **지어내게 된다.** 통화 메타데이터가 "첫 전사가 도착한 시각"으로 오염된다 |
| C | 외래키를 뺀다 | 고아 전사가 생긴다. D(통화 후 처리)가 통화 단위로 묶을 근거가 사라진다 |

## 결정

**A.** `POST /hub/calls` — 슬라이스 `call_start` 를 `docs/architecture.md §3` 단면대로 만든다.

- 요청: `call_id`(필수) · `domain`(기본 `dasan`, DDL CHECK 4종) · `stt_engine`(기본 `google-stt`,
  가짜면 `mock` 처럼 사실대로) · `channel_count`(기본 1) · `started_at`(없으면 서버 시각)
- **멱등이다.** 같은 `call_id` 를 다시 알리면 `ON CONFLICT DO NOTHING` — 시작 시각이 덮이지 않고
  응답의 `created` 가 `false` 다. 게이트웨이가 재시도해도 통화가 둘이 되지 않는다.
- `customer_id`·`agent_id` 는 받지 않는다. 둘 다 외래키라 없는 값을 넣으면 실패하고, 이 경로에는
  아직 그 정보가 없다(F-3 반복 문의 연결 때 채운다).
- `status` 는 `in_progress` 로 넣는다. DDL 이 자유 문자열이라 통화 후 처리(D)가 붙으면 그쪽이 바꾼다.
- PostgreSQL 설정이 없으면 로그 어댑터로 떨어진다 — 전사 기록과 **같은 조건**이다. 전사는 DB 로
  가는데 통화만 로그로 가면 외래키가 깨지므로 둘의 분기 조건을 일부러 같게 뒀다.

## 근거

- B 를 고르면 "측정하지 않은 값을 기록"하는 꼴이 된다(절대 원칙 2 의 변형). 통화가 언제·어떤
  엔진으로 시작됐는지는 전사가 아니라 통화를 연 쪽이 안다.
- 게이트웨이가 생기면 통화를 여는 순간 이 엔드포인트를 부르면 된다 — 지금 테스트하는 사람이 하는
  일과 같다. 게이트웨이 코드가 붙어도 서버 쪽은 바뀌지 않는다.

## 함께 고친 것 (결정이 아니라 수정)

같은 날 같은 경로에서 드러난 것 둘. 결정 사항이 아니라 버그라 여기 적어 두기만 한다.

- **커넥션 팩토리가 `DATABASE_URL` 을 안 읽었다.** 운영(k3s)은 그것 하나만 주입한다(런북 12-2).
  `/health` 는 `postgres_configured: true` 였지만 실제 연결은 호스트 없이 시도되는 구조였다.
  `DATABASE_URL` 이 있으면 그것을 쓰고 개별 `POSTGRES_*` 는 뒤로 보냈다.
- **ES 인덱스가 없을 때 500 → 503.** 운영에서 `/hub/search` 가 `index_not_found_exception` 으로
  500 이었다. 코드 오류가 아니라 적재 미완이므로 503 에 이유를 실어 돌려준다.

## 되돌리는 법

`call_start` 슬라이스 9개 파일과 `main.py` 의 `include_router(call_start_router)` 한 줄을 지운다.
자기소개(`/hub/myself`) 목록에서 한 줄을 뺀다. DB 는 건드리지 않았다.
