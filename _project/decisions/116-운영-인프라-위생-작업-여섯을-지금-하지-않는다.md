# 116. 운영 인프라 위생 작업 여섯을 지금 하지 않는다

- 날짜: 2026-09-19
- 작성: 정성윤
- 상태: 채택
- 관련: `decisions/208`(운영 NER·임베딩 — t3.large 재측정이 전제) · 런북 `0`·`8`·`20`·`21-1` · 미결 「09-17 운영 점검에서 넘긴 것」
- 티켓: 없음 (티켓을 만들지 않기로 한 것이 이 결정의 내용이다)

## 맥락

2026-09-17 운영 점검(류준, 읽기 전용)에서 **운영 AWS 가 런북과 어긋난 항목 여섯**이 나왔다.
전부 「지금 고장 난 것」이 아니라 **위생·보험 성격**이고, 남은 기간(마감 2026-10-27)에
사람 손이 드는 콘솔 작업이다.

| # | 어긋남 | 런북이 요구하는 것 |
|---|---|---|
| ① | 자동 중지가 없다 (AL2023 에 `crontab` 없음, 3일 연속 가동) | 21-1 「반드시」 |
| ② | 탄력적 IP 가 없다 | 8장 |
| ③ | AMI 스냅샷이 0개 | 20장 「반드시」 |
| ④ | EBS 30GB 비암호화 | 7-4 |
| ⑤ | `ai` DNS 자리표시자가 살아 있다 (`216.198.79.1`) | `decisions/105` 이후 쓰지 않는 이름 |
| ⑥ | 안 붙은 보안 그룹 `launch-wizard-2` 가 22 를 전체 개방으로 열어 둔다 | 3장 |

**여기에 하나를 덧붙인다 — 운영 EC2 는 런북의 `g4dn.xlarge` 가 아니라 `t3.large` 다.**
그 변경에 결정 기록이 없었다. **이 문서가 그 기록을 겸한다**(아래 「함께 기록하는 사실」).

## 선택지

| 후보 | 판단 |
|---|---|
| 여섯을 지금 다 한다 | 런북과 맞춰진다. 대신 콘솔 작업 반나절 + ①②는 서로 얽혀(자동 중지를 켜면 EIP 가 먼저 필요) 순서를 지켜야 한다 |
| **지금 하지 않는다** | 남은 기간을 기능·측정에 쓴다. 대가는 아래 「남는 위험」에 적는다 |
| 일부만 (③ AMI 만) | 보험값이 가장 큰 하나. 검토했으나 이번 결정에서는 택하지 않았다 |

## 결정

**여섯 전부 지금 하지 않는다.** 티켓도 만들지 않는다 — 안 할 일을 보드에 띄워 두면
「지금 누가 무엇을 하는가」가 거짓이 된다(`CLAUDE.md` §4).
미결 항목에는 **「하지 않기로 했다」로 닫아** 남긴다(지우지 않는다 — 절대 원칙 8).

## 근거

- **런북의 예산 경고는 이 인스턴스의 것이 아니다.** 0장·21장의 «24/7 이면 $597 — 예산 초과» 는
  **`g4dn.xlarge`(GPU) 기준**이고, 운영은 GPU 없는 `t3.large` 다. 자동 중지의 급함이 그만큼 내려간다.
  ⚠ **그렇다고 공짜가 아니다** — 실제 청구액은 이 머신에서 확인할 수 없어 **적지 않는다**(절대 원칙 2).
  금액이 궁금하면 Billing 콘솔의 실제 청구서로 본다.
- **⑥ 은 실제 노출이 0 이다.** `launch-wizard-2` 는 **어느 인스턴스에도 붙어 있지 않다**(09-17 실측).
  22 가 열린 규칙이 적혀 있을 뿐 트래픽이 닿는 경로가 없다. 「열린 SSH」로 인용하지 않는다.
- **④ 의 대상이 개인정보가 아니다.** 전사 원문·마스킹 기록은 **RDS** 에 있고, EC2 EBS 에는
  k3s·컨테이너·ES 인덱스(공개 지식베이스 98조항)가 있다. SEC-1 이 걸리는 자리가 아니다.
- **②③ 는 서로를 부른다.** EIP 없이 인스턴스를 멈추면 퍼블릭 IP 가 바뀌어 DNS 를 손으로 고쳐야 한다.
  **멈추지 않기로 한 이상(①) EIP 의 필요도 함께 줄어든다** — 셋을 같이 안 하는 것이 일관적이다.

## 남는 위험 (받아들이는 대가)

- **가장 큰 것은 ③ 이다.** AMI 가 없고 `infra/terraform/` 은 설계서일 뿐 `destroy`→`apply` 재현 경로가 없다
  (콘솔로 세웠다). **인스턴스를 잃으면 재구축이 반나절 이상**이고, 그 시점이 마감 직전이면 데모가 없다.
  RDS·S3 는 별개라 데이터는 남는다 — 잃는 것은 **노드 세팅**이다.
- 비용은 24시간 계속 나간다. 마감(10-27) 이후 정리는 런북 「프로젝트 종료 시 정리」.
- ⑤ 는 사람이 헷갈린다 — `ai.solidbob.cloud` 는 `decisions/105` 로 없어진 이름인데 DNS 에 답이 있다.

## 되돌리는 법

항목마다 독립적이라 **하나씩 되살릴 수 있다.** 마음이 바뀌면 런북의 해당 절만 그대로 따른다 —
① 21-1(단, AL2023 은 `crontab` 이 없어 EventBridge 스케줄러로) · ② 8장 · ③ 20장 ·
④ 7-4(스냅샷 → 암호화 복원이라 인스턴스 교체가 따른다) · ⑤ 클라우드플레어에서 레코드 삭제 ·
⑥ EC2 → 보안 그룹 → 삭제. **③ 만 되살리는 것이 가장 싸다**(런북 20장 «싼 보험»).

## 함께 기록하는 사실 — 운영 EC2 는 `t3.large` 다

런북 0장·7-2 는 `g4dn.xlarge`(GPU 1장)를 전제로 쓰였지만 **운영은 `t3.large`(GPU 없음)로 돌고 있다.**
언제·왜 바뀌었는지는 결정 기록이 없어 **이 문서가 처음 적는다.** 딸려오는 것 —

- 11장 「GPU 를 여러 파드가 나눠 쓰게 만들기」·14장 Ollama GPU 점유는 **지금 운영에 해당하지 않는다.**
- **`decisions/208`(운영에 NER·임베딩을 올릴지)의 측정값은 M5 맥에서 잰 것이다** — t3.large 재측정이
  아직 남아 있고, 이 문서는 그 전제를 바꾸지 않는다.
