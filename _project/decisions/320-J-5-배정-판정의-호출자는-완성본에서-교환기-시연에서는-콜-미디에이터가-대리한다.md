# 320 — J-5 배정 판정의 호출자: 완성본은 교환기, 시연은 콜 미디에이터가 대리한다

**날짜**: 2026-09-22
**작성**: 장민석 (브랜치 `server`)
**상태**: 채택 — 구현됨(call-mediator `0.2.4`, 배포 전)
**관련**: `decisions/313`(판정 API — 이 결정이 **호출자 표기만** 고친다) · `126`(미디에이터가 부른다 — 그대로 유지, 성격을 명시한다) · `204`(J 블록) · 절대 원칙 10
**티켓**: `w7-j5-routing-caller`

---

## 맥락

`126`(정성윤, 09-21)을 구현한 뒤 `313` 과 대조하다가 둘이 **다투는 것처럼 읽힌다**는 것이 드러났다.

- `313` 은 선택지 표에서 「통화 시작 때 판정해 기록만」을 기각했다 — `POST /hub/calls` 는 **이미 상담원과 연결된 뒤** 불리기 때문이다.
- 그런데 같은 문서의 인증 줄과 기획서 7.3절(`plan.md` 허브 HTTP 표면)은 호출자를 「교환기·**게이트웨이**(= 콜 미디에이터)」로 적었다. 기각 근거로 든 주체를 호출자로 적은 **모순**이다.
- `126` 은 그 표기를 따라 콜 미디에이터를 골랐다. 동기는 「시연에서 J-5 가 보이고 집계가 숫자를 갖는다」였다.

엔드포인트는 하나(`POST /hub/routing-decisions`)이고 `126` 은 그것을 바꾸지 않는다. 갈린 것은 **누가·언제 부르는가** 하나다.

## 선택지

| | 장점 | 단점 |
|---|---|---|
| ① `313` 만 — 교환기 몫으로 두고 우리는 안 부른다 | 완성본 구조 그대로 · 기록이 전부 진짜 | 시연에서 J-5 가 안 돈다 · 현황판 배정 판정 0 · 페르소나 SYN-007 기대값을 확인할 길이 없다 |
| **② `126` 유지 — 시연용 대리 호출자로 명시** | J 블록 전체(요청 → 승인 → 재인입 판정)가 실제 통화로 돈다 · 판정 재료는 실데이터 | 판정이 연결을 바꾸지 못한다 · 후보 명단이 고정값이다 |

## 결정

**② — 사용자 선택(2026-09-22).** 시연을 AI 페르소나 합성 통화로 돌리는데, 그 대본이 J-5 를 전제로 짜여 있다 —
SYN-006(블랙리스트 요청) → SYN-007(같은 번호 재인입, 기대값 `"routing": "veteran"`, 「떨어지면 그 사실이 로그에 남아야 한다」).

1. **완성본의 호출자는 교환기(ACD)다 — 연결 전에, 실제 대기 상담사 명단을 들고 부른다.** `313` 의 설계 그대로다.
2. **시연에서는 콜 미디에이터가 통화 시작 직후 대신 부른다**(`126`). 이것은 완성본의 일부가 아니라 **교환기가 없는 시연 환경의 대리**다.
3. 대리의 한계 둘을 숨기지 않는다 — 발표·화면에서 「배정됐다」가 아니라 **「배정 판정」**으로 부른다.
   - **판정이 연결을 바꾸지 못한다** — 이미 받은 상담원이 그대로 받는다. `313` 대로 `call.agent_id` 를 건드리지 않고 `routing_log` 는 판정 기록이다.
   - **후보 명단은 `ROUTING_CANDIDATES`(설정 고정값)**다 — 「지금 받을 수 있는 상담사」가 아니다. 비면 빈 목록 → 서버가 기존 배정 규칙으로 떨어뜨린다.
4. `313` 의 인증 줄과 기획서 7.3절의 호출자 표기를 **「교환기(연결 전) — 시연에서는 콜 미디에이터가 대리(`320`)」**로 고친다.
5. 인증은 `126` 대로 서비스 토큰이다(교환기도 서버 간 호출이라 같다).

## 근거

- 판정 재료(고객 식별 · 적용 중 블랙리스트 · 근속 · 기준값)는 전부 운영 데이터다. 가짜는 후보 명단 하나이고, 그것을 적어 두면 절대 원칙 10(측정할 수 없는 것을 측정한 것처럼 쓰지 않는다)에 걸리지 않는다
- 페르소나 대본이 이미 J-5 를 기대값으로 갖고 있다 — 호출자가 없으면 SYN-007 은 확인할 수 없는 기대값이 된다
- 모순은 `313` 의 표기에서 시작됐다. 표기를 고치지 않으면 같은 오해가 다시 생긴다

## 되돌리는 법

- 교환기가 붙으면 **콜 미디에이터의 호출 한 곳**(`call_registry.ts` `decideRouting`)을 지우고 태그를 올린다 — 안 지우면 판정이 두 번 기록된다
- 서버 API·`routing_log`·관리자 설정은 그대로 둔다
