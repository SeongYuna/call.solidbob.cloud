# 309 — 블랙리스트 등록 만료를 관리자가 연장·단축한다 (205 「연장은 새 요청으로만」 철회)

**날짜**: 2026-09-15
**작성**: 장민석 (브랜치 `server`)
**관련**: `decisions/205` ⑤(보존 기간) · `decisions/304`(만료는 승인 때 관리자가 일수로) · 관리자 화면 「연장」 버튼(`apps/admin` `extendEntry`, 로컬 전용이었다)

## 맥락

관리자 화면에 등록 연장 버튼이 있는데 서버에 API 가 없어 **브라우저 메모리에서만** 바뀌었다. 확인해 보니 `decisions/205` ⑤ 가
*「연장은 새 요청 + 새 근거로만」* 이라 정해 두었다 — 버튼이 결정과 반대였다.

게다가 **그 «새 요청» 경로가 실제로 막혀 있었다.** `blacklist_entry` 의 부분 유니크 인덱스(`customer_ref WHERE released_at IS NULL`)가
**만료됐지만 해제되지 않은** 행도 자리로 세서, 만료 뒤 같은 고객의 새 요청을 승인하면 늘 23505 → 409 였다. 오류 문구는 «만료를 기다린다» 였지만 기다려도 풀리지 않는다.
(2026-09-15 integration 테스트로 재현 — 수정 한 줄을 빼면 실패)

## 선택지

| | 내용 |
|---|---|
| ① 205 유지 + 막힌 경로 수정 | 연장은 새 요청, 단축은 해제. 스키마 변경 없음 |
| ② **205 철회 + 관리자 연장·단축 API** | 만료를 직접 바꾸고 이력을 쌓는다. 스키마·마이그레이션 |
| ③ 단축만 허용 | 보존 기간을 줄이는 방향만 즉시, 연장은 새 요청 |

## 결정 (사용자 선택, 2026-09-15)

**②. 막힌 경로 수정도 함께 한다.**

- `POST /hub/blacklist-entries/{entry_id}/expiry {expires_in_days, reason}` — 만료를 **«지금부터 N일 뒤»** 로 다시 정한다. 연장·단축을 가르지 않는다
  - 1~365일(승인과 같은 상한) · 사유 필수, 저장 전 마스킹 · 변경자는 로그인한 관리자의 `admin_account.agent_id`(없으면 409, `decisions/304`)
  - 해제된 등록은 409 · 없으면 404. **만료됐지만 해제되지 않은 등록은 바꿀 수 있다**(되살리는 것이 곧 연장이다 — 이력에 남는다)
- `GET /hub/blacklist-entries/{entry_id}/expiry-changes` — 변경 이력, 오래된 순(관리자)
- 새 테이블 **`blacklist_entry_expiry_change`**(이전·새 만료 시각 · 변경자 · 사유 · 시각). 갱신·삭제하지 않는다. 방향(연장/단축)은 두 시각으로 드러나 따로 두지 않는다
- **승인할 때 같은 고객의 만료된 미해제 등록을 먼저 닫는다** — `released_at = expires_at`(실제로 끝난 시각) · `released_by = NULL`(사람이 푼 게 아니다) · 사유 「만료 — 같은 고객의 새 승인으로 닫음」

## 근거

- 관리자는 이미 «등록 여부·기간» 을 정하는 사람이다(`decisions/204`·`304`). 기간만 새 요청을 거치게 하면, 새 근거가 없는 연장은 상담원이 억지 요청을 올리는 쪽으로 샌다
- 205 의 걱정(근거 없이 기간이 늘어 영구 표시가 되는 것)은 **사유 필수 + 이력**으로 드러나게 한다 — 막지는 못한다(아래)

## ⚠ 남는 것

- **연장을 되풀이하면 사실상 영구 표시를 만들 수 있다.** 365일 상한은 한 번의 변경에만 걸린다. 이력으로 드러날 뿐 막지 않는다 — 누적 상한이 필요하면 따로 정한다
- 이력 테이블도 사유(마스킹본)를 무기한 보관한다 — `decisions/205` 「반려 요청 사유를 일정 기간 뒤 비우는 작업」 과 같은 보존 기간 문제가 여기에도 생긴다
- 프론트(`apps/admin`)는 아직 개월 단위 로컬 연장이다 — 조서희 님께 전달

## 되돌리는 법

1. 라우터 두 개(`blacklist_expiry_change_router.py`·`blacklist_expiry_change_list_router.py`)를 `main.py` 에서 빼면 기능이 닫힌다
2. 완전히 지우려면 슬라이스 파일 · `BlacklistPort.change_expiry`/`list_expiry_changes` · `ExpiryChange` DTO · 생성기의 테이블을 지우고, 운영에서 `DROP TABLE "blacklist_entry_expiry_change"`
3. 승인 시 만료 등록을 닫는 수정(`_CLOSE_EXPIRED`)은 **되돌리지 않는다** — 205 와 무관한 버그 수정이다
