# 136. 관리자 토큰 수명을 운영 값으로 올린다 — access 30분 · refresh 12시간

- 날짜: 2026-09-28
- 결정자: 정성윤 (사용자 확인 — 값도 사용자가 골랐다)
- 관련: `decisions/403`(관리자 구글 로그인) · 미결 「access 5분·refresh 10분은 테스트 값이다」(2026-09-14) ·
  티켓 `w7-demo-infra-readiness` 3번 · 수동 QA `Q-05`

## 맥락

`admin_access_token_ttl_seconds=300` · `admin_refresh_token_ttl_seconds=600` 은 2026-09-14 에
**「테스트만 진행할 것」이라는 전제**로 넣은 값이다. 그 전제가 바뀌었다 — 관리자 화면이 운영에 올라갔고
시연에서도 쓴다.

**15분이면 로그인이 풀린다.** 수동 QA 1회차에서 실제로 잡혔다(`Q-05`: 「5분 넘게 두면 로그인이 풀린다」).
시연에서 관리자 화면을 열어 둔 채 상담원 통화를 보여주다가 승인하러 돌아가면 이미 튕겨 있다.

운영 시크릿에는 **두 키가 아예 없었다** — 코드 기본값 300/600 으로 돌고 있었다.

## 선택지

| | access | refresh | 성격 |
|---|---|---|---|
| 그대로 | 5분 | 10분 | 시연 중 튕긴다 |
| 흔한 운영 값 | 15~30분 | 8~24시간 | 하루 한 번 로그인 |
| **채택** | **30분** | **12시간** | 시연 한 회차(1~2시간)를 덮고, 하루를 넘기지 않는다 |

## 결정

**access 30분(1800초) · refresh 12시간(43200초).**

- 운영 시크릿 `server-env` 에 `ADMIN_ACCESS_TOKEN_TTL_SECONDS=1800` · `ADMIN_REFRESH_TOKEN_TTL_SECONDS=43200`
  을 넣고 `callguard-server` 를 재시작했다(이미지 변경 없음).
- **코드 기본값도 같이 올렸다**(`server/core/config.py`). 시크릿에서 키가 빠진 채 새로 배포돼도
  **조용히 5분으로 돌아가지 않게** 하기 위해서다 — 그 조용한 회귀가 이 항목이 09-14 부터 안 보인 이유와 같다.
- `.env.example` 은 자격증명 보호 훅이 편집을 막는다 — **사람이 두 줄을 직접 고쳐야 한다**(아래).

## 근거

- **위험이 크지 않다.** 관리자 로그인은 구글 계정 **허용 목록**이 한 겹 더 있고, access 토큰은 Redis 세션
  마커와 함께 쓰여 `revoke()` 로 즉시 끊을 수 있다(`redis_jwt_access_token_issuer`).
- **12시간은 하루를 넘기지 않는다.** 아침에 로그인하면 그날 작업이 덮이고, 다음 날은 다시 로그인한다.
- QA `Q-05` 를 **운영 값으로 한 번만** 확인하면 된다 — 나중에 바꾸면 그 번호를 또 눌러야 한다.

## 되돌리는 법

```bash
kubectl -n callguard patch secret server-env --type json \
  -p '[{"op":"remove","path":"/data/ADMIN_ACCESS_TOKEN_TTL_SECONDS"},
       {"op":"remove","path":"/data/ADMIN_REFRESH_TOKEN_TTL_SECONDS"}]'
kubectl -n callguard rollout restart deploy/callguard-server
```
키를 지우면 **코드 기본값(이제 1800/43200)** 으로 돌아간다. 옛 5분/10분으로 되돌리려면 시크릿에 그 값을
명시하거나 `config.py` 를 함께 되돌린다.

## 사람이 해야 할 것 하나

`.env.example` 의 두 줄을 고친다(훅이 Claude 의 편집을 막는다).

```
ADMIN_ACCESS_TOKEN_TTL_SECONDS=1800
ADMIN_REFRESH_TOKEN_TTL_SECONDS=43200
```
