- `apps/call`의 `CallSummaryPanel`(확정 요약 카드 아래)에 통화 요약 재수정
  이력을 읽기 전용 목록으로 추가했다. 서버 `GET /hub/calls/{call_id}/summary-revisions`
  (`summary_revision_list_router.py`, `require_agent`)는 있었지만 프론트에
  호출 함수 자체가 없었다.
- 조사(1번) 중 정정: 지시문이 예로 든 `fetchCallRecord`는 실제로는 **토큰을
  안 쓴다**(`coreClient.ts` — `get<CallRecordResponseWire>(path)`, 헤더 없음).
  토큰 읽기+`Authorization` 헤더 패턴은 `reviseSummary`(`readAgentToken()` →
  없으면 즉시 `CoreApiError` → `{ Authorization: \`Bearer ${token}\` }`)에서,
  "GET + wire→camelCase 매핑" 패턴은 `fetchCallRecord`에서 가져와 합쳤다 — 이
  둘을 합친 함수가 이 파일에 아직 없어서 새로 만든 첫 사례다.
- `coreClient.ts`에 `fetchSummaryRevisions(callId)`와 `SummaryRevisionItem`
  타입을 추가했다. `revision_id` 등도 서버 `_types.StrField` 규칙대로 이미
  문자열이라 `toNum` 같은 변환이 필요 없었다.
- `CallSummaryPanel.tsx`에 `SummaryRevisionHistory` 컴포넌트를 추가하고,
  `SummaryConfirmationForm`의 잠금 카드(확정 후)와 재수정 폼(재수정 중) 양쪽
  아래에 `confirmed === true`일 때만 렌더한다 — 확정 전에는 이력이 있을 수
  없어(서버가 확정 전 재수정을 409로 막음) 호출 자체를 안 한다.
  `useEffect([callId, refreshKey])`로 첫 마운트와 재수정 성공 직후
  (`lastRevisedAt` 변경) 둘 다 다시 부른다. 실패 시 빈 catch로 삼키지 않고
  `wrapup-error`(`role="alert"`) — 이미 이 컴포넌트가 쓰는 에러 표시 클래스를
  그대로 재사용. 빈 배열이면 "재수정한 적이 없습니다."
- 판단(3번) — **`lastRevisedAt` 문구를 대체하지 않고 같이 두었다.** 그
  문구는 재수정 성공 직후 서버를 다시 안 불러도 바로 채워지는 가벼운
  한 줄 요약이고, 새 목록은 필요할 때 펼쳐 보는 상세(이전 요약·이전
  유형·사유)다. 하나(fetch)가 실패해도 다른 하나는 여전히 보인다 — 같은
  컴포넌트의 "카드 사용 현황"(총계+목록을 같이 둠)과 같은 방식.
- 판단(4번) — **별도 게이팅 코드를 추가하지 않았다.** `SummaryConfirmationForm`
  자체가 이미 `mode !== "mock" && call.callId.length > 0`일 때만 렌더되므로
  (`CallSummaryPanel.tsx` 기존 코드), 그 안에 얹은 `SummaryRevisionHistory`도
  mock 모드에선 애초에 마운트되지 않는다 — mock 시나리오에는 이 API에
  대응하는 데이터가 없으므로 정확히 맞는 동작이다.
- 빌드 확인: `cd apps/call && npm run build`(`tsc --noEmit && vite build`) 통과.
