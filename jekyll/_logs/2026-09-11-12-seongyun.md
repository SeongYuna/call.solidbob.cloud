- **운영 AWS 자원 이름을 실물로 되돌렸다 — 오늘 앞선 정정(10 기록·`decisions/108` 1번)이 틀린 전제였다.**
  108 은 «운영 실물이 `callguard` 다» 를 근거로 AWS 자원까지 `callguard-*` 로 정했다. 그런데 그 근거는
  **k8s 오브젝트**(네임스페이스 `callguard`·Deployment `callguard-server`) 이름이었다. 사용자가 콘솔로 확인한 것:
  - EC2 보안 그룹 **`assist-web`** — 런북 원안 그대로다. 런북 3-2 에 적혀 있던 «운영 인스턴스는 원안대로
    만들어지지 않았다» 는 틀렸다.
  - RDS(`describe-db-instances`): **식별자 `callguard-pg` · 마스터 사용자 `callguard` · 초기 DB `assist`**.
    식별자·사용자는 문서와 맞았지만 **DB 이름이 달랐다.** 이대로 런북 12-2 를 실행했다면 시크릿이 없는 DB
    `/callguard` 를 가리켜 서버가 `database "callguard" does not exist` 로 붙지 못했을 것이다.
- 고친 것:
  - 런북 — 머리말에 이름 정정을 달았다. 0장 자원표 · 3장(`assist-db`, 소스 `assist-web`) · 6-4 · 6-5(초기 DB `assist`) ·
    6-7 연결 문자열 · 12-2 `patch` JSON(`/assist`, `POSTGRES_DB_NAME=assist`) · 17-1 기대 출력 `('assist', 'callguard')` ·
    증상 표 · 문제 해결 표를 고쳤다.
  - `infra/k8s/base/secret.example.yaml`(형식 `…/assist`) · 티켓 `w4-rds-prod-db`(RDS 생성됨 체크, 실물 값).
  - `decisions/108` — 원문은 지우지 않고(절대 원칙 8) 1번 바로 아래에 날짜 붙인 정정을 달았다.
- 확인: 12-2 의 `printf` 가 만드는 JSON 을 파싱했다 — 사용자 `callguard` · DB `assist` · `sslmode=require` ·
  `POSTGRES_DB_NAME` `assist`. 저장소에 남은 `callguard-db`·`/callguard` 는 108 원문 두 줄뿐이다(정정이 붙어 있다).
- **아직 모르는 것**: RDS 에 붙은 **DB 보안 그룹의 이름**. ID 만 봤다. 문서에는 원안 `assist-db` 로 적고
  «실물 미확인» 이라고 표시했다. 5432 인바운드 소스가 `assist-web` 인지도 확인하지 않았다 — 17-1 에서 타임아웃이
  나면 여기부터 본다. 보안 그룹 ID 는 공개 저장소라 문서에 적지 않았다.
- **같은 세션에서 CI 결함 둘을 고쳤다**(a5 세션이 찾아 알려 왔다 — 11 기록 보강):
  - `test.yml` integration step 에 `set -o pipefail` 을 넣었다. `shell:` 을 지정하지 않은 step 은 `bash -e` 이고
    pipefail 이 꺼져 있어서, `pytest … | tee` 가 실패를 삼켰다. 게다가 «1 failed, 3 passed» 도 `[0-9]+ passed`
    grep 을 통과했다 — **실패해도 초록이었다.** `bash -e` 로 흉내 내 보니 수정 전 종료코드 0, 수정 후 1 이다.
    게이트웨이 세션도 자기 `gateway` job 에 같은 수정을 넣었다.
  - `integration_settings` 픽스처의 `.env` 폴백을 뺐다. 이제 `CALLGUARD_TEST_DATABASE_URL` 만 보고 없으면 스킵한다.
    이 테스트들은 행을 쓰고 지우는데 `.env` 는 쓰지 않기로 한 Neon 을 가리키고 있었다. 11 기록의 «없으면 `.env`» 는
    이제 사실이 아니다.
  - a5 가 게이트웨이의 실제 `HttpHub` 로 이 작업 트리 서버를 두드려 확인했다: 통화 전 전사 409 · 통화 시작 멱등 ·
    같은 순번 두 통화 분리 · P4 구간 섞임 없음.
