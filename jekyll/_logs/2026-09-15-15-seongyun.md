- **라이브 룰셋의 복원본을 만들었다 — `.github/ruleset-main.json`.**
  `…-12` 기록의 「남긴 것 ②(룰셋 자체의 백업이 없다)」를 이어서 닫았다. 전에는 라이브 룰셋
  (`21538648`)이 **유일본**이라 누가 지우면 되돌릴 근거가 없었다.
  - `gh api` 응답에서 PUT 이 받지 않는 **읽기 전용 8개**를 걷어냈다:
    `id`·`node_id`·`created_at`·`updated_at`·`source`·`source_type`·`_links`·`current_user_can_bypass`.
    남은 쓰기 가능 필드 여섯(`name`·`target`·`enforcement`·`conditions`·`rules`·`bypass_actors`)이
    **라이브와 한 글자도 다르지 않음을 대조 확인**했다.
  - 되살리기: `gh api -X PUT $R/21538648 --input .github/ruleset-main.json` (지워졌으면 `-X POST $R`).
    뜨는 명령과 함께 `CLAUDE.md` §7 에 적었다.
  - **`branch-protection.json` 과 역할이 다르다** — 그쪽은 «클래식 보호로 되돌릴 때의 정책 기록»
    (`decisions/011`)이고, 이쪽은 «지금 쓰는 룰셋의 복원 산출물»이다. 둘 다 남긴다.

- **남은 것 하나 (미결·`w8-final-docs` 에 적었다)** — `branch-protection.json` 의 **형식 차이**는
  못 없앤다. 클래식 API 형식이라 라이브 설정 둘을 담을 자리가 없다:
  `require_extra_approval_for_unattributed_changes` · `allowed_merge_methods`.
  클래식으로 되돌리는 순간 그 둘은 사라진다는 뜻이다 — 지우는 게 아니라 **적어 두는 쪽**으로 뒀다.

- **동기화 규칙을 못 박았다** — `CLAUDE.md` §7 에 «룰셋을 고치면 `ruleset-main.json` 을 함께
  갱신한다». 오늘 이 항목이 생긴 경위가 «룰셋만 바뀌고 파일은 안 바뀌었다»라, 규칙을 안 적으면
  같은 어긋남이 다시 난다.
