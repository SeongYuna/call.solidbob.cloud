- **게이트웨이에 접속 제어를 넣었다 — 배포 선행 조건이었다.** [09 기록](/progress/)의 게이트웨이는 `Origin` 만 봐서
  브라우저만 막았다. a5 세션이 짚었다 — Ingress 로 열리면 비브라우저 클라이언트가 `call_id` 없이 `WS /ws` 로 **모든
  통화의 자막·추천을 받고**, `/ingest` 로 **STT 캡까지 과금을 태울** 수 있었다. 미결 「게이트웨이 배포」에 ⑥ 으로 올리고
  바로 막았다([w4-gateway-streaming-stt](/backlog/w4-gateway-streaming-stt/)).
- **규칙** (`services/gateway/src/domain/access.ts`) — 이 머신(루프백)은 토큰 없이 받는다(로컬 개발 무설정). 그 밖은
  **문마다** 토큰이 맞아야 하고, 토큰을 안 넣고 배포하면 **전부 401(fail-closed)** 이다 — 쿠버네티스에서는 Traefik 을
  거쳐 오므로 루프백이 아니다. 루프백 판정은 소켓 주소로만 하고 `X-Forwarded-For` 는 믿지 않는다.
- **토큰을 둘로 갈랐다 — a5 세션 검토로 설계를 바꿨다.** 처음엔 공유 토큰 하나였다. 그런데 대시보드는 공개 사이트라
  브라우저가 내는 토큰은 번들에서 누구나 읽는다 — 하나였다면 그 값으로 **과금 문까지** 열렸다.
  `/ingest` = `GATEWAY_INGEST_TOKEN`(진짜 비밀, **헤더로만** — URL 은 접근 로그에 남는다) ·
  `/ws` = `GATEWAY_VIEW_TOKEN`(**비밀이 아니다**, 무작위 스캔만 막는다). 둘을 같게 두면 기동 때 경고한다.
  비교는 해시 후 상수 시간이라 길이가 달라도 예외 없이 거절한다. 토큰·거절된 쿼리는 로그에 남기지 않는다.
- **확인**: 테스트 53 → **65개 통과**. 핵심 규칙 둘은 일부러 망가뜨려 테스트가 잡는 것까지 봤다 — 「토큰 미설정이면
  통과」로 바꾸면 fail-closed 테스트 2개가, 「과금 문도 `?token=` 을 받음」으로 바꾸면 URL 거절 테스트가 실패한다.
  **실측도 했다** — 루프백이 아닌 이 머신의 네트워크 주소로 붙어 운영 상황을 흉내 냈다. 토큰 미설정이면 바깥 `/ws`·`/ingest`
  둘 다 401, 루프백은 열림. 설정 뒤에는 `/ingest` 가 토큰 없음·틀림·**뷰 토큰**·**`?token=` 으로 낸 진짜 비밀** 전부 401,
  맞는 헤더만 통과. `/ws` 는 `?token=뷰` 통과·과금 토큰 401. `/health` 는 토큰 없이 200. 로그에 토큰 문자열 0건.
- **정직하게** — `/ws` 는 아직 **제대로 막힌 게 아니다.** 뷰 토큰은 공개 번들에 들어가면 누구나 갖는다. 자막을 보는
  사람을 가르려면 상담원 로그인이 필요하고 서버에도 없다(「서버에 인증이 없다」). 미결 항목에 그렇게 적었다.
- **다른 세션과 겹치지 않게 했다** — bc 세션이 `0.1.2` PR 을 준비 중이라, 공유 배포 파일(`kustomization.yaml`·
  `release.yml`·`secret.example.yaml`)은 건드리지 않았다. 같은 작업 트리라 게이트웨이가 그 PR 에 섞여 나가지 않도록
  «게이트웨이 파일은 이름으로 빼고 스테이징해 달라»고 알렸다.
- 남은 것: 배포(이미지·k8s·Ingress `/gateway`·`release.yml`) — 서버 `0.1.2` 가 운영에 나간 뒤다(`POST /hub/calls` 가
  거기서 생긴다). 배포 때 두 토큰을 서로 다른 값으로 시크릿에 넣는다. `.env.example` 키 넷은 사람이 넣는다.
  `_project/STATE.md` 는 오늘 앞 세션들처럼 그대로 뒀다.
