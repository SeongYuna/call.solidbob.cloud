- `apps/admin`의 `EntriesTab`(블랙리스트 등록 상세)에 만료 변경 이력을 읽기
  전용 목록으로 추가했다. `fetchBlacklistExpiryChanges`(`hubClient.ts:376-385`)는
  이미 있었지만 부르는 화면이 없었다.
- 조사(1번): `EntriesTab.tsx`는 등록마다 `EntryRow` 하나를 그리고, 연장·해제는
  `useState`로 로컬 입력을 받아 부모 콜백(`onExtend`/`onRelease`)으로 올린다 —
  모두 props로 받은 데이터라 자체 fetch가 없었다. 같은 앱의 `SettingsTab.tsx`가
  `useAuthStore`를 직접 구독해 자체적으로 `fetchAgentTokens` 등을 부르는
  선례가 있어(`accessToken`을 props로 안 받고 스토어에서 직접 읽음), 이 패턴을
  재사용했다 — `AdminPanel.tsx`를 거쳐 새 prop을 추가할 필요가 없었다.
  `AuditLogTab.tsx`의 "아직 ...이력이 없습니다" 빈 상태 문구 관례도 참고했다.
- 구현: `EntryRow`에 `history` 상태(`collapsed | loading | ready | error`)를
  추가하고, "변경 이력 보기/숨기기" 토글 버튼을 눌렀을 때
  `fetchBlacklistExpiryChanges(accessToken, entry.entry_id)`를 호출한다.
  결과를 오래된 순 그대로(서버가 그렇게 준다) 렌더 — 이전 만료일 → 새 만료일 ·
  변경자 · 사유 · 변경 시각. 빈 배열이면 "변경 이력 없음", 실패하면
  `.header-error`(`role="alert"`) — 이 저장소가 이미 쓰는 에러 표시 클래스를
  재사용했다(빈 catch로 삼키지 않음).
- `accessToken`이 없는 경우(로그인 풀림)도 별도 에러 메시지로 처리했다.
- 매번 펼칠 때마다 새로 fetch한다(캐시 안 함) — 관리자 화면이라 최신 상태
  확인이 더 중요하다고 판단, 데이터 양도 작아 비용 문제 없음.
- 빌드 확인: `cd apps/admin && npm run build`(`tsc --noEmit && vite build`) 통과.
