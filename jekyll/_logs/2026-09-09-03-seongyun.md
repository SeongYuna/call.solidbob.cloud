- **어제 작업을 커밋·머지했다**(PR #51, `774f95f`). CI 가 `jekyll` 에서 한 번 걸렸는데 —
  내가 쓴 진행 기록이 `/logs/` 를 가리켰다. **그런 경로는 없다**(컬렉션을 렌더링하는 페이지는
  `/progress/` 다). 링크 검사가 잡았고 고쳐서 통과했다.
- **`apps/dashboard/package-lock.json` 을 복구했다.** 세션 시작 때부터 삭제돼 있었는데,
  조서희가 `f140066` 로 커밋한 파일이고 gitignore 대상도 아니다. **`apps/platform` 쪽 락파일은
  멀쩡했고**, `npm ci --dry-run` 이 통과하는 걸 보면 낡아서 지운 것도 아니다 — 사고로 본다.
- **CI/CD 1단계를 세웠다.** 확인하다가 전제 둘이 실제와 다른 걸 찾았다 —
  ① **인스턴스에 IAM 역할이 안 붙어 있었다**(IMDS `iam/info` → 404). SSM 에이전트는 돌고
  있었지만 등록이 안 돼 Send-Command 가 불가능했다. 역할을 붙이니 로그가
  `HealthCheck reporting agent health` 로 바뀌었다. ② **인스턴스에 git 도 저장소 클론도 없다.**
- **그래서 배포를 「인스턴스에서 git pull」이 아니라 「러너가 렌더한 YAML 을 SSM 으로 실어
  보내기」로 바꿨다.** 인스턴스에 git 을 깔 이유가 없고, CI 가 렌더한 그 YAML 이 그대로
  적용되므로 어긋날 여지가 줄어든다. 렌더 결과는 `/opt/callguard/current.yaml` 에 남겨
  부팅 수렴이 재사용한다. base64 로 실어 보내 따옴표 이스케이프 문제를 없앴다(4,116자,
  SSM 한도 100,000자).
- **버전은 저장소가 정한다.** `kustomization.yaml` 의 `newTag` 를 CI 가 읽는다.
  원래 계획은 CI 가 태그를 만들어 저장소에 되쓰는 것이었는데 **main 이 보호돼 있어 봇이
  push 할 수 없다.** 방향을 뒤집어 PR 안에서 사람이 올리게 했다 — 「저장소 = 클러스터」
  불변식이 구조적으로 유지되고, 이번 머지가 배포인지도 눈에 보인다.
- **발동 조건은 태그가 아니라 main 머지가 됐다.** 신뢰 정책이 `refs/heads/main` 으로 만들어졌다.
  문서만 고친 머지로 API 가 재배포되지 않도록 경로 필터를 걸었다.
- **⚠ 빌드 판정을 「바뀐 파일」이 아니라 「레지스트리에 그 태그가 있나」로 바꿨다.**
  처음에는 경로만 봤는데, [seq 2](/progress/)가 짚은 `imagePullPolicy: IfNotPresent` 문제를
  대입해 보니 구멍이 있었다 — **`kustomization.yaml` 의 newTag 만 올린 PR 은 경로 조건에
  안 걸려 굽지 않고, 없는 이미지를 적용해 ImagePullBackOff 가 난다.** 이제 태그가 레지스트리에
  없으면 무조건 굽고, **코드가 바뀌었는데 태그가 그대로면 실패시킨다**(옛 이미지가 조용히
  계속 도는 것을 막는다). 로컬에서 `docker manifest inspect` 로 두 태그를 실측해 확인했다 —
  `0.1.0` 있음 / `0.1.1` 없음.
