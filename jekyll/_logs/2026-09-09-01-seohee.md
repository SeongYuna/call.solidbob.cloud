- **서버 `RecommendResponse.fired`(필수)가 프론트 계약(`RecommendationBatch`)에서 빠져 있던 걸 반영했다.** 서버는 이미 `fired: false`(검색 안 함)와 `fired: true, cards: []`(B-6 관련 문서 없음)를 구분해 보내고 있었는데, 프론트 타입에 필드가 없어 화면에서 둘 다 "관련 문서가 아직 없습니다"로 뭉개지고 있었다. `_project/decisions/401`에 근거를 남겼다 — 서버 수정은 필요 없고 프론트 타입 누락만 고치면 되는 건이었다.
- `RealGatewayClient.parseRecommendation`을 `fired` 분기로 나눴다. `fired: false` 응답은 서버가 실제로 보내는 형태(`call_id`·`cards`·`trigger_at_ms` 없음)를 그대로 받아들이도록 기본값(빈 문자열·0·빈 배열)을 채운다. 구조 추정용 태그 매칭(`hasKeys`)에도 `fired` 단독 케이스를 추가했다.
- **정확한 지연시간(`e2e_latency_ms`) 노출 대신 로딩 인디케이터로 대체했다.** 실제로 화면에 그 숫자를 쓰는 곳이 없었어서 그냥 필드를 지웠다(타입·파서·mock 데이터 3곳). 대신 `cardsLoading`/`lastFired`를 스토어에 추가하고, `TermsPanel` 팝업뷰가 카드가 없을 때 로딩 스피너 → "이 민원 유형은 서류 안내 대상이 아닙니다"(fired:false) → 기존 "관련 문서가 아직 없습니다"(fired:true, cards:[]) 순으로 갈리게 했다.
- 로딩 신호(`onRecommendationPending`)는 §7.3 계약에 없어 **mock만 보낸다** — mock 게이트웨이가 트리거 시점에 먼저 쏘고 `internal_latency_ms` 뒤에 실제 카드를 배달한다. 실서버는 아직 이 신호가 없어 라이브 모드에서는 로딩 스피너가 뜨지 않는다(계약이 생기면 연결).
- 확인: `apps/dashboard` `npm run typecheck` 통과, `npm run dev` 정상 기동. 브라우저 자동화가 이 환경에 없어(Chrome 확장 미설치), esbuild로 번들한 스크립트로 `parseGatewayMessage`+스토어 리듀서를 직접 실행해 세 상태(`fired:false`/`fired:true,cards:[]`/`fired:true,cards:[...]`)와 로딩 전이가 기대대로 나오는 것을 확인했다. 실제 렌더링(스피너 위치 등)은 브라우저로 눈으로 보진 못했다.
- 남은 것: 실서버가 `onRecommendationPending`에 대응하는 신호를 계약(§7.3)에 추가하기 전까지는 라이브 모드에서 로딩 인디케이터가 동작하지 않는다. 브라우저에서 실제 렌더링(스피너 위치·스타일) 육안 확인이 남아 있다.
