- **상담기록 재생 화면 재설계** — 남아 있던 마지막 큰 항목. 착수 전 코드를 보다가 예상 못
  한 걸 발견했다: `callStore.ts`의 `openHistory()`가 `historySegments`·`historyCards`·
  `historyTranslations` 등 풍부한 상태를 채우고 `TranscriptPanel`·`TermsPanel`도 그 상태를
  읽는 분기가 이미 있었는데, `App.tsx`가 `viewMode === "history"`면 무조건 요약 화면
  (`CallSummaryHost`)으로 이동해버려서 **그 인라인 자막 재생 코드가 실제로는 절대
  렌더링되지 않는 죽은 코드**였다. `.claude/rules/call.md`는 "「상담기록」은 목록만 연다.
  항목을 고르면 왼쪽 자막 패널이 그 기록을 보여 준다"고 적어 둔 원래 설계였는데, 실제
  동작(요약 화면 전체 화면 전환)과 어긋나 있었다.
- 사용자에게 방향을 물어("죽은 코드를 되살릴지" vs "지금 동작을 정본으로 삼을지") **"둘
  다 살리는 방향으로"** 라는 답을 받아 두 화면을 토글로 공존시켰다:
  - `historyView: "record" | "transcript"` 상태 신설. `App.tsx`의 `showSummary`를
    `phase === "wrapup" || (viewMode === "history" && historyView === "record")`로 좁혀
    기본 진입은 요약 화면(기존과 동일)이되, "자막 보기"/"요약 보기" 버튼으로 전환 가능하게
    했다(`TranscriptPanel`의 history-banner, `CallSummaryPanel`의 `CallSummaryShell` 헤더).
  - `openHistory`가 실 API 설정 시 `fetchCallTranscript` + `fetchCallRecord`(신규,
    `coreClient.ts` — `GET /hub/calls/{id}/record` 전체 래핑)를 병렬로 불러 두 화면을
    한 번에 채운다.
  - 실제 계약은 추천 카드(`recommendations[].cards[]`)와 필요서류 판정(`closures[]`)이
    서로 다른 배열이라 mock처럼 "카드 하나에 판정 하나가 붙는" 모양이 아니다 —
    `panelCardsFromRecord`가 실 카드는 판정 없이 그대로, 판정마다 표시용 카드를 하나씩
    따로 만들어 기존 `TermsPanel`의 "필요서류" 체크리스트 렌더링을 그대로 재사용한다.
    번역·TTS·콜가드·악센트힌트 재생은 실서버에 애초에 없는 데이터라 항상 빈 채로 둔다
    (지어내지 않는다).
  - `CallHistoryPanel`(목록)도 실 API 분기 추가 — `GET /hub/calls`. "다시 재생"(mock
    시나리오 흉내)은 실제 통화엔 의미가 없어 뺐다.
  - 카드 채택 토글(`AdoptToggle`)은 상담기록 조회 중엔 숨겼다 — 채택 기록이
    `state.callId`(실시간 통화)에 귀속되는 구조라 지난 통화 조회 중 누르면 엉뚱한 통화에
    붙는 잠재 버그가 있었다(기존 코드, 이번에 발견).
  - 확정된 요약(`historyRecord.summaryConfirmed`)이면 「요약 확정」 폼이 잠긴 채로 열려
    곧바로 「재수정」할 수 있다(`SummaryConfirmationForm`에 `initiallyConfirmed` prop
    추가) — 지난 세션에 남겨 뒀던 "재수정은 같은 세션에서만 가능" 제약이 이걸로 풀렸다.
- **버그 하나 발견·수정**: 대기화면의 「최근 상담기록」에서 열면 `shell`이 `standby`로
  남아 있어, "자막 보기"로 전환하는 순간(`showSummary`가 false가 되는 순간) 대기화면이
  TranscriptPanel 대신 떴다. `openHistory`가 `shell: "assist"`도 같이 정하도록 고쳤다.
  헤드리스 크롬 + CDP(Node 내장 WebSocket, 의존성 추가 없음)로 실제 클릭까지 왕복 확인
  (목록→요약→자막→요약→실시간 복귀) — 스크린샷·콘솔 에러 스캔 전부 정상.
- `apps/call` `tsc --noEmit`·`vite build` 클린.
- `jekyll/open-items.markdown`의 관련 두 항목을 완료로 표시하고 처리 내역을 적었다.
- 남은 것: J-5 배정 판정(`POST /hub/routing-decisions`) 호출 주체(게이트웨이 쪽, 정성윤
  결정 대기), 블랙리스트 보존 정리 "해제" 관련 요청(사용자 의미 확인 대기 — 아직 결론
  안 남).
