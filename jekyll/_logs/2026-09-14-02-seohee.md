- **관리자 로그인을 새로 만들었다 — 구글 OAuth만, 회원가입 없음.** 사용자 지시대로
  access token은 Redis 5분(테스트 스코프), refresh token은 RDS 10분 회전(rotation)으로
  잡았다. 맥락·근거·되돌리는 법은 `_project/decisions/403`에 전부 남겼다.
- **DB**: `db/generate_schema_docs.py`의 `TABLES`에 `admin_account`(허용 목록 —
  회원가입이 없으니 이 행이 있어야만 관리자다)·`admin_refresh_token`(원문 대신
  SHA-256 해시만 저장, 회전 시 지우지 않고 `revoked_at`만 찍는다)을 추가하고
  재생성했다. **`db/schema.sql`은 직접 고치지 않는다** — 자동 생성 파일이다.
- **`server/apps/admin_auth/` 신설** — `hub`와 같은 레벨의 독립 슬라이스(클린
  아키텍처: dtos·ports·use_cases·adapter·dependencies). 구글 id_token 검증(`google-auth`),
  JWT 서명(`PyJWT`) + Redis 세션 존재 확인(로그아웃이 exp 전에 즉시 반영되게), refresh
  token 회전을 각각 어댑터로 분리했다. `.importlinter`에 `admin_auth`를 네 계약
  전부(root_packages·클린 아키텍처·`ai` 비의존·프레임워크 격리)에 추가했다.
  라우트: `POST /admin/auth/google`·`/refresh`·`/logout`, `GET /admin/auth/me`.
  **설정이 없으면 다른 hub 프로바이더처럼 Log 어댑터로 대체하지 않고 RuntimeError로
  막는다** — 인증에서 가짜 구현은 곧 구멍이다.
- **`server/core/config.py`·`.env.example`에 5개 키 추가**
  (`GOOGLE_OAUTH_CLIENT_ID`·`ADMIN_JWT_SECRET`·`ADMIN_ACCESS_TOKEN_TTL_SECONDS`·
  `ADMIN_REFRESH_TOKEN_TTL_SECONDS`·`REDIS_URL`), `server/requirements.txt`에 `PyJWT`·
  `redis`·`google-auth` 추가.
- **`apps/admin` 프론트**: `AdminLoginScreen.tsx`(Google Identity Services 버튼,
  `index.html`에 `gsi/client` 스크립트 추가) · `lib/auth/authStore.ts`(access token은
  메모리에만, refresh token만 localStorage — 새로고침 시 조용히 재로그인) ·
  `lib/auth/authApi.ts`. `App.tsx`가 로그인 게이트로 `AdminPanel`을 감싼다. 기존
  자리채움 `mock/adminAuth.ts`("계정 API가 오면 이 값만 바꾼다"던 그 주석)는 이제
  안 쓰여서 지웠다.
- **확인한 것**: `cd server && pytest`(302건, 신규 인터랙터 단위테스트 8건 포함)
  전부 통과. 기존 `test_connection.py`가 `Settings`를 직접 생성하고 있어서 새 필드
  5개 때문에 깨졌던 것을 픽스처에 반영해 고쳤다(내 기능 추가가 남의 테스트를
  건드린 사례라 따로 적는다). `apps/admin`은 `npm run typecheck`·`npm run build`
  통과. **실제 브라우저 로그인은 이 환경에 Google Client ID·Redis·RDS가 없어서
  못 해봤다** — 로컬에서 `.env`에 값 채우고 `docker run redis:7-alpine` 띄운 뒤
  실제로 눌러봐야 한다.
- 남은 것 (`jekyll/open-items.markdown`에 옮김):
  1. Google Cloud Console에서 OAuth 클라이언트 ID 발급 — 아직 아무도 안 만들었다.
  2. `admin_account`에 첫 관리자 이메일을 넣는 SQL을 운영 DB에 직접 실행해야
     로그인할 수 있는 사람이 생긴다.
  3. 운영(k3s)에 Redis를 어떻게 띄울지 — 이번 결정은 로컬 스코프만 다뤘다
     (ElastiCache는 안 쓴다, `infra/CLAUDE.md` §1-2). k3s 안에 컨테이너로 띄울지
     정성윤과 정해야 한다.
  4. access 5분/refresh 10분은 "테스트만 진행"이라는 전제의 값이다 — 실제
     운영에 올리기 전에 다시 정해야 한다.
