- **실서버 모드에 mock이 새던 곳 둘을 막았다.** 배포된 `call.solidbob.cloud`는
  `VITE_CORE_API_URL`이 구워져 있어 `isCoreApiConfigured()`가 항상 `true`인
  실서버 모드인데, 두 컴포넌트가 그 체크 없이 mock 전용 데이터를 그대로 그리고
  있었다.
  1. `CustomerHistorySummaryCard.tsx` — "재상담 고객" 카드가 `mock/customerHistory.ts`의
     시나리오 고정 이력(09-01·08-15 등)을 실제 통화에도 띄우고 있었다.
     `isCoreApiConfigured()`가 true면 `null`을 반환하도록 게이팅.
  2. `TranscriptPanel.tsx`의 "권한 확인 (데모)"·"원문 보기" 버튼 쌍 — 실서버 모드에서는
     `plain_text`가 안 오고 이미 마스킹된 텍스트가 그대로 다시 뜰 뿐이라 "원문 보기"
     라벨이 사실과 다르다. `isCoreApiConfigured()`로 렌더 자체를 껐다(제거 아님 — 완전
     제거는 팀 결정 기록 후 별도로).
  - mock 모드 동작은 손대지 않았다 — 둘 다 `isCoreApiConfigured()` false 분기는 그대로.
  - 기존 `isCoreApiConfigured()`를 그대로 재사용했고 새 플래그는 만들지 않았다.
- **읽기 전용 조사**: `detectCustomerRisk`(고객 발화 욕설/PII 키워드·정규식 감지)가
  실서버 모드에서도 무조건 호출됨을 확인 — `TranscriptPanel.tsx:661-664`에 모드 체크가
  없다. 결과(`CustomerRiskBanner`)는 항상 화면에 뜬다(`:856-875`). 서버발 `call_guard`
  배너(`:831-844`)는 **다른 컴포넌트**인데, 같은 줄에서 클라이언트 감지기가 abuse/distress를
  잡으면 `hideLegacyGuard`(`:697-699`)로 서버 배너 쪽을 숨긴다 — 겹치면 클라이언트
  하드코딩 감지기가 서버 신호를 가린다. 이번 세션에서는 코드를 고치지 않았다(범위 밖).
- `apps/call`: `tsc --noEmit` + `vite build` 통과(`npm run build`).
- 남은 것: 두 버튼(권한확인/원문보기)의 **완전 제거**(mock 코드까지)는 이번에 안 함 —
  사용자 지시대로 팀 결정 기록이 먼저다. `detectCustomerRisk`와 서버 `call_guard`의
  배너 우선순위(`hideLegacyGuard`)가 실서버에서 원하는 동작인지도 미결.
