- **컴포즈를 걷어내고 k3s 배포 준비를 시작했다(0단계).** 개인 운영 지침서(09-04)를 따라가려 했는데
  **지침서가 있다고 전제한 파일 두 개가 저장소에 없었다** — `infra/docker/server.Dockerfile`·
  `infra/docker/Caddyfile`. git 이력 전수 확인 결과 **커밋된 적이 없다**(`infra/terraform/`·
  `infra/aws-console-setup.md` 도 같다). 티켓 `w3-aws-deploy` 는 셋 다 `[x]` 로 적고 있다 —
  체크만 먼저 되고 파일이 안 따라온 것이다. 절대 원칙 8대로 그대로 적는다.
- **만든 것**: `server.Dockerfile`(server + ai/apps 한 이미지) · `Caddyfile` · `.dockerignore` ·
  `infra/README.md` 재작성(컴포즈 → `docker run` 두 줄). `infra/elasticsearch/Dockerfile` 은
  삭제돼 있어 복구했다 — nori 이미지를 굽는 유일한 파일이다.
- **`.env` 가 8월 25일자 MySQL 판이었다.** `MYSQL_*` 키를 `POSTGRES_*` 로 옮기고
  `POSTGRES_PORT` 를 **3306 → 5432** 로 고쳤다. 그대로 배포했으면 `/health` 가
  `postgres_configured: false` 를 **에러 없이** 뱉었을 것이다. `decisions/018` 이 코드는
  바꿨지만 각자의 `.env` 는 손댈 수 없었다 — 다른 사람 `.env` 도 같은 상태일 수 있다.
- **로컬에서 실제로 구워 확인했다**: 이미지 **362MB**(torch 를 안 넣어서다), `/docs` 200,
  `/health` 의 `spokes` 에 **`retrieval` 확인**. 이 한 줄이 「빌드 컨텍스트가 저장소 루트인가」를
  재는 지표다 — `server/` 만 넣으면 서버는 뜨는데 검색만 조용히 빠진다(`decisions/024`).
- **이미지 전달 경로는 지침서와 다르게 간다.** 지침서는 EC2 에서 굽고 `k3s ctr images import`
  로 반입하는데, 그건 이미지가 GB 급일 때 유리하다. 362MB 면 **Docker Hub 왕복이 싸고**
  EC2 를 새로 세워도 이미지가 남는다. 근거: `_project/decisions/107`.

  변경 통보**(`cd infra && docker compose up -d` 가 없어진다). 그리고 **GPU·EXAONE 을 이번
  배포에 넣을지** 는 정하지 못해 미결 항목에 걸었다 — 지금 코드에 GPU 경로가 없어서 11·14장을
