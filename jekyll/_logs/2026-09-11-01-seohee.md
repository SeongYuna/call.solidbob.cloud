- **`services/gateway`(Node.js/Express/ws)를 새로 만들었다** — 담당 경계상 정성윤
  몫(`_project/decisions/012`)이지만, 서버 운영자·백엔드 협조를 바로 받기 어려운
  상황에서 실제 폰으로 통화 테스트를 하며 개발을 진행하고 싶다는 요청으로
  `decisions/023`에 따라 진행했다. 근거·맥락은 `decisions/402`에 따로 남겼다.
- 처음엔 Twilio Media Streams + 서버 쪽 Google Cloud STT로 만들었으나, ① 지금은
  전화 사업자 계정을 만들 단계가 아니고 ② Google STT 자격증명은 원래 A-1/A-2 본체
  (류준·장민석 몫)라는 지적이 맞아서, **그 경로를 전부 지웠다**
  (`googleStt.js`·`sttBudget.js` 삭제, `@google-cloud/speech` 의존성 제거). 대신
  `GET /dev` 페이지가 브라우저 내장 Web Speech API로 그 자리에서 텍스트로 바꿔
  보낸다 — GCP 자격증명이 전혀 필요 없다. **품질 측정용이 아니라 "게이트웨이→hub→
  대시보드" 배선 확인용**으로 범위를 한정했다(정식 성능 수치는 여전히
  `ai/apps/evaluation/` 하네스만 쓴다).
- `apps/dashboard/src/lib/ws/types.ts`의 `gatewayUrl()`에 **런타임 오버라이드**를
  추가했다 — `?gateway=<wss URL>` 쿼리로 방문하면 `localStorage`에 저장돼 다음
  방문부터도 유지된다. Vercel 빌드타임 환경변수(`VITE_GATEWAY_WS_URL`)는 배포
  담당자 권한이 있어야 바꿀 수 있어서 필요했다.
- **개인 Vercel 계정**(`whtjgml2002-6071s-projects/call-solidbob-cloud`,
  `https://call-solidbob-cloud.vercel.app`)에 `vercel --prod` CLI로 직접 배포해
  확인했다 — `git push`가 아니라 CLI 배포라 main·팀 도메인(`call.solidbob.cloud`)은
  안 건드렸다.
- **세션 중 배포 백엔드(`server.solidbob.cloud`)의 "call 행 생성 경로 없음" 버그**
  (`STATE.md`에 이미 기록된 장민석 블로커)가 팀 쪽에서 고쳐진 걸 확인했다 —
  `POST /hub/calls`가 새로 생겼고, 순서를 안 지키면 409로 명확히 알려준다
  (`decisions/301`). 고쳐지기 전엔 새 통화 ID로 전사를 보내면 500이 났었다(재현·기록함).
- **엔드투엔드 실측 성공**: 로컬 게이트웨이(ngrok 터널) → 배포된 실제 백엔드
  → 개인 Vercel 대시보드까지, 실제 폰으로 "여보세요"라고 말해서 자막이 뜨는 것까지
  확인했다. `GET /hub/calls/{call_id}/transcript`로 조회해 DB에 실제로 영구
  저장된 것도 확인했다(`{"text":"오세요 여보세요", ...}`).
- 작업 중 실제로 겪은 것들: ① curl로 한글 텍스트를 쉘 변수 보간(`-d "..."`)으로 보내면
  인코딩이 깨져 400이 나고, 파일로 보내면(`--data-binary @file`) 정상 — 처음엔 이걸
  백엔드 버그로 오인했다. ② 리팩터링 중 `stop()`이 "stop" 메시지·ws close 양쪽에서
  두 번 불려 COST-1 사용량이 이중으로 쌓이는 버그를 만들었다가 직접 발견해 고쳤다
  (지금은 Twilio 경로 자체가 없어져 이 가드도 함께 지워짐).
- 남은 것: `/dev` 경로는 브라우저 STT 품질이라 정식 A-1/A-2(Twilio 등 실제 전화 연동)를
  대체하지 않는다 — 그건 여전히 미착수 상태다. 시연을 위한 영상 녹화 등은 사용자가
  나중에 직접 진행하기로 했다(이 세션에서는 안 함).
