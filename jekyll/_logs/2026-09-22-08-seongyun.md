  원인은 태그 번호 충돌 — #117 이 server 태그를 `0.1.27 → 0.1.28` 로 올렸는데, 그 뒤 #114(정성윤)가 **같은 `0.1.28`** 로 main 에 먼저 들어갔고,
  준님이 main 을 `ai` 에 받으면서 «서버 코드(DTO·스키마 주석)는 바뀌었는데 newTag 는 base 와 같은 0.1.28» 이 됐다.
  검사가 잡아야 할 조합을 정확히 잡은 것이다(같은 태그로 다시 구우면 노드가 캐시된 옛 이미지를 쓴다).

  `check_release_tags.py` ⑥이 다른 브랜치의 newTag 를 보고 경고하는 그 경우이고, «먼저 손댄 쪽이 산다»(§4)를 그대로 따랐다.
  `ai` 브랜치에 커밋 하나(`59403b7`, 준님 로그·PR 본문의 «0.1.28» 은 그 시점의 사실이라 로그는 안 고쳤고 PR 본문에만 정정 메모를 달았다),
  룰셋의 «최신 main 필수» 때문에 main 을 한 번 더 받아(`5a3d403`) 다섯 검사 통과 후 머지.
