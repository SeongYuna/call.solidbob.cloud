- **AWS 운영 인프라를 코드로 세웠다 — `terraform validate` 까지. 아직 `apply` 는 안 했다**
  ([w3-aws-deploy](/backlog/w3-aws-deploy/) 신규). 이 머신에 AWS 자격증명이 없어서
  `aws configure` 는 사용자 손이 필요하다. **안 된 것을 됐다고 적지 않는다** — 지금 서 있는 것은
  코드고, 실제로 뜬 리소스는 **0개**다. 도구도 새로 깔았다(Terraform 1.16.1 · AWS CLI 2.36.38,
  `sudo` 가 비밀번호를 요구해서 `~/.local` 에).
- **착수 전에 미결 하나를 닫았다 — 배포는 한 컨테이너, 도메인도 하나**(`_project/decisions/105`).
  **새 결정이 아니라 `024` 의 미반영분이다** — `024` 가 「검색 스포크를 같은 프로세스에서 꽂는다」를
  정한 순간 배포 단위는 이미 하나로 정해졌고, `CLAUDE.md` 의 두 도메인 서술이 그보다 낡아 있었을 뿐이다.
  문서 우선순위(결정 기록 > 기획서 > 파생 문서)를 그대로 적용했다. ⚠ **같은 건이 미결 항목에 두 번**
  올라와 있었다(08-27 에 나와 장민석 님이 각자 적었다) — 둘 다 닫고 중복이었다는 사실을 남겼다.
  고친 곳 5군데: `CLAUDE.md §3` · `docs/harness.md` · `README.md` · `docs/07` · `ai/CLAUDE.md`.
  **`ai/CLAUDE.md` 는 류준 님 영역이라 그 한 줄만 손대고 누가 왜 고쳤는지 파일에 적어 뒀다.**
  장민석 님이 [w3-retrieval-wiring](/backlog/w3-retrieval-wiring/)에 남긴 「정성윤 님 확인 대상」이
  이 건이다 — **남의 티켓이라 파일은 안 건드렸고 여기서 답한다: 한 컨테이너가 맞다.**
- **⚠ Elasticsearch 를 관리형으로 못 쓴다 — 이게 오늘 설계에서 제일 컸다.**
  Amazon OpenSearch Service 는 **ES 7.10 포크**라 `elasticsearch==9.5.0` 클라이언트가 안 붙는다.
  `decisions/020` 이 9.x 클라이언트로 8.15.3 서버에 붙여 보고 이미 받은 그 에러다
  (`media_type_header_exception`). **관리형을 포기해서 잃는 게 없다는 점이 다행이다** —
  nori 는 우리가 구운 이미지에 있고 RRF 는 basic 에서 막혀 어차피 `ai/` 코드가 계산한다(`decisions/021`).
  그래서 **EC2 에서 로컬과 같은 Dockerfile 로 굽는다** — 갈리면 형태소 분해 결과가 달라진다.
- **서버 이미지에 `ai/requirements.txt` 를 넣지 않기로 했다.** 거기엔 `torch`·`transformers` 가 있어
  이미지가 수 GB 가 되고 t3.medium 에 얹기 부담스럽다. 그런데 요청 경로가 `ai/` 에서 실제로 쓰는 것은
  `retrieval` 뿐이라, 그 트리의 서드파티 import 를 전수로 확인했다 — **`elasticsearch` 하나였다.**
  `server/requirements.txt` + `elasticsearch==9.5.0` 만 설치한다. ⚠ **버전이 두 곳에 손으로 적힌 상태가
  됐다**(`ai/requirements.txt` · Dockerfile). 어긋나면 붙지 않으므로 양쪽 주석에 서로를 적어 뒀다.
- **구성과 그 이유** — EC2 t3.medium 하나(caddy · server · elasticsearch) + RDS PostgreSQL 17.
  **RDS 를 나눈 이유는 백업 하나다** — 전사 데이터는 지우면 복구 경로가 없다.
  **NAT 게이트웨이는 두지 않았다**(월 $35 인데 사설 서브넷에 RDS 뿐이라 바깥에 나갈 일이 없다).
  **키페어 대신 SSM Session Manager** — 22 번을 아예 안 열고 키 파일도 안 돌아다닌다(SEC-2).
  ES·PostgreSQL 포트는 보안그룹에 **없다** — ES 는 `xpack.security` 를 끈 채로 도는 구성이라
  노출하면 인증 없는 검색 엔진을 인터넷에 여는 것이 된다.
- **비용은 월 ~$48, 종료(10-27)까지 ~$96** 으로 잡았다. 크레딧 범위 안이다.
  ⚠ **AWS 예산은 알리기만 하고 막지 않는다** — STT 쪽 COST-1 은 GCP 쿼터라는 **하드캡**이 1차에
  있었는데 **AWS 에는 그에 해당하는 게 없다.** 실제 상한은 인스턴스 등급을 작게 잡은 것 자체다.
  이 차이를 `infra/terraform/README.md` 에 적어 뒀다 — 같은 구조인 줄 알고 쓰면 안 된다.
- **곁들여 — `README.md` 가 아직 「도메인 4종」이었다.** `knowledge-base`·`golden-set` 두 줄이
  `decisions/201` 전환을 반영하지 않고 있었다(08-28 「머지 후 당일 처리」 목록에 있던 건).
  공개 첫 화면이라 함께 고쳤고, 빠져 있던 `infra/` 줄도 넣었다.
- **검증**: `terraform fmt` · `init` · `validate` 통과(provider aws 6.62.0 · random 3.9.0).
  `compose.prod.yml`·`docker-compose.yml` YAML 파싱 확인. 지킬 빌드 **95페이지 · 깨진 내부 링크 0건**.
  ⚠ **도커 빌드는 못 돌렸다** — 이 머신에 도커 데몬이 없다. Dockerfile 은 아직 «작성했다» 까지다.
- **남은 것**: ① `aws configure --profile callguard` 후 `terraform apply`(RDS 때문에 10분쯤)
  ② 클라우드플레어 `server` A 레코드(**프록시 끄고** — 켜면 Let's Encrypt HTTP-01 이 막힌다) ·
