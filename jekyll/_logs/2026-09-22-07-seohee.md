- `apps/call`·`apps/admin` 둘 다 `temperature_outliers`가 `null`(미측정)일 때 "0건"으로
  잘못 표시되던 것을 고쳤다. 서버 스키마(`server/apps/hub/adapter/inbound/api/schemas/
  blacklist_request_create_schema.py:26`)를 확인해보니 `StrField | None`이고
  "null 은 「미측정」 — 0(이상 없음)과 다르다(decisions/316)"라고 이미 명시돼 있었다.
- grep으로 두 앱 전체에서 찾은 사용처(파서·타입·렌더):
  - `apps/call/src/types/contract.ts:365`(`BlacklistEvidence.temperature_outliers`) — 타입이
    `number`라 애초에 null을 담을 자리가 없었음.
  - `apps/call/src/lib/api/coreClient.ts:268,301` — wire 타입이 `string`(실제로는
    `string | null`이 옴), `toEvidence()`가 `toNum(wire.temperature_outliers)`로 무조건
    변환 — `Number(null) === 0`이라 조용히 0이 됐다(원인).
  - `apps/call/src/lib/blacklist/collectEvidence.ts:32,42` — 로컬에서 근거를 모을 때도
    `options.temperatureOutliers ?? 0`으로 기본값 0. 이쪽은 서버 null이 아니라 "아직
    실시간으로 재는 신호가 없어서 옵션을 아무도 안 넘긴다"는 다른 경로지만 결과적으로
    "미측정"이 "0건"으로 보이는 같은 문제라 같이 고쳤다.
  - `apps/call/src/components/BlacklistRequestButton.tsx:108` — 렌더 지점. 이 화면(요청
    작성 전 미리보기)은 `collectEvidence`가 만든 로컬 값만 보여준다 — 서버가 보낸
    `BlacklistRequestItem.evidence`(널 가능)를 렌더하는 곳은 apps/call에 따로 없었다
    (스토어엔 쌓이지만 `alreadyRequested` 판정에만 쓰이고 화면엔 안 나감).
  - `apps/admin/src/types/blacklist.ts:24` — 위와 동일한 타입 문제.
  - `apps/admin/src/lib/api/hubClient.ts:94,133` — 위와 동일한 `toNum` 문제.
  - `apps/admin/src/components/admin/RequestsTab.tsx:123` — 렌더 지점(관리자 승인요청창,
    실제 서버 값을 보여주는 쪽 — 여기가 진짜 버그가 드러나는 화면).
  - `apps/admin/src/mock/adminFixtures.ts:25`는 고정값 `3`이라 영향 없음(수정 안 함).
- 고친 내용(두 앱 동일 패턴, 공유 유틸 새로 안 만듦 — 각 앱에 지역적으로):
  1. 타입을 `number` → `number | null`로 넓혔다.
  2. wire 타입을 `string` → `string | null`로 넓히고, 변환을 `toNum(...)`에서
     `wire.temperature_outliers === null ? null : toNum(...)`로 바꿨다 — `apps/call`의
     `fetchCallRecord`가 `similarity_score`에 이미 쓰던 관용구를 그대로 재사용.
  3. `collectEvidence.ts`의 `?? 0`을 `?? null`로 바꿨다(apps/call만 해당 — admin엔 이런
     로컬 조립 코드가 없다).
  4. 두 렌더 지점 모두 `value === null ? "미측정" : `${value}건`` 조건부 표시로 바꿨다.
  - API 계약(요청 바디)이나 페칭 로직 자체는 건드리지 않았다 — 표시 단계 한정.
- 빌드 확인: `cd apps/call && npm run build`, `cd apps/admin && npm run build` 둘 다
  (`tsc --noEmit && vite build`) 통과. 새 테스트 프레임워크 도입 없음(둘 다 아직 러너 없음).
