- **운영 DB 가 옛 스키마인 채로 새 코드가 배포돼 있었다 — 순서가 뒤집혔다.** 런북 19장은
  「**이미지를 올리기 전에** 스키마를 넣는다」고 적어 뒀는데, PR #79 가 머지되면서 `release.yml` 이
  자동으로 돌아 **server `0.1.5` 가 06:33 에 배포**됐다(plan·image·gateway-image·deploy 전부 success).
  운영 DB 는 그때 **22 테이블 = `fd96adc`(09-09) 상태**였다. **사람이 끼어들 지점이 없는 구조다** —
  머지가 곧 배포라서, 스키마를 먼저 넣으라는 문장이 있어도 지킬 자리가 없었다.
- **테이블 수는 AWS 에 붙은 다른 세션이 확인했다**(22개, RDS 정상). 이 머신에서는 못 잰다 —
  `kubectl` 이 없고(`~/.kube/config` 는 로컬 k3s 를 가리킨다) AWS 자격증명도 없다(`sts get-caller-identity` → `NoCredentials`).
  SSH 키는 `~/.ssh/` 에 있으나 `callguard-key.pem`+`ubuntu` 는 거부됐다. ⚠ **런북 8장은 키 이름을
  `assist-key.pem` 으로 적고 있는데 그런 파일이 없다** — 09-14 에 고친 IAM 역할·S3 버킷 이름과 같은 부류의 어긋남이다.
- **무엇이 깨지고 있었는지 코드로 짚었다**(추정이 아니라 파일·줄 기준).
  - `POST /hub/calls` 에 **발신 번호가 있을 때만** 500 — `hmac_customer_ref_adapter.py:39` 가
    `hexdigest()` 로 **64자**를 만드는데 옛 `customer.customer_id` 는 `VARCHAR(40)` 이라 `22001 value too long`.
  - F-2 필요서류 판정 저장 500 — 옛 `closure` 는 처리유형 4종 + BOOLEAN 10개 모양이라 `procedure`·`verdict`·`closure_item` 이 없다.
  - 관리자 로그인 500 — `admin_account` 테이블 자체가 없다(`42P01`).
  - **전사·마스킹·검색·콜 가드 저장은 정상이었다** — `call_guard_flag`·`voice_outlier` 는 `fd96adc` 에 이미 있다.
- ⚠ **`/health` 는 이 상태에서도 `ok` 였다.** `0.1.5` 기대 출력(`spokes` 5종)과 정확히 일치했다.
  **배포 판정으로는 안 드러난다** — 눌러 봐야 안다. `w4-admin-auth-runtime` 이 적어 둔 것과 같은 모양이 또 났다.
- **`fd96adc` → 현재 `schema.sql` 차이는 순증이다** — 없어지는 테이블이 없고 `admin_account`·
  `admin_refresh_token`·`closure_item` 셋이 는다(+ `closure` 재정의, `customer_id` 40→64).
  블랙리스트 테이블은 이미 운영에 있었다.
- **파일을 인스턴스로 옮기는 경로는 `curl` 이다 — 인스턴스에 git 도 저장소 사본도 없다**
  (`converge.sh` 주석: 「인스턴스에 git 이 없고(2026-09-09 확인) 깔 이유도 없다」). 있는 것은 렌더된
  매니페스트 캐시 `/opt/callguard/current.yaml` 뿐이다. 저장소가 공개라 raw URL 로 받는다.
  **무결성을 대조했다** — 로컬 작업본 · `origin/main` 의 blob · raw URL 셋의 sha256 이
  `a915193774c6ef9a4b73dab927425c6e83a1c68c6326766a373a949447998422` 로 같다.
- **적용 명령은 런북 17장 패턴에서 `autocommit=True` 하나를 바꿨다.** 이 마이그레이션은 자체
  `BEGIN;`/`COMMIT;` 을 갖고 있어서, psycopg 가 트랜잭션을 또 열면 중첩된다. autocommit 으로 두면
  파일의 트랜잭션이 그대로 살아 **중간에 실패하면 아무것도 안 바뀐다.**
- **적용·`CUSTOMER_REF_HMAC_KEY` 주입은 인스턴스 쪽 세션에서 끝냈다(사용자 수행).**
  ⚠ **적용 후 테이블 수 확인 출력은 이 세션에 들어오지 않았다** — 「25 테이블 · 셋 다 존재」를
  내가 본 것이 아니므로 측정값으로 인용하지 않는다(절대 원칙 2·10). 다음 세션이 런북 19-6 으로 찍어 남긴다.
- 남은 것:
  - **`admin_account` 행 삽입 + `agent_id`** — 비어 있으면 블랙리스트 승인·해제가 409 다. 회원가입 화면이 없어 SQL 로 넣는다.
  - **`.env.example` 에 `CUSTOMER_REF_HMAC_KEY`** — 자격증명 보호 훅이 이 파일 편집을 막아 사람이 넣는다(키 이름만).
  - ⚠ **구조를 안 고치면 또 난다.** 「머지 = 배포」인데 스키마는 사람 손이라 항상 뒤따라간다.
