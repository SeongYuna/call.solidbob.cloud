- **훅이 조용히 죽어 있었다 — 윈도 머신에서 원인을 찾아 고쳤다.** 증상은 Bash 를 쓸 때마다 뜨던
  `PreToolUse:Bash hook error / Failed with non-blocking status code: Python`.
  - **원인 ①: 이 머신에 파이썬이 아예 없었다.** `python3` 가 `…\WindowsApps\python3.exe`(0바이트 앱 실행 별칭)
    → `AppInstallerPythonRedirector.exe`(마이크로소프트 스토어로 보내는 미끼)로 풀렸다.
    그 미끼가 **stderr 에 `Python ` 을 찍고 종료 코드 49** 로 죽는다 — 화면의 「status code: Python」이 바로 그 문자열이다
  - **그래서 `.claude/settings.json` 의 훅 둘이 통째로 무력했다** — 런북 가드(PreToolUse)가 배포 파일을 막지 못하고,
    **`Stop` 훅(`check_session_end.py`)이 돌지 않아 진행 기록 누락도 안 잡혔다**(exit 2 를 낼 주체가 없었다)
  - **고침**: `winget install --id Python.Python.3.13` (3.13.15, `%LOCALAPPDATA%\Programs\Python\Python313`).
    ⚠ **설치판은 `python3.exe` 를 안 만든다** — 훅이 `python3` 를 부르므로 `python.exe` 를 복사해 만들었다.
    저장된 사용자 PATH 는 Python313 이 WindowsApps 보다 **앞**(인덱스 1 vs 3)이라 미끼는 가려진다
  - **원인 ②(설치만으로는 안 풀리는 것): 콘솔 인코딩.** 윈도 파이썬의 stdout 기본이 **cp949** 라
    `check_session_end.py` 가 할 말이 있을 때 찍는 머리말 `세션 종료 검사 — CLAUDE.md §0.5` 의
    **`—`(U+2014)에서 `UnicodeEncodeError`** 로 죽는다(실측). 즉 **경고·차단이 필요한 바로 그 순간에만 터진다.**
    가드 쪽은 stderr(`backslashreplace`)라 죽지는 않지만 한글이 전부 깨져 읽을 수 없었다
  - **고침**: `.claude/settings.json` 의 훅 명령 둘을 `python3 -X utf8 …` 로. **맥에서는 무동작**이라 팀에 영향 없다.
    고친 명령 그대로 재현 확인 — 가드가 차단 상황에서 **한글 그대로 exit 2**, 세션 종료 검사 「통과」 exit 0
  - ⚠ **이 세션에는 아직 안 먹는다** — 지금 도는 Claude Code 프로세스가 설치 전 PATH 를 물고 있다. **재시작해야 적용된다**
- 루비(지킬)는 여전히 없다 — 사이트 빌드 검증은 이 머신에서 못 한다
