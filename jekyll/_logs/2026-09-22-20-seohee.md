- `main`을 다시 확인하는 과정에서 **J-5(배정 판정)가 이미 장민석 님 손으로 실제
  구현·운영 배포까지 끝나 있는 것을 발견했다**(call-mediator `0.2.5`, 운영
  `0.1.35`, PR #131) — 제가 오늘 만들었다가 롤백한 직후 넘겨받아 처리한 것으로
  보인다. 새 결정 `decisions/320`도 확인 — 313을 철회하지 않고 "완성본 호출자는
  교환기, 시연에서만 콜 미디에이터가 대리"로 313·126을 조정한, 제 `407`보다
  더 정교한 결론이었다(독립적으로 같은 방향에 도달).
- 화면에 뜨는지 재확인 결과 **여전히 어디에도 안 뜬다**는 것을 재검증했다 — WS
  실시간 방송 없음(백엔드에 `routing_decision` 메시지 타입 자체가 없음),
  상담기록 상세에 필드 없음, 별도 조회 API 없음. **다만 현황판(admin-stats)
  집계 수치만은 예외**였다 — 서버가 `routing_decisions`·`routing_blacklisted`·
  `routing_fell_back`을 이미 주고 있었고 `hubClient.ts`가 파싱까지 했는데,
  `adminStore.ts`·`WallboardTab.tsx`가 그 값을 저장·렌더하지 않고 버리고
  있었다(지난 현황판 연결 작업 때 "렌더하지 마라"는 지시를 따른 결과 — J-5가
  그때는 미구현이라 전부 0일 게 뻔해서였는데, 이제 실제 값이 쌓인다).
- **이 부분만 순수 프론트 작업이라 장민석 님을 기다리지 않고 바로 고쳤다** —
  나머지(WS 배너·상담기록·조회 API)는 여전히 백엔드 작업이 먼저 필요해 손대지
  않았다.
- `adminStore.ts`: `statsRoutingDecisions`·`statsRoutingBlacklisted`·
  `statsRoutingFellBack` 상태 추가, `loadAll`에서 `fetchAdminStats` 결과로 채움
  (API 호출은 이미 있었고 값만 새로 저장).
- `AdminPanel.tsx`: 위 세 값을 읽어 `WallboardTab`에 새 props로 전달.
- `WallboardTab.tsx`: 기존 4지표 도넛 아래에 **별도 섹션**("배정 판정(J-5)")을
  추가 — 기존 `wallboard-grid`·`wallboard-tile` 클래스를 그대로 재사용, 새
  CSS 없음. 도넛에는 안 섞었다 — "새 지표를 만들지 않는다"는 약속은 그 도넛
  하나에 한정된 것이고, J-5는 그날 처음 값이 쌓이기 시작한 별개 기능이라
  성격이 다르다고 판단. 전체 판정 0건이면 "아직 판정된 통화가 없습니다"로
  정직한 빈 상태, 블랙리스트 판정 건수는 0보다 크면 강조(`is-watch`) 표시.
