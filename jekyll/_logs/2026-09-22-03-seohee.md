- `apps/call/src/lib/api/coreClient.ts`의 `closeCall`(`POST /hub/calls/{id}/close`)이
  다른 인증 필요 호출(`confirmSummary`·`reviseSummary`)과 달리 `Authorization` 헤더를
  안 싣고 있던 것을 맞췄다. 서버가 아직 이 헤더를 검증하지 않아 지금 당장 동작이
  바뀌진 않지만, 나중에 검증이 붙을 때를 대비해 기존 패턴(`readAgentToken()` → 없으면
  `CoreApiError` → 있으면 `Bearer` 헤더)을 그대로 재사용했다.
- `RealGatewayClient.wrapUp()`(`lib/ws/realCallMediatorClient.ts:94`)이 `closeCall`을
  그대로 호출하는 것을 확인했다 — 별도로 `/hub/calls/{id}/close`를 직접 부르는 코드는
  없다.
- `coreClient.ts` 안에서 `Authorization`을 안 싣는 나머지 호출 목록(수정 안 함, 확인만):
  - `fetchCallList` — `GET /hub/calls` (읽기)
  - `fetchCallTranscript` — `GET /hub/calls/{id}/transcript` (읽기)
  - `searchDocuments` — `POST /hub/search` (쓰기 메서드지만 상태를 바꾸지 않는 조회)
  - `submitCardFeedback` — `POST /hub/cards/{card_id}/feedback` (쓰기)
  - `fetchCallRecord` — `GET /hub/calls/{id}/record` (읽기)
  - (`fetchAgentMe`는 토큰을 인자로 받아 이미 싣는다 — 제외)
- 빌드 확인: `cd apps/call && npm run build` (`tsc --noEmit && vite build`) 통과.
- 남은 것: 위 목록에 헤더를 붙일지는 이번 작업 범위 밖 — 다음 세션에서 필요하면 논의.
