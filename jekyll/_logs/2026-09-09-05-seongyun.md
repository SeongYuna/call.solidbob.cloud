- **파이프라인이 실제로 배포까지 끝냈다. 원인은 OIDC `sub` 형식이었다.**
  진단 단계가 찍은 값 —

  ```
  GitHub:    repo:SeongYuna@280208914/call.solidbob.cloud@1344602683:ref:refs/heads/main
  신뢰 정책:  repo:SeongYuna/call.solidbob.cloud:ref:refs/heads/main
  ```

  **계정·저장소의 불변 숫자 ID 가 이름 뒤에 붙어서 온다.** GitHub 의 「주체 클레임에 불변 ID
  포함」 형식이다. 이름만으로 매칭하는 정책과는 안 맞는다. 신뢰 정책의 `sub` 를 ID 형식으로
  고치니 바로 통과했다. **이 형식이 오히려 안전하다** — 저장소를 개명해도 정책이 유지되고,
  같은 이름의 다른 저장소는 ID 가 달라 통과하지 못한다.
- **⚠ 진단 없이 세 번 헛짚었다.** ① 「공급자가 없을 것」(있었다) ② 「Secret 오타」(일치했다)
  ③ 「Secret 재생성」(변화 없음). AWS 쪽 네 가지를 전부 검증하고도 못 찾았는데,
  **어긋난 쪽이 GitHub 이 보내는 값이라 AWS 를 아무리 봐도 안 보였다.**
  실제 값을 찍는 데 드는 비용이 추측보다 훨씬 쌌다.
- **배포가 코드를 실제로 실어 날랐다는 증거** — `/openapi.json` 의 `CardSchema` 가
  `score` → `similarity_score` 로 바뀌었다. 함께 실린 것: `95d930f`(계약 수정) ·
  `dd63ffd`(CORS 개방). 사람이 손댄 것은 `newTag` 한 줄뿐이다.
- **`plan` 의 안전장치도 실제로 작동했다.** 장민석 님 CORS 머지 때 *"코드가 바뀌었는데
  newTag 가 0.1.0 그대로"* 로 막았다. 없었으면 배포가 성공한 것처럼 보이면서 캐시된 옛
  이미지가 계속 돌았을 것이다(`imagePullPolicy: IfNotPresent`).
- **진단 단계는 목적을 다해 제거했다.** 워크플로는 `plan → image → deploy → smoke → rollback` 만 남는다.
- **브랜치 정렬**: `PM`·`ai`·`server` 를 main 으로 맞췄다. **`frontend` 는 손대지 않았다** —
  조서희 님의 미머지 커밋(`bcf00d2`, 진행 기록)이 하나 있어 강제로 밀면 사라진다.

  `psycopg` 의 async 모드가 Windows 기본 `ProactorEventLoop` 를 거부한다(코드 확인:
  `connection.py:56` 이 `AsyncConnection`, 저장소에 이벤트 루프 정책 설정 0건).

  `VITE_CORE_API_URL` 로 붙으면 지금 바로 풀린다(CORS 가 열려 있다).
