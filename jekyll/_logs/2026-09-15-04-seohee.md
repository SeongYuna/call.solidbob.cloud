- **장민석이 `frontend`↔`server` 병합 대조에서 남긴 프론트 수정 5건을 처리**
  (`jekyll/open-items.markdown` "조서희 님께 — `frontend` 병합분 대조에서 나온 프론트 수정
  5건" 항목).
  1. **블랙리스트 요청 계약 변경**(`decisions/307`) — `POST /hub/blacklist-requests`가 이제
     상담원 토큰(`Authorization: Bearer cga_…`)을 요구하고 `requested_by` 본문 필드는
     빠졌다. `apps/call/src/lib/agentToken.ts` 신규 — `apps/platform`의 `liveCallToken.ts`와
     같은 패턴으로 `?agent_token=` URL 쿼리 한 번 → sessionStorage, 화면에 입력창은 두지
     않았다. `coreClient.ts`의 `createBlacklistRequest`가 토큰을 헤더로 붙이고, 토큰이
     없으면 서버를 부르지 않고 바로 에러를 던진다.
  2. **카드 피드백 `card_id` 타입** — `decisions/308`로 카드에 `card_id`가 생겼지만 문자열
     (StrField)이다. `submitCardFeedback`(number 기대)·`RecommendationCard`
     (`types/contract.ts`)·`realGatewayClient.ts`의 `parseCard`를 전부 문자열로 정정.
  3. **만료 상한 불일치** — 관리자 UI는 24개월까지 허용하는데 서버 상한은 365일(~12개월)
     이라 13개월 이상 승인·연장은 422. `RequestsTab.tsx`·`EntriesTab.tsx`·`SettingsTab.tsx`
     세 곳의 `max`를 24→12로 낮췄다.
  4. **새 엔드포인트** — `POST /hub/blacklist-entries/{id}/expiry`(연장·단축, 사유 필수,
     `decisions/309`)를 `hubClient.ts`에 추가하고 `adminStore.ts`의 `extendEntry`를 로컬
     날짜계산 mock에서 실호출로 교체. `SettingsTab.tsx`에 상담원 토큰 발급 UI(`/admin/
     agent-tokens` 발급·목록·폐기, 원문 1회 노출+복사)도 새로 만들었다. **`GET /hub/calls/
     {id}/record`(상담기록 재생)는 이번 스코프에서 뺐다** — mock 시나리오 재생(카드·종결·
     감정분석 통짜)을 실제 API 조합으로 바꾸려면 화면 흐름 재설계가 필요해서다.
  5. **해제 사유 하드코딩** — `AdminPanel.tsx`의 해제 액션이 항상 `"관리자 해제"`를
     보내던 것을, `EntriesTab.tsx`에 실제 사유 입력창을 추가하고(연장·해제 공용, 비어
     있으면 두 버튼 다 비활성) 실제 값을 넘기도록 고쳤다.
- `apps/call`·`apps/admin` 둘 다 `tsc --noEmit`·`vite build` 클린 확인.
- `jekyll/open-items.markdown`의 관련 항목들(위 5건 + 카드 피드백 계약 구멍 + 만료
  연장 API 항목)을 완료 표시하고 "무엇을 어떻게 처리했는지"를 이어 적었다 — 서버 쪽
  기록(장민석)은 그대로 두고 프론트 쪽 처리 결과만 덧붙였다.
- 남은 것: `fetchCallList` 주석의 낡은 "`customer_id` 늘 null" 서술(사소, 안 고침),
  `GET /hub/calls/{id}/record` 상담기록 재생 화면 연결(재설계 필요), `GET .../expiry-changes`
  연장 이력 화면(요청 없어 보류).
