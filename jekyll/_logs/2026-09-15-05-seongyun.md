- **관리자 로그인이 운영에서 실제로 됐다 — 구글 로그인 → 관리자 화면 진입까지 완주했다.**
  기록 04 에서 저장소 쪽을 닫았고(PR #89), 여기서는 값·계정 작업을 끝냈다. 세 갈래를 함께 열었다 —
  화면(`admin.solidbob.cloud`) · OAuth · 세션 Redis. 근거 `decisions/112`, 절차는 런북 **18-3** 에 남겼다.
- **PR #89 는 검사 5종 전부 통과했고, `tag-check` 가 예측대로 초록이었다** — 이미지 태그를 안 올렸는데
  통과한 것이 「`infra/k8s/**` 는 이미지 판정 경로가 아니다」의 확인이다. 릴리스도 `image`·`gateway-image`
  **skipped** · `k3s-deploy` success 로 돌아 매니페스트만 적용됐다.
- **머지 배포는 서버 파드를 재시작하지 않는다 — 여기서 한 번 걸렸다.** 시크릿을 patch 하고 릴리스가
  성공했는데도 CORS 프리플라이트가 계속 400 이었다. Deployment 스펙이 안 바뀌면 `kubectl apply` 가
  no-op 이고, **시크릿은 파드가 뜰 때만 읽힌다.** `rollout restart` 뒤 200 으로 바뀌었다.
  런북 18-3 에 이 문장을 굵게 남겼다.
- **CORS 는 덮지 않고 덧붙였다.** 기존 값이 `https://call.solidbob.cloud` 하나뿐이라
  `,https://admin.solidbob.cloud` 를 붙였다. 실측 — admin 오리진 **400 → 200 + allow-origin 에코**,
  `call` 오리진은 200 그대로, 모르는 오리진(`evil.example`)은 여전히 400. **상담원 화면이 안 깨진 것까지 봤다.**
- **`CORS_ALLOWED_ORIGINS` 는 `server-env` 안의 키라 patch 가 한 번이다.** 사용자가 짚어 줘서 알았다 —
  내가 목록에 「키 3종」과 「CORS」를 따로 적어 두 작업처럼 보이게 했었다. 게이트웨이에도 같은 이름의 키가
  있지만 **별개 값**이고(매니페스트에 평문), 관리자 화면은 게이트웨이에 붙지 않아 건드리지 않았다.
- **RDS 테이블은 이미 있었다 — 내 첫 절차가 틀렸다.** 17-4 를 처음엔 `admin_account`·`admin_refresh_token`
  DDL 로 썼는데, 작업 중 main 을 받아 보니 `db/migrations/2026-09-14-…sql` 이 이미 만들어 뒀고
  09-15 확인(26 테이블 일치)까지 돼 있었다. 그대로 돌렸으면 **이미 있는 테이블에 CREATE 를 걸어 실패**한다.
  17-4 를 「확인 + 허용 목록 행 1건」으로 좁히고, 「스키마 변경은 `db/migrations/` 에 파일을 더한다」를 남겼다.
- **Vercel 세 번째 프로젝트 — 번들에 값이 박혔는지 직접 봤다.** `VITE_` 는 빌드 때 문자열로 들어가므로
  Import 화면에서 환경변수를 먼저 넣었다. 확인은 배포된 번들을 받아서 했다:
  `/assets/index-2GxCi4n7.js` 안에 `server.solidbob.cloud` 와 클라이언트 ID 가 둘 다 있다.
- **Deployment Protection 은 켜지 않기로 했다 — 판단이 바뀌었다.** 처음 「잠그고 올리자」고 한 이유는
  **로그인이 100% 실패하는 상태**였기 때문인데, 백엔드가 붙어 진짜 관문이 살아났다. 남는 노출은 번들의
  UI 구조와 mock 시드뿐이고 시드는 전부 합성이다(`req-seed-1`·`hmac_seed_1`·`****3841` — 실제 개인정보 0건).
  Hobby 플랜이라 Production 보호가 제약되는 것도 겹친다. 판단 근거를 티켓에 적었다.
- **런북 18-3 은 «완주한 뒤에» 넣었다.** 구글 콘솔·Vercel 절차는 미검증 상태로 정본에 넣지 않았다 —
  17-3 이 "운영에서 아직 돌리지 않았다"를 달아둔 것과 같은 이유다. 증상→원인 표(7행)도 함께 넣었는데,
  이 작업에서 실제로 겪은 것들이다(재시작 누락 · CORS · 재배포 필요).
- **`seed_documents.py` 를 운영 RDS 에 돌렸다 — `document` 0행 → 98행.** 09-14 에 확인했을 때는 스크립트가
  `ai` 브랜치에만 있어 못 했는데 그 뒤 main 에 들어왔다. 안 돌리면 **에러가 아니라 조용히 NULL 이 된다** —
  `call_guard_flag_repository.py:25` 가 `(SELECT document_id FROM document WHERE document_id = %s)` 로
  **있을 때만 잇고 없으면 NULL** 을 넣는다(그대로 넣으면 FK 23503 으로 탐지 기록이 통째로 사라져서 그렇게 막아 뒀다).
  화면·API 응답에는 근거 조항이 실리므로 **멀쩡해 보이고 DB 만 비어 간다.**
  돌리기 전 이미 쌓인 것은 1건뿐이었고(그 1건은 NULL 로 남는다 — 소급하지 않는다), 더 쌓이기 전에 닫았다.
  런북 17-3 의 「운영에서 아직 돌리지 않았다」를 실측 결과로 바꿨다.
- 남은 것: **`admin_account.agent_id` 가 NULL** 이라 블랙리스트 승인·해제가 409 다. 일부러 비워 둔 자리이지
  빠뜨린 값이 아니다(`decisions/304`) — 어느 상담원 마스터 ID 로 기록할지 [미결](/open-items/)에 선택지 셋으로 적었다.
  화면 데이터도 아직 mock 시드다(로그인만 실동작).
