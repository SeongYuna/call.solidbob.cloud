- **게이트웨이에 남아 있던 미결 넷을 마무리했다** — `services/gateway` 본체(A-1~A-4)는 09-11 에 이미 완료·배포된 상태였고, 그 뒤 [미결](/open-items/)에 남은 것을 사용자와 골라 한 브랜치(`server`)에서 `server/`·`ai/`·`services/gateway/` 를 같이 고쳤다(`decisions/302`).
  - **트리거 발동 시각 = 게이트웨이 도착 시각** ([w4-trigger-arrival-time](/backlog/w4-trigger-arrival-time/)) — 게이트웨이가 STT final 을 받은 시각을 `received_at_ms`(통화 기준 ms)로 추천 요청에 싣고, `TranscriptEvent` → `IsFinalTrigger` 가 그 값을 쓴다. 없으면 기존 «발화 종료 + 346ms» 모형. 08-27 부터 열려 있던 «트리거 지연을 잴 수 없다» 가 **실시간 경로에서는** 풀렸다. **평가 하네스는 여전히 측정 불가**다 — 골든셋에 도착 시각이 없다(절대 원칙 10). 실제 통화로 분포를 뽑아 본 적은 아직 없다
  - **ES 연결 실패 500 → 503** ([w4-es-unreachable-503](/backlog/w4-es-unreachable-503/)) — `ConnectionError`·`ConnectionTimeout`. 예외 메시지에 ES 주소가 들어 있어 본문에 싣지 않는다(SEC-2, 테스트로 고정)
  - **「검색 중」 신호 + 통화 시작을 §7.3 에** ([w4-recommendation-pending-contract](/backlog/w4-recommendation-pending-contract/)) — `plan.md` §7.3 에 통화 시작·`received_at_ms`·`recommendation_pending` 을 올렸다. 게이트웨이에 전송 코드를 넣었지만 **꺼 뒀다** — `apps/call` 실서버 파서가 모르는 `type` 에 오류 배너를 띄워 켜면 라이브 화면이 깨진다. `apps/` 는 조서희 님 전담이라 고치지 않고 요청을 미결에 남겼다(사용자 선택)
  - **모노 녹음 화자 분리 `speaker=auto`** ([w4-gateway-mono-diarization](/backlog/w4-gateway-mono-diarization/), `decisions/303`) — 구글 화자 분리(2명)를 켜고 final 을 라벨마다 잘라 **먼저 말한 화자 = 상담원**으로 보낸다(사용자 선택). 추측이라 기본값이 아니고 통화 기록 엔진이 `google-stt+diarize`. 구글이 응답마다 처음부터의 단어를 다시 보내므로 단어 끝 시각 워터마크로 거른다. interim 은 라벨이 없어 보내지 않는다
- **확인한 것**: gateway `typecheck` + 테스트 92 통과(79 → 92) · server `pytest` 327 통과 / 7 스킵 · `lint-imports` 4 계약 유지 · ai `pytest` 194 통과 / 13 스킵 · 3 계약 유지. 이미지 태그 server `0.1.3`→`0.1.4` · gateway `0.1.1`→`0.1.2`(`src/` 를 고쳐 안 올리면 릴리스가 실패한다)
- **확인하지 못한 것**: ⚠ **`speaker=auto` 를 실제 구글 응답으로 돌려 보지 않았다** — 이 머신에 STT 키도 AI Hub 음성도 없다. 테스트는 `cloud_speech.proto` 주석에 적힌 응답 모양을 흉내 낸 가짜 위에서만 돈다. `ko-KR` 이 스트리밍 화자 분리를 거절할 가능성도 열려 있다
- 남은 것: 조서희 님 `recommendation_pending` 수신 → `announcePending` 켜기 · 키 있는 머신에서 `stream_wav.ts --speaker auto` 실측 · main 의 관리자 로그인 머지가 서버 태그를 안 올린 것(이번 PR 의 0.1.4 로 같이 풀린다) — 전부 [미결](/open-items/) 「게이트웨이 마무리에서 남은 것」
