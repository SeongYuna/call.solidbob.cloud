- 합성 통화 재생기(mock 시나리오 재생)를 볼 때 `AgentCallBox`의 "통화받기" 모달이
  자막을 덮던 문제를 조사 후 고쳤다.
- 조사: `AgentCallBox`는 `App.tsx:113-134`에서 `shell !== "standby"`이고
  `showSummary`가 아니면 **`viewMode`·`mode`와 무관하게 무조건** 렌더됐다. 컴포넌트
  자체는 `status`(`useAgentCallSession`)가 `"idle"`이거나 `"ended"`일 때 백드롭
  모달을 그리는데(`AgentCallBox.tsx:34-36`), `status` 초기값이 항상 `"idle"`이라
  "assist" 셸에 들어가는 순간부터 이미 조건을 만족한다.
- mock 재생 판단: 새 상태를 만들기 전에 기존 `mode`로 충분한지 먼저 확인했다.
  `replay()`(`hooks/useCallMediatorSession.ts:127-133`)는 `client.mode !== "mock"`이면
  아예 실행되지 않아 — "합성 통화 재생"은 정의상 `mode === "mock"`인 경우로 한정된다.
  실제·mock 클라이언트 둘 다 `connect()` 진입 즉시(동기) `onStatus`로 자기 모드를
  알리므로(`realCallMediatorClient.ts:38`, `mock/mockCallMediator.ts:41`),
  `AgentCallBox`가 렌더되는 시점엔 `mode`가 이미 정확하다 — 스토어 초기값
  `mode:"mock"`(`callStore.ts:405`)이 남아 있을 수 있는 대기화면에서는 애초에 이
  컴포넌트가 안 뜬다. **새 플래그 없이 `mode`로 판단 가능해서 그대로 썼다.**
- 수정: `App.tsx`에 `mode = useCallStore((s) => s.mode)`를 추가하고,
  `<AgentCallBox session={agentCall} />` 렌더를 `mode === "live"`일 때만 하도록
  감쌌다 — 재생 중(`mode === "mock"`)엔 모달을 아예 렌더하지 않는다(최소화 형태가
  아니라 완전 생략을 골랐다 — 재생 중엔 실제로 받을 전화가 없어 기능 자체가
  의미 없기 때문). 실제 라이브 통화(`mode === "live"`) 동작은 그대로다.
- 빌드 확인: `cd apps/call && npm run build`(`tsc --noEmit && vite build`) 통과.
  새 테스트 프레임워크 도입 없음.
