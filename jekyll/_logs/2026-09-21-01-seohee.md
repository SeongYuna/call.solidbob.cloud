- **상담원 토큰 발급 화면에서 이름을 치면 404가 나는 문제를 고쳤다.** `agent` 테이블에
  상담원을 만드는 화면·API가 애초에 없어(테스트 단계) `GET /admin/agents`가 항상 빈
  목록을 돌려줬고, 화면이 "agent.agent_id 직접 입력" 칸으로 빠졌다. 거기에 상담원 이름
  ("최효원")을 치면 서버가 그걸 `agent_id`로 해석해 FK 위반 404("상담원이 없습니다:
  최효원")가 났다 — 캡처로 지적받아 확인.
- 발급 대상을 **이름으로만** 받도록 바꿨다 — 서버(`IssueAgentTokenInteractor` +
  `AgentDirectoryPort.resolve_or_create`)가 같은 이름의 상담원을 찾아 쓰거나, 없으면
  그 자리에서 새로 만든다. `apps/admin` 화면은 입력창 하나(이름)로 단순화하고, 상담원
  목록이 있으면 `<datalist>`로 자동완성만 거든다. 근거·남는 것: `_project/decisions/406`.
- `server/apps/agent_auth` 유닛 테스트 24건(신규 3건 포함) 통과 확인. Postgres 통합
  테스트(`test_agent_directory_repository.py`)는 새로 추가했지만 로컬에 DB가 없어
  미실행 — 다음에 `CALLGUARD_TEST_DATABASE_URL`로 돌려서 확인 필요.
- `apps/admin` `tsc --noEmit` 통과 확인. 브라우저에서 실제 발급까지는 이번 세션에서
  못 봤다(로컬에 admin_auth 로그인·postgres 붙은 서버가 없음) — 다음 세션에서 운영 또는
  로컬 풀스택으로 재확인 필요.
- 티켓: `w5-agent-token-name-only`(done, `w4-agent-token`의 남은 프론트 항목을 이어받음).
- 남은 것: 이름 중복(동명이인)을 막지 않는다 — 같은 이름을 두 번 치면 두 번째부터 같은
  상담원의 토큰이 추가 발급된다. 상담원 관리 화면이 실제로 필요해지면 이 자동 생성
  경로를 걷어내고 정식 등록 API로 바꿔야 한다(`decisions/406` ⚠ 남는 것).
