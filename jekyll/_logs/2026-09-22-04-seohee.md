- `submitCardFeedback`(`apps/call/src/lib/api/coreClient.ts`)에 `closeCall`과 같은 패턴으로
  상담원 토큰을 실었다 — `readAgentToken()`이 없으면 서버를 부르지 않고 바로
  `CoreApiError`, 있으면 `Authorization: Bearer` 헤더. 서버가 `decisions/315`로
  `require_agent` 가드를 걸어(`server/apps/hub/adapter/inbound/api/v1/card_feedback_router.py`)
  헤더 없이는 항상 401이었다.
- `callStore.ts`의 `toggleAdoption`이 서버 실패를 조용히 삼키던 것(빈 `catch`)을 고쳤다:
  - 토글 전 값(`previousEntry`)을 잡아 뒀다가 `submitCardFeedback` 실패 시 그 값으로
    되돌린다(원래 없던 카드면 키 자체를 지운다) — 낙관적 업데이트 롤백.
  - 새 UI를 만들지 않고 기존 `state.error`(`AppHeader.tsx`가 `header-error`로 렌더링하는
    배너)를 그대로 재사용해 실패 메시지를 띄운다.
  - 이 액션이 `get()`을 못 쓰던 스토어라 `create<CallState>((set) => …)`에 `get`을 추가했다
    (다른 액션 동작에는 영향 없음 — 새로 추가만).
- 빌드 확인: `cd apps/call && npm run build` (`tsc --noEmit && vite build`) 통과.
  이 저장소에 아직 테스트 러너가 없어(`package.json`에 `test` 스크립트 없음) 별도 테스트는
  돌리지 않았다 — 새 프레임워크 도입 금지 제약과도 맞다.
- 남은 것: `submitCardFeedback` 실패가 잦아지면(토큰 만료 등) 배너가 매 토글마다 뜰 수 있다 —
  빈도가 문제가 되면 디바운스/묶음 처리 논의.
