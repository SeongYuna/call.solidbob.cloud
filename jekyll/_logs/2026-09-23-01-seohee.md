- 정성윤의 2026-09-22 수동 QA 결과표(급한 순서 1~6 + 작은 것들)를 코드로 하나씩 확인했다 —
  고치기 전에 먼저 원인을 코드에서 짚고 어느 게 정말 `apps/` 문제이고 어느 게 `server/`
  문제인지 갈랐다. `cga_wrong` 로그인 오류 문구("…받아라")는 `server/apps/agent_auth/adapter/inbound/api/agent_guard.py:31`의
  `detail` 문자열을 `apps/call`이 그대로 relay하는 것으로 확인 — 프론트 수정 대상이 아니다.
- **w6-close-callid-missing** — 원인이 "추천 미발동"이 아니라 **§7.3 계약에 "통화 시작" 메시지
  자체가 없던 것**임을 확인. `apps/call`만으로는 완결이 안 돼 `services/call-mediator`까지
  같이 고쳤다:
  - `services/call-mediator`: `ports.ts`에 `started`(`StartedPayload{call_id}`) 메시지 추가,
    `RegistryDeps.announceStarted`(기본 false, 다른 `announce*`와 같은 안전장치), `call_registry.ts`의
    `callFor()`가 서버 `POST /hub/calls` 성공 직후(통화당 한 번) 방송하도록. `main.ts`에서
    `announceStarted: true`로 켰다. 테스트 3건 추가 — `npm test` 160/160.
  - `apps/call`: `CallMediatorListener.onStarted?` 신설 → `realCallMediatorClient.ts` 파싱 →
    `useCallMediatorSession.ts` → `callStore.applyStarted(callId)`(전사 없이 `callId`만 세팅).
  - 안전장치: `wrapUp()`이 `callId`가 비어 있으면 `/close`를 안 부르고 원인이 보이는 오류로
    바꾼다(전엔 빈 문자열로 404).
  - 남은 것: `apps/call`에 테스트 실행기가 없어 "파서 테스트 1건"을 못 채웠고, 운영에서
    추천 0건 통화로 실측한 적이 없다 — `status: in-progress`.
- **w6-closure-card-pairing** — `callStore.ts`의 `attachIndex`가 "가장 최근 자동 카드"에
  붙이던 걸 **판정의 조항(`procedure`)과 같은 문서(`card.source.doc_id`)를 실제로 추천한
  카드**에 붙이도록 고쳤다. 맞는 카드가 없으면 남의 카드에 붙이는 대신 `cardFromClosure()`로
  판정 전용 카드를 새로 만든다. 회귀 테스트·운영 재확인은 못 했다 — `status: in-progress`.
- **w6-compliance-alert-ui / w6-warning-badge-direction** — 조사해 보니 **같은 버그가 아니라
  진단이 틀린 케이스**였다. 고객 줄의 「⚠ 경고」는 컴플라이언스가 아니라 C-5 마스킹 표시로,
  `.claude/rules/call.md §2`가 정한 의도된 동작이다(배지 방향 조건 1번은 원래 충족돼 있었다).
  진짜 문제는 서버가 보내는 실제 `compliance` findings(`state.compliance`)가 스토어에만
  쌓이고 **화면 어디에도 안 그려지던 것** — 실제로 뜨던 배너는 "불법체류" 한 단어만 잡는
  로컬 자리표시자(`detectComplianceRisk`)였다. `TranscriptPanel.tsx`에서 실서버 모드일 때
  서버 findings를 `ComplianceWarningBanner`로 그리도록 고쳤다(대체 표현은
  `alternative_source.title`). `compliance_unavailable`(탐지 미동작 표시)은 이번엔 손대지
  않았다. 서버 컴플라이언스 규칙이 QA 문장을 실제로 잡는지는 미확인 — `status: in-progress`
  둘 다.
- 확인 검증: `apps/call`(`tsc --noEmit`·`vite build`), `services/call-mediator`(`tsc --noEmit`·`npm test` 160/160)
  전부 통과. `apps/call`엔 여전히 자동 테스트가 없다 — 남은 QA 항목(대기화면 확인창·통화받기
  마이크 실패 안내·이력 레이아웃 등)은 이번 세션에서 손대지 않았다.
