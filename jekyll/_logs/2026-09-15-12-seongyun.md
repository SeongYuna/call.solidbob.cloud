- **`.github/branch-protection.json` 을 라이브 룰셋에 맞췄다 — 미결 항목을 닫았다.**
  값 셋이 어긋나 있었다: `contexts` 셋 → **다섯**(`gateway`·`tag-check`) · 승인 `1` → **`0`** ·
  `enforce_admins` `false` → **`true`**(라이브 `bypass_actors: []` = 우회 없음에 대응).
  - **지우지 않고 고친 이유**: `decisions/011:76` 이 «룰셋을 걷어내고 클래식으로 돌아갈 때를 위해
    남겨 둔다»로 정해뒀다. 목적이 대비본이라면 **값이 어긋난 채로 두는 것이 곧 위험**이다 — 되돌리는
    순간 승인 1건이 생겨 흐름이 막히고, 새로 건 게이트 둘(`gateway`·`tag-check`)이 조용히 사라진다.
  - 고치기 전에 `decisions/011` 을 먼저 읽었다. 안 읽었으면 «안 쓰는 파일이니 지우자»로 갔을 텐데,
    그건 결정 기록을 뒤집는 것이었다(§1 문서 우선순위).
  - 라이브 값은 `gh api .../rulesets/21538648` 로 확인했다: 필수 검사 다섯 · `strict: true` ·
    승인 0 · `bypass_actors: []` · `deletion`·`non_fast_forward`.

- **남긴 것 둘 (미결에 적었다)**
  ① **형식이 다르다** — 이 파일은 클래식 보호 API(`branches/main/protection`) 형식이고 라이브는
     룰셋 API 다. 클래식에 대응물이 없는 라이브 설정 둘은 못 담았다:
     `require_extra_approval_for_unattributed_changes: true` · `allowed_merge_methods`.
  ② **룰셋 자체의 백업이 없다** — 지금 라이브가 유일본이다. 이 파일은 «클래식으로 되돌릴 때의 정책`
     기록이지 룰셋 복원 산출물이 아니다. 룰셋 JSON 을 떠 둘지는 따로 정한다.
