- **`call-mediator` 운영 전환을 끝까지 확인했다** — PR #101 머지 뒤 검사. 레지스트리에 `callguard-server:0.1.17`·`callguard-call-mediator:0.2.0` 이 구워졌고, `https://server.solidbob.cloud/call-mediator/health` 가 ok(키·캡·토큰 2종 설정, 활성 통화 0), 옛 `/gateway/health` 는 404, 상담원 오리진으로 토큰 없이 두드리면 `/ws`·`/dev/text` 둘 다 401(설계대로).
- **시크릿은 값 그대로 복사됐다** — Vercel 에 들어 있던 기존 뷰 토큰으로 새 미디에이터의 `/ws` 가 열렸다(50ms, 헬스 `dashboards` 0→1→0). 토큰을 다시 꺼낼 일이 없었다.
- **한 번 헛돌았다: Vercel 변수의 값만 새 경로로 바꾸고 이름은 옛 `VITE_GATEWAY_*` 그대로였다.** 새 코드는 `VITE_CALL_MEDIATOR_*` 를 읽으므로 그 배포의 번들에는 API 주소 하나만 구워졌고, 상담원 화면이 목업 모드로 돌아가 있었다(번들 안 옛 이름은 0회 — 코드 개명은 깨끗했다). 이름을 바꿔 재배포한 뒤 번들 `index-Dwmrb6cW` 에 주소 셋(`…/call-mediator`·`…/call-mediator/ws?token=`·API)이 구워졌고, **번들에 구워진 구독 주소 그대로 운영에 열어 42ms 열림·`dashboards` 0→1→0** 을 확인했다. 교훈: 환경변수는 값과 이름을 따로 본다 — `vercel env ls` 는 이름만, `env pull` 은 값까지 보여 준다.
- 문서의 「운영은 아직 옛 경로」 경고 둘(STATE 인프라 줄 · 런북 19-1)을 걷고, 티켓 체크 다섯·미결 항목 하나를 닫았다.
- 남은 것: EC2 의 옛 `deploy/callguard-gateway`·`svc/callguard-gateway`·`secret/gateway-tokens` 삭제(인그레스에서 빠져 밖에서는 안 닿지만 파드가 돈다) · 로컬 `.env` 의 `GATEWAY_*` 세 키 이름 변경. 이 기록과 위 문서 수정은 아직 커밋 전이다.
