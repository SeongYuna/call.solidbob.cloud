- 상담기록 드롭다운(`CallHistoryPanel`)의 실서버 목록(`LiveCallHistoryList`)이
  `item.customer_ref`(발신 번호의 HMAC)를 그대로 렌더하고 있던 것을 조사 후 고쳤다.
- 조사 결과 `coreClient.ts:145-146`의 "서버는 아직 customer_id를 안 채운다(F-3)"
  주석이 **낡았음을 확인** — 서버 스키마(`call_list_schema.py:19`)는 이미
  "콜 미디에이터가 X-Caller-Phone을 넘기고 HMAC 키가 있을 때만 채워진다"는
  조건부 실값 경로를 갖고 있어, 지금도 조건이 맞으면 원본 해시가 그대로 온다.
  mock 목록(`MockCallHistoryList`)은 `mock/callHistory.ts:54`의 `고객 #hex`
  라벨(항상 유일값, 재문의 상황 자체가 없음)이라 대상에서 뺐다.
- 재문의 판단 데이터: `GET /hub/calls` 응답에 집계 필드는 없지만, 같은
  `customer_id`가 여러 행에 걸쳐 그대로 반복되므로(서버 리포지토리가
  `customer_id`로 필터링하는 것으로 확인, `call_list_repository.py:18,25-29`)
  **이미 받아온 목록(최대 50건) 안에서 세는 것만으로 충분**했다 — 새 API 불필요.
- 결정: 이 저장소의 "정보 없으면 자리를 비운다" 관례(`CallSummaryPanel`의
  선택적 섹션 등)와 admin의 "기존(재범)" 배지 개념을 합쳐, **원본 해시는 절대
  렌더하지 않고, 같은 값이 목록 안에서 2건 이상일 때만 "재문의 고객" 라벨을
  보여주고 1건뿐이면(또는 서버가 아직 null을 보내면) 아무것도 안 보여준다.**
  `entryDisplayHint`의 `"****"`처럼 매번 자리표시자를 채우진 않았다 — 정보가
  없을 때 자리를 차지하는 게 오히려 신호를 흐린다고 판단.
- `LiveCallHistoryList`에 `repeatCounts`(customer_ref → 등장 횟수, `useMemo`)를
  추가하고, 렌더를 `<span className="call-history-ref">{item.customer_ref}</span>`
  에서 `count > 1`일 때만 `"재문의 고객"` 텍스트를 보여주는 조건부로 바꿨다.
  새 CSS 클래스는 안 만들고 기존 `.call-history-ref` 스타일을 그대로 재사용.
- 빌드 확인: `cd apps/call && npm run build`(`tsc --noEmit && vite build`) 통과.
