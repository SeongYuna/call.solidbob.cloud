## 추가 — 운영 API 가 안 붙는 원인 조사 (같은 날, 코드 수정 없음)

- **서버는 떠 있다(`/health` 200). 그런데 실제 API 호출은 원인 다섯 개가 겹쳐 막혀 있다.**
  운영 주소를 직접 호출하고 GitHub Actions 기록을 REST API 로 조회해 확인했다(이 머신에 `gh` 가 없다).
  CI(`test.yml`)는 #61·#62 모두 success — **테스트가 아니라 배포 쪽 문제**다.
  1. **운영 이미지가 `0.1.1`(09-09 오후)에서 멈춰 있다.** `release.yml` 실행 #59(09-09 09:13Z)·
     #61(09-10 13:35Z) 둘 다 failure. 증거: 운영 `/openapi.json` 에 `POST /hub/calls` 가 없다(404) ·
     `/health` 의 `spokes` 가 `masking·closure_gate·retrieval` 셋뿐(트리거 없음) ·
     `POST /hub/recommendations` → 501 "trigger 스포크가 등록되지 않았습니다 (B-1)".
  2. **DB 를 읽는 엔드포인트가 전부 500** — `GET /hub/knowledge-gaps`·`GET /hub/calls/{id}/transcript`.
     가장 유력한 원인은 옛 이미지의 DB 연결 코드가 `DATABASE_URL` 을 읽지 않는다는 것이다(장민석
     09-10-01 기록, 고친 커밋 `7396275` 는 1번 때문에 운영에 없다). `/health` 의 `postgres_configured: true` 는
     설정값이 있다는 뜻일 뿐 연결된다는 뜻이 아니다. ⚠ **파드 로그로 확정하지 못했다** — 이 머신에
     `aws`·`kubectl` 이 없다. 운영 RDS 에 스키마가 적용되지 않았을 가능성도 남아 있다.

     바뀔 뿐, 적재 전까지는 계속 실패한다.

     "Disallowed CORS origin". `server-env` 에 `CORS_ALLOWED_ORIGINS` 가 없어 `server/core/config.py` 기본값(로컬
     Vite)으로 떴다고 본다 — 시크릿은 저장소 밖이라 키 목록은 직접 보지 못했고 응답으로 추론했다.
