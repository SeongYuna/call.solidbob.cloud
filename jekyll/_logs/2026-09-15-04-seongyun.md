- **관리자 로그인을 실제로 되게 만드는 작업을 셋으로 갈라 시작했다** — 화면(서브도메인) · OAuth · Redis.
  근거·선택지·되돌리는 법은 `_project/decisions/112`. 오늘 닫은 것은 **저장소 쪽 전부**고,
  남은 것은 값·계정 작업이라 저장소에 들어갈 수 없다.
- **먼저 확인한 것 — 이미 배포돼 있는데 아무도 눌러 보지 않았다.** 운영 `/admin/auth/test` 가
  `{"router":"admin_auth","marker":"0.1.7"}` 를 돌려주고 `/openapi.json` 에 `google`·`refresh`·`logout`·`me`
  넷이 있다. 그런데 **붙을 곳이 네 개 비어 있다**: Redis 없음 · 시크릿 키 3종 없음 · CORS 에 관리자 오리진 없음 ·
  화면에 도메인 없음. (테이블은 처음에 「없다」고 봤는데 **작업 중 main 을 받아 보니 이미 있었다** — 아래.) `decisions/403` §7 이 프로바이더를 요청 스코프로 둔 탓에
  **앱 기동도 `/health` 도 정상**이라 이 다섯은 눌러 보기 전에는 드러나지 않는다.
- **Redis 를 클러스터 안에 넣었다**(`infra/k8s/base/redis.yaml`, kustomize `resources` 추가).
  **볼륨을 일부러 안 붙였다** — 저장하는 것이 5분짜리 access token 세션뿐이고, 영속이 필요한 refresh 는
  이미 RDS 에 해시로 있다. 파드가 다시 떠도 사용자는 재로그인 없이 복구된다. `maxmemory-policy` 는
  `noeviction` 으로 뒀다: 5분 TTL 세션에 128MB 는 남아도는 크기라 **가득 차면 용량이 아니라 버그**이고,
  `allkeys-lru` 로 두면 그 버그가 「가끔 로그아웃됨」으로 조용히 흘러간다. ElastiCache 는 만들지 않았다
  (`infra/CLAUDE.md` §1-2). 이걸로 `decisions/403` §5 의 「운영에 필요해지면 그때 정한다」를 닫았다.
- **런북에 두 절을 더했다** — **16-3**(세션 Redis: 주소·비영속·ClusterIP·확인 명령) ·
  **17-4**(첫 관리자 계정).
- **작업 도중 main 을 받아 전제 하나가 뒤집혔다 — 그래서 17-4 를 다시 썼다.**
  처음에는 `admin_account`·`admin_refresh_token` 이 운영에 없다고 보고 DDL 을 통째로 넣는 절을 썼다.
  그런데 main 에 **`db/migrations/` 규약**(09-14·09-15 두 파일)이 생겼고, 09-14 마이그레이션이 그 두 테이블을
  이미 만들었으며 **09-15 확인에서 26 테이블 이름 일치**로 검증돼 있었다(`_logs/2026-09-15-05-minseok.md`).
  내 DDL 을 그대로 돌렸으면 **이미 있는 테이블에 CREATE 를 걸어 실패**한다. 17-4 는 「테이블 확인 + 허용 목록 행 1건」
  으로 좁혔고, 「앞으로 스키마 변경은 `db/migrations/` 에 파일을 더한다」를 한 줄로 남겼다.
  **09-14 에 「없다」고 적힌 것은 그 시점 사실이었다** — 그 뒤에 들어간 것을 내가 안 보고 시작했다.
- **`secret.example.yaml` ① 에 키 3종 설명을 적었다** — `GOOGLE_OAUTH_CLIENT_ID`(비밀 아님, 서버가
  audience 검증에 쓴다) · `ADMIN_JWT_SECRET`(진짜 비밀, `openssl rand -hex 32`) · `REDIS_URL`.
  **`CORS_ALLOWED_ORIGINS` 주의도 같이 적었다** — 관리자 화면은 상담원 화면과 **다른 오리진**이고,
  빠지면 브라우저가 프리플라이트에서 막는데 **서버 로그에는 아무것도 안 남는다.**
- **화면 배포는 「앞단을 잠그고 올린다」로 정했다**(`w4-admin-subdomain`). 지금 그대로 공개하면
  ① `VITE_API_BASE_URL` 이 없어 로그인이 100% 실패하고(빌드타임 변수라 나중에 넣으면 재배포다)
  ② 로그인 게이트가 `App.tsx` 의 클라이언트 상태 한 줄이라 `AdminPanel` 과 mock 픽스처가
  **번들에 그대로 실려** 주소를 아는 사람이 내부 운영 화면을 본다. Vercel Deployment Protection 을
  켜고 올리면 노출 없이 지금 쓸 수 있고, 백엔드가 붙은 뒤에 끄면 된다.
