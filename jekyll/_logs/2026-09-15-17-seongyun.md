- **`decisions/111` 에서 「이번에 하지 않은 것」으로 미뤄둔 CI 결함 다섯을 닫았다**(`decisions/114`).
  전부 「지금 터지지는 않지만 조용히 새는」 부류라, 그대로 두면 `111` 이 경계한 그 방식으로 잊힌다.
- **① ES 이미지를 CI 가 아예 몰랐다** — `paths` 에 `infra/elasticsearch/**` 를 넣고 `es-image` 잡을
  만들고 태그 게이트에도 `es` 를 추가했다. 전에는 Dockerfile 을 고쳐도 워크플로가 안 깨어나고,
  ES `newTag` 만 올리면 **굽는 잡이 없어 ImagePullBackOff** 였다(server 스모크는 통과해 늦게 발견된다).
- **② `converge.sh` 가 게이트웨이 롤아웃을 안 봤다** — 부팅 시 게이트웨이가 못 떠도 「완료」를 찍었다.
  릴리스 배포는 둘 다 보는데 부팅 경로만 하나였다(09-11 도입 때 누락). 한 줄 추가.
- **③ 같은 SHA 에 검사가 두 벌** — `test.yml` 의 push 트리거를 `[main]` 으로 좁혔다.
  **`concurrency` 를 합치는 「싼 수정」은 쓰지 않았다** — 두 런이 같은 SHA 에 같은 이름으로
  check-run 을 보고해서, 취소된 쪽이 나중에 기록되면 필수 검사가 `cancelled` 로 남아 **머지가 막힌다.**
  필수 검사가 다섯이 된 지금은 더 위험하다. 잃는 것은 「PR 없이 브랜치에만 push」 하나뿐이다.
- **④ `branch-protection.json`** 은 다른 세션이 라이브에 맞춰뒀고 이번 커밋으로 들어간다.
- **⑤ 운영 이미지에 테스트 86개가 실렸다** — `.dockerignore` 에 `**/tests`·`**/conftest.py`·
  `**/pytest.ini`·`**/.importlinter`·`ai/apps/evaluation` 추가. 동작 위험은 없었다(pytest 미설치).
  **`call_guard`·`voice_signal` 은 남겼다** — C-6·D-5 가 꽂힐 자리라, 빼면 나중에 꽂는 사람이
  로컬에선 되는데 운영에서만 ImportError 로 헤맨다.
- **⑤ 를 하면서 안전망에 사각지대가 생기는 걸 발견해 같이 막았다.**
  `server/tests/test_image_layout.py` 는 Dockerfile 의 `COPY` 만 읽어서, `COPY ai/apps/` 가 그대로여도
  `.dockerignore` 가 그 안을 빼면 **테스트는 초록인데 이미지엔 없다.** `_ignored_by()` 를 더해
  `.dockerignore` 도 함께 보게 했다 — 실측으로 `evaluation` 은 잡히고 `retrieval`·`provider`·`call_guard` 는 안 잡힌다.
- **브랜치 간 태그 경고의 판정을 고쳤다** — `111` 의 「계보 안인가」 기준은 모두가 공유하는 값
  (`es` 의 `9.5.1`)마다 경고를 띄워 **아무도 안 읽게 된다.** merge-base 의 값과 비교해
  **「저쪽이 실제로 바꿨는가」** 로 바꿨다. 지금은 조용하고, `origin/ai` 가 올린 `0.1.11` 을 집으면 뜬다.
- 태그: server `0.1.10 → 0.1.12` · gateway `0.1.4 → 0.1.5`(`.dockerignore` 가 두 이미지에 다 걸린다).
  **`0.1.11` 은 `origin/ai` 가 선점한 것을 어제 넣은 경고가 알려줬다.**
- 남은 것: ES 태그는 버전을 따라가므로 Dockerfile 만 고칠 땐 접미사(`9.5.1-2`)를 쓴다 ·
  「PR 없는 브랜치 push 는 CI 가 안 돈다」가 불편하면 되돌릴 수 있다(중복도 같이 돌아온다).
