- `apps/call`의 WS 파서(`realCallMediatorClient.ts`)가 `compliance_unavailable`을
  알려지지 않은 타입으로 취급해 `onError("알 수 없는 콜 미디에이터 메시지입니다.")`를
  부르던 것을 고쳤다 — 그 결과가 화면 상단 에러 배너로 뜨고 있었다(검사 실패가 사용자
  눈엔 시스템 에러처럼 보임).
- `types/contract.ts`에 `ComplianceUnavailable`(`call_id`·`segment_id`·`status`) 타입을
  추가했다. `status`는 서버(`call_registry.ts`의 `statusOf()`)에서 고정 enum이 아니라
  자유 문자열("501" 등 HTTP 상태 stringify · "연결 실패" · "알 수 없음")로 확인해
  `readString`으로만 검증하고 별도 화이트리스트를 두지 않았다.
- `realCallMediatorClient.ts`: `ParsedMessage` 유니온·`parseCallMediatorMessage`의 알려진
  타입 목록·`parseByKind`에 `"compliance_unavailable"`을 추가하고, `parseCompliance`와
  같은 방식(`readString` 검증)으로 `parseComplianceUnavailable`을 새로 만들었다.
  `handleMessage`에 처리 분기를 추가해 `listeners.onComplianceUnavailable?.(...)`을 부른다.
- `lib/ws/types.ts`: `CallMediatorListener`에 `onComplianceUnavailable?`을
  `onCompliance?`와 같은 시그니처(`(transcriptSegmentId, event) => void`)로 추가.
- `hooks/useCallMediatorSession.ts`: 이 콜백을 `callStore.applyComplianceUnavailable`로 연결
  (`onCompliance` 배선과 나란히).
- `store/callStore.ts`: `complianceUnavailable: Record<string, ComplianceUnavailable>` 상태와
  `applyComplianceUnavailable` 액션 추가. 여러 건을 쌓는 `compliance`(배열)와 달리
  `callGuard`처럼 세그먼트당 최신 1건으로 덮어쓴다(검사 실패는 목록으로 쌓을 이유가 없음).
  **컴포넌트 렌더링은 건드리지 않았다** — 지시대로 이번 범위는 "에러 오인 제거"까지.
- 코드 경로로 확인: `type` 화이트리스트 통과 → `parseComplianceUnavailable`이 유효한
  객체를 반환 → `handleMessage`가 `message === null` 분기를 타지 않고 새 분기에서
  `return` — 리스너 연결 여부와 무관하게 이 타입에 대해 `onError`가 호출될 경로 자체가
  없어졌다.
- 빌드 확인: `cd apps/call && npm run build` (`tsc --noEmit && vite build`) 통과.
  테스트 러너가 아직 없어 새 프레임워크 도입 없이 빌드로만 검증.
- 남은 것: `complianceUnavailable` 상태를 화면에 어떻게 보여줄지(배너 억제 상태 표시 등)는
  다음 티켓 — 지금은 상태만 쌓인다.
