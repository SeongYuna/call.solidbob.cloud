- **진짜 원인을 찾았다.** 사용자가 "토큰 넣고 로그인하면 '최효원'이 그대로 떠야 한다"고
  캡처를 보내왔는데, `apps/call` 대기화면이 `GET /hub/agents/me`가 돌려주는 **`agent_id`를
  그대로 이름 자리에 쓰고 있었다**(`App.tsx`의 `agentName = agentAuth.agentId ?? …`). 앞선
  두 번의 수정(자동 등록·agent_id=이름)은 발급 쪽 문제였고, 이번 건 별개로 **표시 쪽**이
  `display_name`을 아예 안 받아오던 문제였다 — `agent_id`가 우연히 이름과 같아지는
  경우(방금 만든 상담원)만 맞아 보였을 뿐, 20자 넘는 이름이나 예전에 발급된 토큰은
  여전히 틀리게 뜬다.
- **`GET /hub/agents/me`가 `display_name`도 돌려주게 했다.** `AgentDirectoryPort.get(agent_id)`
  (조회 전용, `resolve_or_create`와 달리 안 만든다) 추가 → `AgentProfileUseCase`/
  `AgentProfileInteractor` 신설(포트당 인터랙터 하나라는 이 앱의 기존 관례를 따름) →
  라우터가 `agent_id` 대신 `{agent_id, display_name}`을 응답.
- **`apps/call`도 고쳤다** — `fetchAgentMe`가 `displayName`을 같이 받고, `useAgentAuth`
  훅이 그걸 상태로 들고, `App.tsx`의 대기화면 인사말이 `agentAuth.displayName`을 쓴다
  (`agentId`는 여전히 로그아웃 버튼 노출 여부 판단에만 쓰인다).
- `server/apps/agent_auth` 유닛 25건(신규 1건 포함) 통과, `apps/call`·`apps/admin`
  `tsc --noEmit` 통과. server 이미지 태그 `0.1.22` → `0.1.23`.
- 남은 것: 이번에도 브라우저로 로그인→대기화면까지 직접 확인은 못 했다 — 다음에 실서버
  붙었을 때 캡처로 재확인 필요. `agent` 행이 지워진 채 토큰만 남는 경우(드묾)는 이름 대신
  `agent_id`로 조용히 대체하도록 해뒀는데, 실제로 그럴 일이 있는지는 미확인.
