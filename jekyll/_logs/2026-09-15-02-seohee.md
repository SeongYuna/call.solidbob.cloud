- **F-2·C-6 프론트 계약을 서버 실측에 맞췄다.** 팀 노션 감사 문서에 적힌 어긋남 넷 중
  둘을 실제로 고쳤다 — 나머지 둘(§7.3 전부-문자열 표기는 문서만의 문제, A-5/D/G-2는
  계약 자체가 아직 없음)은 코드로 고칠 대상이 아니라 그대로 알렸다.
  - **closure(F-2)** — `decisions/305`가 이미 확정한 서버 계약(`closure_verdict_dto.py`)에
    맞춰 `ClosureEvent.closure_type`→`procedure`(+`procedure_title`), `ClosureVerdict`를
    `approved/blocked`→`complete/incomplete`로, `detected`·`conditional` 필드를 추가했다.
    `realGatewayClient.ts` 파서·`callStore.ts`·`TermsPanel.tsx`·`BookmarkDock.tsx`·
    `section73.ts`(7.3절 예시)·`mock/scenarios/dasan.ts` 전부 갱신. 지금은 게이트웨이가
    새 형식 전송을 꺼 둔 상태(`announceClosure: false`)라 실사용 영향은 없고, 나중에 켜질 때
    바로 받을 수 있게 준비만 해 둔 것이다.
  - **C-6 콜가드** — `CallGuardFlag.category`를 옛 한글 3종(`폭언`·`욕설`·`위협`)에서 백엔드
    실제 4종(`insult`·`threat`·`sexual`·`distress`)으로 통일했다. **`distress`는 폭언과 다르게
    다룬다**(DASAN-MANUAL-5.4, 통화를 끊지 않고 전문기관 연결) — 이미 `collectEvidence.ts`가
    `distress_count`를 폭언 합계에서 빼고 있었고, `CustomerRiskBanner`도 abuse/distress를
    다른 배너로 보여주고 있었다. 어긋난 건 딱 `CallGuardFlag` 타입 하나였다. 프론트가
    임시로 지어낸 `severity: low/high` 필드는 백엔드 DTO에 없고 부록 A-1(위험도 점수 금지)과도
    어긋나 삭제했다. `TranscriptPanel.tsx`의 레거시 "🚫 콜가드" 알약도 distress면
    "🆘 위기 신호" + 다른 안내 문구로 분기하도록 고쳤다.
- **[w4-dashboard-live-contract](/backlog/w4-dashboard-live-contract/) 착수** — 서버에
  실제로 구현돼 있는 `/hub/*` 라우터를 전부 확인한 뒤(`call_list_router`·
  `transcript_query_router`·`search_router`·`blacklist_*_router`·`call_guard_flag_list_router`
  등, 09-14에 이미 나가 있었다) `apps/call`·`apps/admin`을 실제 REST로 연결했다.
  - `apps/call`: `coreClient.ts` 전면 재작성(통화 목록·자막 조회·수동 검색·블랙리스트 요청 생성·
    카드 피드백 함수), `RealGatewayClient.manualSearch()`가 실제 `/hub/search`를 부르도록 교체,
    WS에 `recommendation_pending`·`call_guard` 파싱 추가, 블랙리스트 요청 실패 시 폼에
    에러 메시지 표시.
  - `apps/admin`: 새 `hubClient.ts` + `adminStore.ts`에 `status`/`error`/`loadAll()` 추가,
    로그인 직후 자동으로 승인요청·블랙리스트·콜가드 집계를 실제로 받아온다. 실패하면 헤더에
    에러 배너("다시 시도" 버튼)를 띄운다 — 빈 목록으로 조용히 넘어가지 않는다(티켓 완료 조건).
  - ⚠ **끝까지 못 붙인 것 셋** — ① 카드 피드백(`POST /hub/cards/{id}/feedback`)은 추천 카드
    응답에 애초에 `card_id`가 없어 뭘 넘길지가 없다(2026-09-11 미결 항목이 아직 안 풀림).
    ② 상담기록(통화 재생) 화면은 지금 카드·종결·감정분석까지 재생하는 mock 시나리오
    기반인데 실제 API는 통화 목록+자막만 줘서, 화면을 그대로 바꿔 끼우면 재생 기능이
    빠지는 셈이라 제품 판단 없이 UI는 안 건드렸다. ③ 관리자 지식베이스 갭 화면은
    `{query, found}` 기준 집계인데 실제 계약은 `{module, description, status}`라 모양이
    달라 탭을 다시 설계해야 한다 — REST 함수만 만들어 두고 화면엔 안 붙였다.
