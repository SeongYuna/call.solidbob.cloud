- **게이트웨이를 운영에 올렸다** (PR #68 → 게이트웨이 `0.1.0`, PR #69 → `0.1.1`). 같은 노드에 따로 뜨고 밖에서는
  `https://server.solidbob.cloud/gateway/…` 로 닿는다. 런북 19-1 을 운영에 대고 쳤다 — `/gateway/health` 설정 넷(구글 키·STT 캡·
  두 토큰) 전부 true, 토큰 없는 `/gateway/ws`·`/gateway/ingest`·`/gateway/dev/text`·`/gateway/dashboard` 전부 401, `/gateway/dev` 200.
  서버는 두 번 다 굽지 않았다(`0.1.3`, 스포크 4종 그대로).
- **첫 배포는 멈췄다 — Docker Hub 새 저장소가 비공개로 만들어졌다.** 빌드·푸시는 성공했는데 익명 pull 이 401(서버 이미지는 200)이라
  k3s 가 ImagePullBackOff. 코드 문제가 아니었다. 사용자가 공개로 바꾼 뒤 재실행했는데 **또 실패했다** — 첫 시도에서 10분이 지나
  Deployment 가 «진행 기한 초과» 로 표시돼 있어 `rollout status` 가 기다리지 않고 바로 실패했다. 파드는 이미 떠 있었고, 한 번 더 돌려 초록.
  롤백은 설계대로 멈춘 게이트웨이만 봤고 서버는 건드리지 않았다. Dockerfile·런북 19-1 에 «새 이미지 저장소는 공개로» 를 적었다.
- **⚠ 내 판단 하나가 틀렸다.** 배포 로그의 `statefulset.apps/elasticsearch configured` 를 보고 «누가 클러스터에서 ES 를 고쳤다» 고 추정해
  bc 세션에 물었는데, **이전 릴리스 전부가 같은 줄을 찍는다** — 적용할 때마다 생기는 차이다(bc 세션이 짚었고 로그로 확인). 해는 없지만
  진짜 변경이 생겨도 묻히므로 [미결](/open-items/)에 올렸다.
- **frontend 브랜치와 같은 자리에 게이트웨이를 만들었다.** 조서희 님이 같은 날 `services/gateway` 에 브라우저 음성 인식(Web Speech API)으로
  글자를 보내는 개발용 게이트웨이를 만들었다(`decisions/402`, 미머지). 기능은 겹치지 않는데 디렉터리가 겹친다. 사용자 결정으로 **하나로 합쳤다**
  (`_project/decisions/109`) — 정식 게이트웨이를 기준으로 402 의 `/dev` 를 글자 입력 채널로 옮겼다. 운영 `https://server.solidbob.cloud/gateway/dev`
  는 이미 HTTPS 라 ngrok 이 필요 없다. 통화 기록 엔진은 `web-speech`, 구글을 안 부르므로 COST-1 캡과 무관. **품질 측정용이 아니다.**
- **옮기면서 구멍 하나를 막았다** — 402 의 흐름은 ngrok 을 쓰는데, 터널은 인터넷 요청을 루프백으로 넘긴다. 내 게이트웨이는 루프백을 믿으므로
  터널 한 줄로 문이 열렸을 것이다. 프록시 헤더가 붙은 루프백은 믿지 않게 했다. 글자 입력 문은 DB 에 쓰므로 **과금 문 토큰만** 받는다
  (브라우저는 서브프로토콜로 — URL 금지, 뷰 토큰 불가). `/dev` 페이지는 CSP(스크립트 해시)·틀 금지로 나간다. 운영 페이지의 해시가 스크립트와
  일치하는 것까지 봤다. 테스트 79개, 새 규칙 둘은 일부러 망가뜨려 테스트가 잡는 것을 확인했다.
- **조서희 님 브랜치와 `apps/` 는 건드리지 않았다.** 합칠 때 할 일(게이트웨이는 main 쪽, `?gateway=` 덮어쓰기는 그대로)을 [미결](/open-items/)에
  조서희 님께 남겼다.
- **다른 세션 덕을 봤다** — a5 세션이 인증·경로·장부·HTTP/2 검사 구멍(`--http1.1`)을 짚었고 운영 실측을 따로 해 줬다. bc 세션은 PR 을
  덩어리째 골라 올려 내 파일이 섞이지 않게 했다. **내가 bc 세션의 로그 13 을 덮어쓴 사고**가 있었다(09 기록 뒤 13 기록 참고) — 이후 새 파일은
  덮어쓸 수 없게 만든다.
- 남은 것: `.env.example` 키 넷(보호 훅 때문에 사람이 — 적용할 파일은 준비돼 있다) · CI 필수 검사에 `gateway` 추가 여부 · `/ws` 사람별 인증 ·
