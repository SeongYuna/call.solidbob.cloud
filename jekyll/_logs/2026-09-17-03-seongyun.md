- **`gateway` 를 `call-mediator` 로 개명했다 (`decisions/115`)** — 「게이트웨이」가 보안 장치로 읽히는 오해가 반복돼 팀이 개명에 합의했고, 후보 `proxy`·`mediator` 중 **GoF 메디에이터 패턴을 쓴다는 설계 의도**에 맞춰 `call-mediator` 로 정했다(`proxy` 는 고치려는 오해를 더 정확한 말로 부르는 셈이고 클러스터에 Traefik 이 이미 프록시다). 한국어 서술은 「콜 미디에이터」.
- **범위는 전부다** — 디렉터리(`services/call-mediator/`) · CI job·릴리스 job · 이미지(`callguard-call-mediator`) · k8s Deployment·Service·시크릿(`call-mediator-tokens`, 키 `CALL_MEDIATOR_*`) · 공개 경로(`/call-mediator/*` — `PUBLIC_PREFIX`·Ingress·프론트 허용 목록) · 환경변수(`CALL_MEDIATOR_PORT`·`VITE_CALL_MEDIATOR_*`) · 대시보드 오버라이드(`?call_mediator=`) · 프론트 식별자·파일 4개 · 런북·규칙·기획서·STATE·미결·티켓 본문. 추적 파일만 대상으로 스크립트 치환 924회 + 손 보정. `apps/` 도 이번 작업에 한해 사용자 지시로 함께 고쳤다(규칙 파일은 이름만 바꿨고 규칙은 그대로다).
- **바꾸지 않은 것** — 진행 기록 · 결정 기록 · `STATE-archive` · 옛 기획서 판(그 시점의 사실, `decisions/015` 선례) · 티켓 슬러그(옛 기록이 링크한다) · AWS NAT Gateway/인터넷 게이트웨이(다른 물건) · 사용량 장부 hostPath.
- **치환이 만든 결함 둘을 테스트가 잡았다** — 한글 테스트 함수명의 「게이트웨이」가 「콜 미디에이터」(공백)가 되어 **server·ai pytest 가 수집 단계에서 SyntaxError**. 함수명만 `콜_미디에이터` 로 고쳤다. 같은 이유로 마크다운 앵커도 봤는데 걸린 곳은 0.
- **태그** — call-mediator `0.1.5` → **`0.2.0`**(새 레포라 어떤 번호든 새 태그지만 `origin/ai` 가 선점한 `0.1.6` 을 피했다) · server `0.1.13` → **`0.1.14`**(주석·설명 문자열만 바뀌었어도 이미지에 들어가는 경로라 `decisions/111` 규칙에 걸린다 — 로컬에서 `check_release_tags.py` 를 돌려 확인).
- **실측 하나: 없는 Docker Hub 레포는 404 가 아니라 401 이다.** `seongyuna/callguard-call-mediator:0.1.5` → 401(토큰은 발급된다), 있는 레포의 없는 태그(`callguard-gateway:9.9.9`) → 404. `tag-check` 는 401 을 「판정 불가」로 보고 죽으므로 **머지 전에 빈 레포를 만들어 둬야 한다.**
- 검증: call-mediator 타입 검사·테스트 **101/101** · `apps/call`·`apps/platform` 빌드 · server·ai pytest 통과 · import 계약 4종 kept · 워크플로·매니페스트 YAML 파싱 · 사이트 빌드 + 내부 링크 깨짐 0.
- 남은 것: **운영 전환이 아직이다 — 문서는 `/call-mediator`, 운영은 `/gateway`.** 사람이 할 일 일곱 가지(Docker Hub 레포 · 시크릿 복사 · Vercel 변수 추가 · 룰셋 · 헬스 확인 · 옛 오브젝트 삭제 · 옛 변수·`.env`)와 순서는 런북 19-1 「개명 전환」·티켓 `w5-call-mediator-rename`. 류준 님 `origin/ai` 의 `services/gateway/` 미머지 작업은 main 을 받을 때 맞춰야 한다. 커밋·PR 은 아직 안 했다.
