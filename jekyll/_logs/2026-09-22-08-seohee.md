- `CallSummaryPanel`의 "연계 가능한 지역자원" 섹션이 게이팅 없이 항상
  `DEFAULT_LOCAL_RESOURCES`(서울출입국·종로구청 하드코딩)로 채워지던 것을 고쳤다 —
  G-2(지역자원 연계)가 미구현이라 서버(`closeCall`·`fetchCallRecord`)가
  `local_resources`를 아예 안 채우는데, 프론트가 그 자리를 mock 목록으로 대신
  채우면서 화면에 mock이라는 표시가 없었다(모든 통화에 같은 두 기관이 뜸).
- `callSummaryFromWrapUp(wrapUp, mode)`에 `mode: CallMediatorMode` 인자를 추가해
  `mode === "mock"`일 때만 `DEFAULT_LOCAL_RESOURCES`로 폴백하게 게이팅했다.
  실서버 모드(`mode !== "mock"`)에서 서버가 안 채우면 `resources`는 `undefined`
  그대로 남는다(`CallSummaryModel.resources` 타입이 이미 `LocalResource[] |
  undefined`라 타입 변경 불필요).
- mock 경로 확인: `mock/mockCallMediator.ts:137-149`(라이브 mock WS)와
  `mock/callHistory.ts:112-123`(상담기록 mock 재생) 둘 다 **이미 자기 쪽에서**
  `DEFAULT_LOCAL_RESOURCES` 폴백을 미리 채워 넣은 `CallWrapUp`을 넘긴다 — 그래서
  `callSummaryFromWrapUp`의 폴백은 이 두 경로에선 사실 거의 안 쓰이고(방어적
  역할만), `mode` 게이팅을 넣어도 mock 동작은 그대로다. 빌드로 확인.
- `wrapUpFromRecord`(상담기록 상세, `:54-61`)는 자체적으로 폴백 로직이 없고
  `callSummaryFromWrapUp`을 그대로 거쳐가므로 — 지시대로 확인해보니 **한 곳만
  고치면 됐다.** `wrapUpFromRecord` 자체는 수정하지 않았다.
- `CallSummaryHost`에 `mode = useCallStore((s) => s.mode)`를 추가해 세 호출부
  (`live`·`playback.wrapUp`·`wrapUpFromRecord(historyRecord)`) 모두에 넘겼다.
- 빈 상태 처리 방식은 **섹션 자체를 렌더하지 않는 쪽**을 골랐다 — "아직
  지원하지 않습니다" 문구 대신, 같은 컴포넌트 안 "카드 사용 현황"·
  "지식베이스 공백" 섹션이 이미 쓰는 `조건 ? <section>...</section> : null`
  패턴, 그리고 `TranscriptPanel`이 `translations[segment_id]` 없을 때 그
  세그먼트에 아무것도 안 그리는 패턴과 일관된다. 렌더 조건을
  `call.resources !== undefined && call.resources.length > 0`으로 바꾸고
  `const resources = call.resources ?? [];` 중간 변수를 없앴다.
- 빌드 확인: `cd apps/call && npm run build`(`tsc --noEmit && vite build`) 통과.
  새 테스트 프레임워크 도입 없음(러너 아직 없음).
