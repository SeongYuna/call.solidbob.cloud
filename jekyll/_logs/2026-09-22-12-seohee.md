- `apps/platform` 홍보 페이지의 통화 ID 공유를 자동화했다 — 지금까지는
  `useLiveCallSession.ts:120`(옛 코드) 안에서 `call_id`가 지역 상수로만
  계산되고 화면·URL 어디에도 안 남아 상담원과 맞출 방법이 없었다.
- 흐름 확인(수정 전 읽기): `Hero.tsx:63-67`의 `IncomingCallCard`가 눌리면
  `setCallOpen(true)` → `Hero.tsx:69-74`가 `<LiveCallModal>`을 마운트하고,
  `LiveCallModal.tsx`의 `useEffect(() => { start(); }, [start])`가 마운트
  즉시 `useLiveCallSession().start()`를 호출해 마이크·WS를 연다.
- `sharedCallId.ts`(apps/platform·apps/call, 지금까지 바이트 단위로 동일)에
  `ensureSharedCallId()`를 추가했다 — URL에 `?call_id=`가 있으면 그 값을,
  없으면 `CALL_ID` 정규식을 만족하는 새 값(`call-<timestamp36>-<random6>`)을
  만들어 `history.replaceState`로 URL에 반영한다. **두 파일을 다시
  바이트 단위로 동일하게 유지했다**(diff 0). apps/call 쪽은 이 함수를
  아직 아무도 안 쓴다 — `useAgentCallSession.ts`는 이번 지시 범위 밖이라
  손대지 않았다(그쪽의 기존 `readSharedCallId() ?? 자체 생성`은 그대로 두면
  이번 링크로 열었을 때 이미 반영된 `?call_id=`를 그대로 집어 쓴다).
- `useLiveCallSession.ts`가 `readSharedCallId() ?? test-web-platform-*` 대신
  `ensureSharedCallId()`를 쓰도록 바꾸고, `callId`를 `useState`의 지연
  초기값으로 훅 최상단에서 계산해 반환 객체(`{..., callId, start, end}`)에
  추가했다 — `start()` 안의 지역 상수였던 것을 훅 스코프로 끌어올렸다.
- `LiveCallModal.tsx`에 "상담원 링크 복사" 버튼을 추가했다(팀 토큰이 있을
  때만 노출 — `readLiveCallToken() !== null`). `apps/call` 대시보드 주소
  (`VITE_CALL_APP_URL`, 없으면 기본값 `https://call.solidbob.cloud`)에
  `?call_id=`(방금 확보한 값)·`?call_token=`(이미 있는 팀 전용 값)을 붙여
  클립보드에 복사한다. `call_token` 자체는 새로 만들거나 노출하지 않았다 —
  여전히 팀이 따로 공유하는 값이다. 복사 성공/실패는 버튼 텍스트를
  "복사됨"/"복사 실패"로 2초간 바꿔 보여준다 — `apps/admin`의
  `SettingsTab.tsx`(`navigator.clipboard.writeText` + "복사"/"복사됨" 토글)
  관례를 참고해 실패 케이스만 추가했다(admin과 코드 공유는 없음 — 별도 앱).
- `vite-env.d.ts`에 `VITE_CALL_APP_URL` 타입을 추가했다. `.env.example`은
  자격증명 보호 훅이 편집을 막아 손대지 않았다 — 공개 URL이라 기본값으로
  바로 동작하지만, 다른 값을 쓰고 싶으면 `apps/platform/.env.example`에
  `VITE_CALL_APP_URL=`을 사람이 직접 추가해야 한다.
- 빌드 확인: `cd apps/platform && npm run build`, `cd apps/call && npm run build`
  둘 다(`tsc --noEmit && vite build`) 통과. apps/call 번들 해시는 직전과
