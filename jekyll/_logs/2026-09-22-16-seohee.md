- `apps/admin`의 현황판(`WallboardTab`)을 `GET /hub/admin-stats` 실 API로
  연결했다. 완료 통화·콜가드는 각각 별도 `limit=1` GET, 승인 대기·활성
  등록은 클라이언트 필터링이던 것을 API 응답 하나로 대체했다.
- `hubClient.ts`: `fetchAdminStats(accessToken)` + `AdminStats` 타입 신규 —
  기존 관리자 인증 GET(`fetchCallGuardFlagTotal` 등)과 같은 패턴
  (`authedGet` + wire→camelCase + `toNum`). 응답에 `routing_decisions`·
  `routing_blacklisted`·`routing_fell_back`도 타입에는 포함했지만(지시대로)
  이번 화면엔 렌더하지 않았다.
- **"완료 통화 누적"을 `calls_closed`로 매핑**(지시대로) — 예전
  `fetchCallListTotal()`은 `GET /hub/calls?limit=1`로 **닫힌 통화가 아니라
  시작된 통화 전체**(`calls_total`)를 셌다. 라벨은 "완료"였는데 실제로는
  전체를 세던 기존 버그를 이번에 같이 고친 셈이다.
- `adminStore.ts`: `loadAll`의 `Promise.all`에서 `fetchCallGuardFlagTotal`·
  `fetchCallListTotal` 두 호출을 `fetchAdminStats` 하나로 교체.
  `statsPendingRequests`·`statsActiveEntries`·`statsCountedAt` 상태를
  새로 추가했다 — **`AdminPanel.tsx`가 사이드바 배지·`NotificationBell`에
  쓰는 기존 `pendingCount`/`activeEntryCount`(요청·등록 목록에서 그때그때
  다시 세는 라이브 값)는 그대로 뒀다.** 승인·해제 직후 즉시 갱신돼야 하는
  용도라 `loadAll` 시점 스냅샷인 admin-stats 값으로 바꾸면 그 반응성을
  잃는다 — 그래서 이름을 `statsPendingRequests`/`statsActiveEntries`로
  구분해 **현황판 전용**으로만 흘려보냈다(`AdminPanel.tsx`의 `WallboardTab`
  호출부만 이 값을 받음).
- `WallboardTab.tsx`: "백엔드 연동 전이라 mock 시드 값..." 안내문을
  `counted_at` 기반 "OO시 기준입니다." 문구로 교체하고, 여전히 맞는
  "실시간 통화 현황은 상담원 앱과 분리돼 있어 안 보인다"는 남겼다.
  `countedAt: string | null` prop 추가.
- 에러 표시(5번): 별도로 안 만들었다 — `fetchAdminStats`가 `loadAll`의
  같은 `Promise.all`에 들어가 있어 실패하면 기존 `AdminPanel.tsx`의
  전역 에러 배너(`header-error`, "데이터를 불러오지 못했습니다: ..." +
  "다시 시도" 버튼, `:111-125`)가 그대로 잡는다 — 이미 있는 관례를
  그대로 재사용.
- 죽은 함수 정리(6번): `fetchCallListTotal`·`fetchCallGuardFlagTotal`의
  호출부를 grep했더니 `adminStore.ts`의 `loadAll` 한 곳뿐이었다(다른
  곳에서 안 씀) — **삭제했다.** 남겨뒀으면 죽은 코드였다.
- 빌드 확인: `cd apps/admin && npm run build`(`tsc --noEmit && vite build`) 통과.
