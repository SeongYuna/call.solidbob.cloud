- **대시보드 Vercel 빌드 실패를 고쳤다** — `apps/dashboard` 가 `apps/platform/src/theme.tsx`·
  `ThemeToggle.tsx` 를 상대경로로 직접 import 하고 있었다. 모듈 해석은 tsconfig 위치가 아니라
  **소스 파일이 놓인 경로**에서 시작하는데, Vercel 은 Root Directory 인 `apps/dashboard` 만
  설치하므로 platform 쪽 파일에서는 react 를 찾을 데가 없다 → `TS2307`·`TS2875`·`TS7006` 5건으로
  `tsc --noEmit` 에서 죽었다. 로컬에는 `apps/platform/node_modules` 가 있어 드러나지 않았다.
- **고친 방법**: 공유하던 3개 파일(`theme.tsx`·`ThemeToggle.tsx`·`ThemeToggle.css`)을
  `apps/dashboard/src` 로 복사하고 import 를 프로젝트 안쪽으로 돌렸다. platform 원본은 그대로 뒀다.
  같이 들어와 있던 `vite.config.ts` 의 `server.fs.allow: [".."]`(로컬 dev 서버만 통과시키던
  임시방편, `9f730f9`)도 걷어냈다.
- **검증**: `apps/platform/node_modules` 가 **없는** 상태 — Vercel 과 같은 조건 — 에서
  `tsc --noEmit` 통과, `vite build` 통과(89 modules). 실패하던 두 단계를 모두 넘겼다.
- 남은 것: **푸시 후 Vercel 재배포가 초록인지 확인.** 그리고 `apps/dashboard/` 는 조서희 소관인데
  배포 복구라 PM 이 먼저 손댔다 — 겹치는 작업이 있으면 알려달라고 통보해야 한다.
- 앞으로: 공유 코드가 더 늘면 복사본이 갈린다. 그때는 npm workspaces 로 `packages/ui` 를 떼고
  Vercel Root Directory 를 저장소 루트로 올린다. 티켓: [w3-dashboard-vercel-build-fix](/backlog/w3-dashboard-vercel-build-fix/)
