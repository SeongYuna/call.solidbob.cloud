## 무엇을

**발화 → 자막 → 마스킹 → 카드 → 통화 후 요약**까지 한 줄로 흐르는 시연 시나리오를 만들고 리허설한다.

## 되는 것은 확인돼 있다 — 끊기는 자리를 찾는 일이다

2026-09-11 에 **로컬 콜 미디에이터(ngrok) → 배포 백엔드 → 대시보드 엔드투엔드 실측이 성공**했고
실제 폰 발화가 DB 에 영구 저장되는 것까지 확인했다. 09-14 에는 운영에서 통화 생성 → 전사
→ **P4 마스킹(`제 번호는 *********** 입니다`)** → 조회에 **원번호가 남지 않는 것**까지 봤다(SEC-1).

**남은 위험은 「배포됐는데 화면에선 안 되는」 자리다** — 09-14 에 관리자 로그인이 그랬고
`/health` 는 `ok` 였다. **눌러 보기 전에는 모른다.**

## ⚠ 시연 전에 사람이 해야 하는 것

- **화자 분리**: 데모는 **물리 2채널(브라우저 2대)**로 우회한다 — AI Hub 데이터가 전부 모노다(V1 실측).
  `speaker=auto` 는 **실제 구글 응답으로 미검증**이다(`decisions/303`)
- **운영 `document` 테이블이 비어 있으면** 콜 가드·추천 카드의 근거 조항이 NULL 로 저장된다 — 먼저 채운다
- **`admin_account` 행이 없으면** 블랙리스트 승인·해제가 409 다

## 완료 조건

- [ ] 시나리오 대본(발화 문장 포함)이 있고, **개인정보 패턴이 실제로 들어 있다** — 마스킹이 도는 것을 보여야 한다
- [ ] 리허설을 **운영 주소로** 한 번 돌린다(로컬 mock 이 아니라)
- [ ] 안 되는 기능은 **끄거나 「미구현」이라고 화면에 적는다.** 되는 척하지 않는다
- [ ] 시연 중 실패했을 때의 대체 경로(녹화 영상 등)를 준비한다
