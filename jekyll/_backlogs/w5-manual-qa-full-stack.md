## 무엇을

**운영 주소**에 떠 있는 서버·AI·콜 미디에이터·상담원 화면·관리자 화면을 한 번에 붙여 놓고,
**사람이 직접** 화면의 버튼을 하나씩 누르고 데이터를 손으로 넣어서 되는지 안 되는지를 표로 남긴다.

## 왜 — 지금 이게 병목이다

- 지금까지 한 검사는 **전부 API 왕복**이다. [합성 통화 E2E](/backlog/w5-persona-e2e/)(`e2e_check.py`)는 DB·API 응답을 대조할 뿐,
  **화면에 실제로 무엇이 보이는지는 보지 않는다.** 서버 pytest 1,301건도 마찬가지다.
- 「배포됐는데 화면에선 안 되는」 사고가 이미 났다 — 09-14 관리자 로그인은 `/health` 가 `ok` 인데 화면에서 막혀 있었다.
  **눌러 보기 전에는 모른다**([시연 리허설](/backlog/w8-demo-rehearsal/)).
- 세 사람(서버·AI·프론트)이 각자 자기 몫을 끝냈다고 보고 있지만, **붙였을 때 되는지는 아무도 확인하지 않았다.**
  이 확인이 끝나야 각자 다음 작업으로 넘어갈 수 있다 — 지금은 셋 다 여기서 멈춰 있다.
- 코드를 읽어 보면 이미 이상한 곳이 보인다. 상담원 마이크 박스는 인식한 글자를 화면에 그리지 않고,
  토큰이 없거나 브라우저가 지원하지 않으면 **안내 없이 모달만 닫힌다**(`apps/call/src/lib/useAgentCallSession.ts`).
  이런 것은 사람이 눌러야 드러난다.

## 규칙 — 이 티켓을 하는 방법

1. **직접 누른다. Claude 나 스크립트에 맡기지 않는다.** 이 티켓이 확인하려는 것은 사람이 화면을 쓸 수 있느냐다.
   재생기(`replay_persona_call.ts`)는 **발화를 넣는 데만** 써도 된다. 판정은 눈으로 한다.
2. **운영 주소로 한다.** 로컬 mock 으로 한 결과는 인정하지 않는다.
3. 항목마다 **✅ 됨 / ❌ 안 됨 / ⚠ 되긴 하는데 이상함 / — 해당 없음(mock)** 중 하나를 적는다. ❌·⚠ 는 **스크린샷 + 브라우저 콘솔·네트워크 탭 캡처**를 남긴다.
4. **찾기만 하고 고치지 않는다.** ❌ 가 나오면 담당자에게 넘긴다 — 서버 `server/` 장민석 · AI `ai/` 류준 · 화면 `apps/` 조서희 · 배포·토큰·주소 문제는 본인.
   넘길 때는 **QA 번호(아래 `Q-xx`) · 누른 순서 · 기대한 것 · 실제로 본 것**을 적는다. 고치면서 가면 QA 가 끝나지 않는다.
5. 진행은 **하루 단위**로 끊는다. 그날 한 범위와 ❌ 목록을 `_logs/` 에 남긴다 — 다 끝낼 때까지 기다리지 않는다. 먼저 나온 ❌ 부터 담당자가 고치기 시작할 수 있다.
